# 第 15 章 事例：EC・日常生活での実践

Webの対話画面を単独で開くだけでは履歴が失われやすく、複数のソフトウェアを行き来してデータを移す手間もかかります。**本章では、既存のソリューションを活用して一連のワークフローを通しで走らせる方法を解説します**。

- 生活・コンテンツ制作：洗練されたプロンプトを使って闲鱼の出品文、小红書のレイアウト、SVG画像カードを生成し、手作業での位置合わせから解放されます。
- 越境EC：単独マシンの巡回チェックから始め、**「船長1名＋12の専門職」チーム**を構築し、承認待ちリストによって人間が最終確認を行います。

## 事例 1：闲鱼出品アシスタント（不用品・中古品情報シート＆問い合わせ対応下書き）

Miles Ma（@miles_mazy、着想元は @0xlangeai）がこのBotを作成しました。中古品の出品情報をAIに丸投げすると、**勝手に新品のスペックをでっち上げられてしまうリスク**があります。このBotは、商品の現状と公式スペックを切り離して処理し、2カラムの情報シートと返信下書きを生成します。

### 手順と検収基準

1. 正面、傷などのアップ、銘板の写真を撮影し、付属品、手渡し方法、販売価格を整理します。
2. Grok Bot のサイドバーで `+` をクリックし、「新規Bot作成」を選択して「闲鱼出品アシスタント」と命名します。
3. 実物の写真をアップロードしてプロンプトを送信します（89元の中古Logicool K380sキーボードの例）：

```text
帮我做一份闲鱼上架资料。商品是罗技 K380s，黑色，用了 8 个月，空格键有轻微磨痕，逐键输入正常，没拆过机；附两节在用电池，无包装，卖 89 元，支持自提，邮费待确认。查官方型号资料，整理标题、商品描述、需要补拍的照片和常见咨询回复，做成可打开的资料板，并附可复制的上架正文。没提供的信息标为待确认。
```

4. BotがWeb検索で公式サイトのスペックを調べ、HTML情報シートとプレーンテキストの下書きを生成します。

## 事例 2：小红书エディター（企画立案から6枚の知識カード＆ギャラリー生成まで）

![事例 2：小红书エディター（企画立案から6枚の知識カード＆ギャラリー生成まで）](/info/15-ecommerce-s2.png)

### 作成手順

1. Grok Bot のサイドバーで新規Botを作成し、「小红书エディター」と命名します。
2. テーマと要点を決定し、カード枚数を6枚に定め、1080×1440のサイズとメインカラー・サブカラーを設定します。
3. 対話画面に入り、以下のプロンプトを送信します：

```text
给电脑新手做一套小红书图文，主题是“Windows 截图后，图片去哪了”。查微软官方资料，做 6 张 1080×1440 的图：封面、框选截图、整屏保存、当前窗口、剪贴板历史、快捷键对照表。用米白、深蓝和亮黄，文字清楚，配操作示意。直接交 PNG 成图、SVG 源文件和配套发布正文，再做一个能看全套图片的画廊。
```

4. **Botが公式ドキュメントを参照してショートカットキーを確認**し、SVGを生成してPNGをレンダリング、HTMLギャラリーにまとめます。

### 検収基準と注意点

| カード | 内容とレイアウト |
| :--- | :--- |
| 1枚目 | 表紙：中央の大きな文字でスクリーンショットに関する悩みを提示 |
| 2〜5枚目 | 手順カード：範囲選択、全画面などのキャプチャ方法を図解 |
| 6枚目 | まとめカード：4種類のキャプチャ方法と保存先一覧表 |

- カード全体でオフホワイトの背景に濃紺のテキスト、アクセントに鮮やかな黄色を使用します。**1080×1440のPNG画像6枚、SVGソースコード、ハッシュタグ付きの投稿本文、オンラインギャラリーが納品物として揃っている必要があります**。
- スクリーンショットの自動保存はシステムのピクチャ設定に依存します。また、**Win + V による履歴確認は事前に設定を有効化しておく必要**があり、履歴が上書きされていないことが前提となります。
- 誤字脱字の修正はテキストエディタで直接SVGを修正すればよく、**画像を再生成し直す必要はありません**。

## 事例 3：ツール情報リサーチ（用途別にフィルタリング可能なソフトウェア分析レポート）

Miles Ma が作成した「ツール情報リサーチ」Botは、オープンソースリポジトリや公式ドキュメントを収集し、カテゴリ別にフィルタリングできるWebカード型レポートを生成します。

### ツールの制限事項と推奨タスク

| ツール | 導入ハードルと依存関係 | 主な制限事項 | 推奨タスク |
| :--- | :--- | :--- | :--- |
| **PowerToys** | Windowsインストーラーで直接実行可能 | Windows限定、一部の実験的機能で動作が不安定になる場合あり | ショートカットキーによるテキスト抽出やウィンドウの最前面固定 |
| **MarkItDown** | Pythonまたはコマンドライン環境が必要 | 複雑な図表レイアウトの認識精度に限界あり | WordおよびPDFからMarkdownへの一括変換 |
| **changedetection.io** | Dockerまたはサーバー環境が必要 | インフラ運用の知識が必要、スクレイピング対策の影響を受ける | ECサイトの価格タグ変動の監視 |

### 操作手順

1. Grok Bot のサイドバーで新規Botを作成し、「ツール情報リサーチ」と命名します。
2. 調査対象の読者層とターゲットツールのリストを確定します。
3. 対話画面に入り、プロンプトを送信します。

```text
帮内容工作室整理 PowerToys、MarkItDown 和 changedetection.io，查官方仓库和文档。每个工具写清能帮忙做什么、上手需要什么、主要限制，再给一个具体使用例子。做成能按用途筛选的网页简报，附来源链接。
```

4. Botがリポジトリの説明や依存関係をスクレイピングし、**フィルタリング用スクリプトを含むHTMLレポートを作成**してワークスペースに保存します。

### 検収基準と注意点

- 各カードにはツールの位置付け、導入前提条件、主な制限事項、実践タスク、公式サイトのリンクなど、**6つの重要要素が含まれていること**。
- Webページ上部にカテゴリボタンが配置され、カードをスムーズに絞り込めること。
- 制限事項の説明は必ず客観的に行い、changedetection.io にはDockerやサーバーが必要であることを明記し、「ハードルゼロ」などと誇張しないこと。
- これはデスクリサーチによるスクリーニングであり、**Botが全工程の実機テストを行うわけではありません**。導入要件を満たさない候補ソフトウェアを迅速に除外することを主目的とします。

## 事例 4：動画チュートリアルクリエイター（インタラクティブ教材ツール＆字幕付きショート動画）

これは Miles Ma（@miles_mazy、着想元は @0xlangeai）による活用法です。ルービックキューブの時計回り・反時計回りの回転や4回回転による復元は、文章だけで説明するのが難しく、人間が撮影するのも時間がかかります。**Grok Bot はクラウド上でインタラクティブなWebページを構築し、画面録画から字幕の焼き込みまでを自動化できます**。

### 実装手順

1. サイドバーで新規Botを作成し、「動画チュートリアルクリエイター」と命名します。
2. 完全な解法アルゴリズム全体を扱わず、**1回のセッションで1つの基本動作のみに絞って解説**します。
3. 以下のプロンプトを送信します：

```text
给孩子做一个魔方入门小工具，能认识六个面、点按钮演示右面顺转和逆转，再展示右面连续转四次回到原位。把实际操作录成一分钟左右的教学视频，加中文配音和字幕，交付视频和工具文件。
```

4. Botが自動的にWebページを作成し、クリック操作をシミュレートして画面録画を行い、中国語字幕付きの動画を生成します。

### 到達基準（クオリティの目安）

| 納品物 | 検収基準 |
| :--- | :--- |
| **インタラクティブWebページ** | HTML/JSソースコードが保存され、Rをクリックで色が変わり、R'で元に戻り、リセットボタンで4回回転して初期位置に戻ること。オフラインで開けること |
| **完成版動画** | 約51秒のMP4およびSRT字幕ファイル。画面の動作と字幕のタイミングが一致していること |

管理画面のデモや特定の単機能チュートリアルを作成する際にも、このパターンをそのまま応用できます。

## 事例 5：ブックマーク整理マネージャー（SNSのブックマークを企画ネタ帳へ変換）

![事例 5：ブックマーク整理マネージャー（SNSのブックマークを企画ネタ帳へ変換）](/info/15-ecommerce-s5.png)

Miles Ma（@miles_mazy）が作成したこのBotは、ブックマークしたコンテンツを企画ネタのストックに変換します。

### 操作手順

1. サイドバーで新規Botを作成し、「ブックマーク整理マネージャー」と命名します。
2. 代表的なリンクを5種類選びます（ポッドキャスト第115回、画像・テキスト変換など）。
3. 以下のプロンプトを送信します：

```text
整理这几条 X 收藏链接，按主题分类，每条留下作者、原链接、核心观点和可以借鉴的写法。再围绕“给新手的 AI 实操教程”提出三个具体选题，做成 Markdown 素材库和选题清单。
```

4. Botが整理を行い、「ブックマーク素材集」と「企画提案」の**2つのMarkdownファイル**を生成します。

### 検収基準と制限事項

- 検収基準：**元の著者名と元リンクを保持**し、文章構成のロジックを分解したうえで、3つの企画を「1回の作業で即座に実行できる粒度」まで具体化すること。
- 制限事項：**他人の実践結果やデータを自分の体験であるかのように捏造することは厳禁**とし、構成の思考プロセスのみを参考にすること。

## 事例 6：Amazon運用チームの構築（フロント巡回から「1＋12」の複数役割連携まで）

![事例 6：Amazon運用チームの構築（フロント巡回から「1＋12」の複数役割連携まで）](/info/15-ecommerce-s6.png)

### 背景と役割の定義

- **実践者**：Zach（@1999Zach22）。
- **実施内容**：元々ローカルの Claude / Codex で実行していたSkillを全面的に Grok Bot へ移行し、共有クラウドPC上に「船長1名＋12の業務担当」からなるAmazon越境EC AI運用チームを立ち上げました。

### 概要

Codex CLI などのローカルツールはPCを常時起動しておく必要があり、外出先から確認できません。一方、**Grok Bot は24時間稼働の米国クラウドPCを標準搭載**しており、スマートフォンとPCの間でシームレスに連携できるほか、実際の購入者アカウントを使ってAmazonのフロントエンドを閲覧したり質問したりすることも可能です。

Zach 氏は**「船長1名＋12の業務担当」**というアーキテクチャを採用しています。ユーザーは船長のみとやり取りを行い、船長が各担当ポジションを統括・スケジューリングします。

**すべてのポジションにおいて、店舗の管理画面を直接変更することは厳格に禁止**されており、人間が確認するための「承認待ちリスト」のみを出力します。

| 担当ポジション | 主な責務 | 厳禁とされる境界線 |
| :--- | :--- | :--- |
| 出海船長 | 部下の統括・割り振り、週報とリストの報告 | 人間を通さずに直接ビジネス上の意思決定を下すこと |
| アシスタント / ハイジャッカー対策 / VOC（顧客の声） | 相乗り出品の巡回、商品リサーチ、低評価レビューの分析 | 出品者管理画面にログインすること、無断でプロジェクトを立ち上げること |
| 財務 / 広告運用担当 | 単品利益の試算、広告運用の提案書作成 | 管理画面にログインして入札額を変更したり除外キーワードを追加したりすること |
| コピーライター / デザイナー / ゲートキーパー（監査） | 広告文や画像の出力、コンプライアンス最終審査 | 直接本番に公開すること、人間に代わって最終決定すること |
| 振り返りBot | 週次成果の集約、ナレッジベースの更新 | 運用上の課題を隠蔽すること、実績を捏造すること |

### 実践ステップ

#### 1. サブスクリプションプランと環境の準備
- **入門には月額30ドルのPremiumプランを選択**（月額8ドルのPlusプランにはBot機能が一切ありません）。必要に応じて月額100ドルのSuperプランや月額200ドルのUltraプランへアップグレードします。
- PCとスマートフォンで同一アカウントにログインし、**クラウドPCが正常に稼働していることを確認**します。詳細は [Grok Bot プランと利用量ガイド](https://cursor.com/cn/help/grok-bot/plans) を参照してください。

#### 2. まずは単一のBotで3つのタスクを通しで検証
クラウドPCの米国IPとブラウザを使用して、以下の3つの検証を完了させます：
1. **自社出品（Listing）の日常巡回**：メイン画像、価格、バリエーション、相乗り出品をチェックし、異常があれば前日との比較証拠を添えて報告。
2. **AlexaショッピングQ&Aのテスト**：購入者アカウントでログインして質問を行い、約8分間で8種類のシナリオをテストし、過去30日間の価格履歴を調査。
3. **競合商品の定期モニタリング**：価格やクーポンを記録し、**変動があった場合のみ通知**（変動がなければ通知しない）。

```text
每天固定时间去前台检查自家 Listing：主图和价格是否正确，变体是否正常挂载，核心关键词是否能搜索到，是否存在跟卖。只记录指定商品和关键词，有异常才发提醒，并附带与前一日的对比数据和页面截图证据。不登录店铺后台，不执行任何写操作。
```

```text
从消费者的角度，尽可能多地把 Alexa for Shopping 体验一遍，最后给我一份报告。
```

#### 3. 機能の分解と各ポジションの境界線設定
- 単一Botで検証が完了したら、タスクを12の業務担当ポジションに分割します。
- 広告運用や新規出品などの**センシティブな担当ポジションには、管理画面への書き込みを明確に禁止**し、すべて「承認待ちリスト」として成果物を提出させ、判断を仰ぐ境界線を明示します。

```text
你是合理烧钱的广告投手。负责分析广告效率、搜索词转化率、出价与预算建议。
边界约束：
1. 绝对不登录广告后台，不直接修改出价，不调整预算，不添加否定关键词，不新建广告活动；
2. 所有优化建议必须生成「待批清单」，每条建议必须附带调整依据和预期影响；
3. 待批清单单线交付给出海船长，由船长提报给业务负责人审核，严禁自主执行。
```

#### 4. 「1＋N」のタスク引き継ぎチェーンの設計
- **複数のBotによるグループチャットは絶対に作成しないでください**。グループチャットでは全員がコンテキストを重複して受信するため、Tokenが瞬く間に枯渇します。
- **1＋Nアーキテクチャを採用**し、人間は「出海船長」のみとやり取りを行い、船長がタスクを割り振って結果を集約します。

```text
你是出海船长，负责统筹 12 个业务岗位。日常接收业务负责人的目标，拆解为具体子任务派发给对应岗位。所有下属岗位向你单线汇报，由你汇总结果、审核质量；不达标的打回重做，需要人工决策的整理为带选项和依据的待批清单汇报给人。严格遵守交接链规则：
1. 巡检链：助理上报异常与证据，派给数据或广告岗位做归因分析；
2. 选品链：海盗提交机会报告，财务测算单品利润，由你整理为立项建议书提报给人；
3. 上新链：文案出草稿，设计出图，守门员审核，你做终检后交给人确认，由人工在后台发布；
4. 复盘链：收齐各岗位经验，复盘机器人写周报并更新经验库，据此编排下周计划。
所有岗位严禁直接登录店铺后台或执行未授权的修改操作。
```

#### 5. アセットの共有とローカルPCの実行制御
- すべてのBotが**同一のクラウドPCおよびディスクを共有**するため、スクリプトをワークスペースに配置すれば全員が利用可能になります。
- ローカルファイルを読み込むには、設定の「コンピュータ」ページで**「このコンピュータ上で実行」（Execution on Local Computer）を有効化**し、コピー先ディレクトリを指定する必要があります。

  詳細は [Grok Bot コンピュータとアプリケーションドキュメント](https://cursor.com/cn/docs/grok-bot/work) および [Grok Bot 設定ガイド](https://cursor.com/cn/docs/grok-bot/settings) を参照してください。

## 陥りやすい注意点（落とし穴）

- **出品者管理画面への変更権限は絶対に付与しない**：機密・重要な操作はBotに「承認待ちリスト」として出力させ、人間が手動で実行することで、価格設定ミスやアカウント停止を防ぎます。
- **闲鱼出品での勝手な状態補完を防ぐ**：「売り手から提供された情報のみを基準とし、未提供の項目は要確認と明記する」と指示することで、公式の新品スペックが紛れ込んで返品トラブルに発展するのを防止します。
- **12個のBotを1つのグループに入れない**：数往復のやり取りだけで1週間分の利用枠を使い果たしてしまいます。「1＋N」のマスター・スレーブ構成を採用し、ファイルのディスク保存を介してデータを受け渡してください。
- **競合データの収集は1日1回が適切**：数分おきのポーリングはIPブロックのリスクが非常に高く、利用枠も消費します。高頻度の監視が必要な場合は公式APIやMCPを利用してください。
- **月額30ドルのPremiumプランを選ぶ**：月額8ドルのPlusプランにはBotへのアクセス権がありません。2026-10-12以降の「The X Subscription」を確認してください。
- **ローカル制御はパス制限を徹底する**：「常に許可」には設定せず、制御前にファイルパスを限定したうえでポップアップ確認を残し、プライベートなファイルの誤操作を防いでください。

## 完了後の検収方法

**成果物が納品されたら、基準に照らし合わせて1項目ずつ慎重に検証**してください。油断は禁物です。

- **闲鱼情報シート**：傷などの瑕疵と公式スペックが別々に記載され、不明な項目には「要確認」と明記されていること。手渡し場所の勝手な指定やバッテリー状態の虚偽記載がないこと。
- **小红书画像・テキスト**：1080×1440の画像カード6枚とSVGソースコードが揃っており、操作手順でショートカットキーやシステムの前提条件が明示されていること。カラーパレットが崩れていないこと。
- **ツールレポート**：単一のHTMLページにフィルタリング機能と公式リンクが備わっており、Dockerなどの環境要件・制限事項が正確に記載されていること。導入難易度を「誰でもすぐできる」などと誇張していないこと。
- **チュートリアル動画**：完成動画が約1分間で音声と映像が同期しており、Web教材ツールのソースコードが添付されていること。字幕と映像のタイミングがずれていないこと。
- **素材集**：元の著者名と元リンクが明記され、企画ネタが1回の実践タスクで実行できる粒度に落とし込まれていること。中身のない要約や、他人の事例を自分の体験のように扱っていないこと。
- **EC協調運用**：1＋Nアーキテクチャのもとで船長のみとやり取りを行い、価格変更や出品には必ず承認待ちリストを出力させること。勝手な価格改定や無限ループによる利用枠の枯渇を厳禁とすること。
