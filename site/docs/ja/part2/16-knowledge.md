# 第 16 章 事例：ナレッジ自動取り込みと WeChat 連携

スマートフォンのブックマークは散らかりがちで、グループチャットのファイルはすぐに期限切れになり、外出先ではクラウドで **24時間365日** 稼働している Grok Bot を活かしきれません。

1. Web ページとショート動画：Webhook と iOS ショートカットを連携させ、**ワンタップで構造化して取り込み**。
2. スクリーンショットと音声録音：WeChat の転送では添付ファイルを引き継げないため、**パブリックな一時中継ストレージを経由**してエクスポート。
3. 対話・タスク実行：公式の「微信ClawBot」プラグインとロングポーリングを利用し、**WeChat のトーク画面から直接 Grok Bot を呼び出し**。

## 3つの自動化ソリューションの機能と制約の比較

![3つの自動化ソリューションの機能と制約の比較](/info/16-knowledge-s1.png)

| ソリューションと利用シーン | 仕組みと認証 | 注意点・落とし穴 |
| :--- | :--- | :--- |
| 一方向取り込み（Web ページ、公式アカウント記事、ショート動画） | ショートカットから Bearer キー付きで Webhook に POST して取り込み | 一方向の受信のみ |
| マルチモーダル取り込み（WeChat トーク履歴、録音、スクリーンショット複数枚） | テキストは直接送信。ファイルは filebin.net の一時オンラインストレージを経由して公開リンクを生成し、Bot が解凍して取り込み | **ストレージはパスワードなしのため機密情報送信禁止**。大容量アーカイブのフレーム抽出は token 消費が多い |
| WeChat 双方向（指示送信、資料検索、Bot 呼び出し） | WeChat の QR コードスキャンで連携。iLink とクラウドスクリプトで待機し、Webhook に転送してプレーンテキストを返送 | **空回りのリソース消費を防ぐため頻度制限が必要** |

## 事例1：Webhook とショートカットによるナレッジ自動取り込みパイプラインの構築

![事例1：Webhook とショートカットによるナレッジ自動取り込みパイプラインの構築](/info/16-knowledge-s2.png)

**本ソリューションでは、スクレイピング、音声・動画の文字起こし、要約のすべてを Grok Bot クラウド側で処理し、スマートフォンからは URL を送信してトリガーするだけです。

** 铁柱AGI（@cgnot996）は[ルーティン](https://cursor.com/cn/help/grok-bot/routines)の Webhook を利用し、リクエスト送信即起動を実現しました。

### 構築手順
1. デスクトップ版の Details から Routines を開きます。Bot に解析タスクを作成させ、**生成された Webhook URL と key を大切に保管**します。
2. ショートカット「ナレッジベース Bot へ送信」を新規作成し、「URL の内容を取得」を追加して表のとおりパラメータを設定します。

| パラメータ | 設定値 |
|---|---|
| URL | Webhook アドレス |
| 方法 | POST |
| ヘッダー | キー名 `Authorization`、値 `Bearer <key>` |
| リクエスト本文 | JSON を選択し、「ショートカットの入力」を追加 |

3. **閉鎖的なアプリ向けに補助入力ダイアログを追加**。WeChat では共有シートが無効化されていることが多いため、2つ目のショートカット（「メニューから選択」と「テキストを要求」）を中継用として作成し、iPhone のアクションボタンに割り当てて、ボタンを押すだけで貼り付けて送信できるようにします。

## 事例2：WeChat トーク履歴とマルチモーダル素材の連携・取り込み

### 事例の概要
- WeChat のまとめ転送をパッケージ化して Grok Bot に送信すると、自動解凍されて結果（受領証）が返信されます。
- **filebin.net を踏み台として利用し**、ローカルパスへの依存を排除。
- Mac と iPhone に **5つの取り込みモード** を備えたショートカットを配備。

### 概要：なぜ一時的なオンラインストレージの中継が必要なのか

デバイス間ではローカルディスクを直接読み取れず、WeChat の大容量 ZIP ファイルをリクエスト本文に直接含めるとタイムアウトしやすいためです。

1. テキストは JSON 経由で直接送信します。
2. 画像、録音、ZIP ファイルはまず filebin.net にアップロードし、そのリンクを Bot に送信してダウンロードさせます。
3. ストレージ ID には、名前の衝突による情報漏洩を防ぐため、**最低8文字のランダムな英数字**を使用する必要があります。
4. ファイルはデフォルトで7日間保持され、暗号化されていないため、**プライバシー情報や機密情報の送信は厳禁**です。

### 実践：ステップ別の構築手順

#### 1. Webhook の設定
デスクトップ版のメインチャットで次のプロンプトを送信します：

```text
帮我创建一个 Webhook 触发的例行任务。快捷指令会用 POST 请求发来一个 JSON，里面只有一个字段 info。info 可能是我输入的文字，也可能是一个文件下载链接，比如微信聊天记录压缩包、截图、录音。收到后：如果是链接就先下载文件再读取，压缩包先解压；然后整理出要点，收录进知识库，最后给我一份回执，写清楚收录了什么、存在哪里。
```

**送信後、Bot の「ルーティン」で Webhook URL と key を記録します。**

#### 2. ショートカットの設定
インポートリンク：`https://www.icloud.com/shortcuts/2b77155d7c744110a0f0f9ef1bdc42bf`
「【共有版】ナレッジベース Bot へ送信」を編集し、URL、key、および **8文字以上の複雑なストレージ ID**（例：kb7x9m2q）を入力します。ヘッダーは組み込み済みのため変更不要です。

#### 3. WeChat トーク履歴の取り込み
- **Mac 版**：他のアプリへまとめ転送する際に該当のショートカットを選択し、「転送を受信」をクリック。ZIP がオンラインストレージにアップロードされてリンクが送信され、Bot が即座に処理を開始します。
- **スマートフォン版**：まとめ転送時に該当のショートカットを選択し、「転送を受信」をタップ。「アクションを編集」からよく使う項目に固定しておくことも可能です。

#### 4. 単独での呼び出しと収集
Mac では Raycast やメニューバーから、スマートフォンではアクションボタンに割り当てて呼び出します。
- スクリーンショット／録音：確認または録音完了後、オンラインストレージにアップロードしてリンクを送信。
- テキスト入力：オンラインストレージを経由せず、**JSON に直接含めて送信**。
- 画像を選択して補足：画像を選択した後に説明を入力し、まとめてアップロード。
- 転送を受信：コンテンツを受信していない場合は、クリップボードの内容を読み取って送信。

## 事例3：Grok Bot を WeChat に直接接続して双方向にタスクを実行する

![事例3：Grok Bot を WeChat に直接接続して双方向にタスクを実行する](/info/16-knowledge-s4.png)

### 事例の概要
Kin 氏は Grok Bot を WeChat に連携させ、**スマートフォンからメッセージを送るだけでクラウド上の Bot を遠隔操作**できるようにしました。

1. Grok に iLink を呼び出すロングポーリングスクリプトを作成させる
2. 指示を受信する Webhook を構築する
3. WeChat で「微信ClawBot」を有効化し、QR コードをスキャンして連携する

完全なアウトバウンドロングポーリングを採用しているため、**パブリックな受信ポートを開放する必要はありません**。

### 概要：微信ClawBot と iLink のロングポーリングの仕組み

本ソリューションは公式の「微信ClawBot」プラグインと iLink インターフェース（`ilinkai.weixin.qq.com`）を利用しており、クライアントのメモリ改変を行わないため、**アカウント停止のリスクがありません**。

通信はすべてアウトバウンドリクエストであり、**パブリックポートの開放は不要**です：
1. Grok Bot がバックグラウンドで `getupdates` をポーリングしてメッセージを取得し、処理完了後に `sendmessage` を呼び出して返信します。
2. Webhook でテキストを受信後、各専門 Bot に引き渡して連携処理を行います。詳細はドキュメント[Grok Bot の使用](https://cursor.com/cn/docs/grok-bot/work)をご覧ください。

### 実践：ステップ別操作手順と完全なプロンプト

1. PC 版のメインチャットでプロンプトを送信し、「微信下旨入口」ルーティンが作成されるのを待ちます。
::: details 実践：ステップ別操作手順と完全なプロンプト
```text
我想把你接到我的微信上，让我能在微信里直接给你发消息、收到你的回复。请按下面的思路做，每做完一步告诉我结果，需要我操作的地方停下来等我。

1、先调研方案：腾讯「微信ClawBot」插件用的是 iLink 接口（ilinkai.weixin.qq.com）。请确认怎么用 getupdates 长轮询收消息、怎么用 sendmessage 回消息。整个程序只走出站请求，不要开公网端口。

2、在 Grok Bot 里建一个由 webhook 触发的 routine，名字可以叫「微信下旨入口」。建好后告诉我去 routine 面板复制 Webhook URL 和 key，然后弹出加密弹框让我填进去，不要让我在聊天里发明文。

3、在你的云端电脑上写一个小转发程序：收到微信消息后 POST 给这个 routine；你处理完以后，用一个 reply 脚本把回复发回微信，同时在我们的主聊天里同步一份。

4、等我在手机微信里启用 ClawBot 插件以后，生成二维码让我用手机扫码确认，同时给我一个可以在微信里直接打开的备用链接。二维码大约 5 分钟有效。

5、绑定成功后，提醒我先在 ClawBot 对话里发一句话，因为回复要用到这条消息带的 context_token。

6、规则：只认绑定的这一个人，别人的消息不处理；回复一律用纯文本，不要用 Markdown，因为微信不渲染 Markdown。

7、最后告诉我：云端电脑重启以后，怎么把转发程序重新拉起来；如果遇到错误码 -14（凭证过期），提醒我重新扫码。
```
:::
2. ルーティンの URL と key をコピーします。**チャット欄に平文で送信することは厳禁**です。シークレットカードに入力し、「安全に保存され、非公開に保たれています」と表示されれば完了です。詳細は[機密情報の安全な保管](https://cursor.com/cn/help/grok-bot/secrets)をご覧ください。
3. WeChat のバージョンは **iOS 8.0.70 / Android 8.0.69 以上** である必要があります。「自分」->「設定」->「プラグイン」で赤いロブスターのアイコンの「微信ClawBot」を有効化します。
4. 「プラグインを有効化しました」と送信し、WeChat で QR コードをスキャンして認証します（QR コードの有効期限は **5分間** です。期限切れの場合は予備リンクを使用してください）。
5. **必ず WeChat 側から最初にメッセージを1通送信してください**（例：「こんにちは」）。API が接続確立のために `context_token` を取得する必要があるためで、送信が完了すると通信チャネルが正式に確立されます。

## よくある落とし穴

1. 転送する前に**必ずローカルで添付ファイルをタップしてダウンロード**してください。そうしないと、エクスポートされた ZIP にプレースホルダーのテキストしか残りません。
2. filebin.net にはパスワードがないため、`test` や `123456` などの安易な文字列は避け、**必ず8文字以上のランダムな文字列を設定**してください。身分証、銀行カード情報、機密契約書などのアップロードは厳禁です。
3. Webhook の設定時にチャット欄へ直接 key を貼り付けず、**シークレットカードを使って安全に保存**してください。ショートカットを共有する前には、個人の key や URL を必ず削除してください。
4. ClawBot の QR コードは5分で無効になります。応答がない場合や `-14` が返される場合は**認証情報が期限切れ**であることを意味するため、再生成してスキャンし直す必要があります。
5. クラウド PC がリセットまたは再起動されると Python のポーリング処理が停止します。WeChat から応答がない場合は、デスクトップ側で **Bot にスクリプトを再起動させて**ください。
6. WeChat は Markdown をレンダリングしないため、**Instruction でプレーンテキストでの返信を強制**し、`**` や `#` などの記号を出力しないようにします。
7. iLink キューでのメッセージ競合による指示の取りこぼしを防ぐため、**複数の OpenClaw リスナーを同時に実行しないでください**。
8. The X Subscription は週ごとのクォータから差し引かれるため、**高頻度でトリガーされる処理には必ずフィルタリングを入れてください**。消費が早すぎる場合は、不要なルーティンを一時停止するか、トリガー条件を緩和してください。

## 完了後の検証手順

1. **Webhook のテスト**：`Authorization: Bearer <key>` を付与した POST リクエストを送信します。**ステータス 200 が返ってくれば成功**です。401 はキーの誤り、404 は URL の誤りです。PC 側の「ルーティン」のステータスが Running… に変わり、ログが出力されていれば問題ありません。
2. **ショートカットのテスト**：テキストを送信して数十秒以内に結果（受領証）が返ってくるかをテストし、画像2枚を転送してアーカイブをテストします。スクリーンショットは必ずアクセス許可のプレビューが表示され、「許可」をタップして初めて送信される挙動になっていることを確認します。
3. **WeChat と同期のテスト**：「微信ClawBot」にメッセージを送信し、**5秒以内に返信があれば成功**です。さらに PC 側を確認し、チャット履歴が同期されていれば完全に開通しています。
