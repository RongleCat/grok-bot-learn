# 第13章 事例：Xでのコンテンツ制作と運用

直接スクリプトを書いて投稿APIを高頻度で呼び出すと、リスク管理によってアカウント停止（BAN）されやすく、数日で1週間分の枠（クレジット）を使い果たしてしまいます。

- クラウドVMパイプラインを構築し、WeChatで一言指示を送るだけで、自動的にトピックを検索して初稿を作成します。
- **下書きの作成のみに留め、人間が手動でクリックして投稿する**という原則を守ることで、アカウントの安全を確保しつつ、機械的な単純作業を肩代わりさせます。

## Xプラットフォームのネイティブ機能：読み取り専用検索からリプライ欄でのタスク割り当てまで

![Xプラットフォームのネイティブ機能：読み取り専用検索からリプライ欄でのタスク割り当てまで](/info/13-x-ops-s1.png)

2026-10-08にネイティブの読み取り専用機能がリリースされ、ポスト検索と7日間のトレンド調査はサブスクリプションプールから消費されるようになりました。

2026-10-11の v0.70.2 でアカウント連携なしでの公開ポスト検索に対応しました。[記録](https://jcng5q8n0f3z.feishu.cn/wiki/ZRFQwIlNgiuJTVkGcJgcrZhsnKd)を参照してください。

|タイプ|アクション|ルールとリスク管理|
|---|---|---|
|ネイティブ読み取り専用|ポスト検索、単一ポスト解析、7日間のトレンド|サブスクリプションプールを消費、アカウント停止リスクなし|
|外部トリガー|リプライ欄での `@bot` 抽出・アーカイブ|スター付きメインBotへルーティング、自動リプライは厳禁|
|アカウント書き込み|ポスト投稿、DM、ブックマーク閲覧、いいね|公式APIを経由、**ヘッドレスブラウザでの投稿は厳禁**|

### 実施方法
1. **対話ウィンドウ**：「過去3日間にXXという話題がどのように評価されているか調べて」と入力するか、リンクを貼って「このポストのコアな視点と読者の議論・対立点を抽出して」と指示します。
2. **リプライ欄**：`@bot 提取本帖核心逻辑并存入选题库` と返信します。[説明](https://jcng5q8n0f3z.feishu.cn/wiki/HHmpwgN4qi86e0kgBvAc1156nkg)を参照してください。

### 検収基準
- **完全な抽出**：元の情報源、投稿日時、議論の流れをすべて取得できていること。
- **応答の境界**：タスク指示後 **30秒以内にログが出力** され、下書きのみを作成して代理投稿は行わず、自動でのいいねや投稿を絶対に行わないこと。

### スケジューリング設定手順

1. 5つのテンプレートを自身のアカウントに追加します。
2. メインBotを1つ選び、スケジューリングの入り口とします。
3. **初期化プロンプトをメインBotに直接送信し、アカウントの方向性（ポジショニング）、各担当者のルーティング、および執筆ルールを永続コンテキストに書き込みます。**

プロンプトの内容は『WeChatで一言言うだけでXを運用できる：私の5つのBotテンプレートを公開』[https://jcng5q8n0f3z.feishu.cn/wiki/DJwawbQxeiUcIjkKbekcVkHRnye](https://jcng5q8n0f3z.feishu.cn/wiki/DJwawbQxeiUcIjkKbekcVkHRnye) から引用しています。

::: details スケジューリング設定手順
```text

2. 确认我的账号定位
一次只问一个关键问题，了解主题、目标读者、我能提供的价值和不写的话题。也可以分析我授权提供的主页和近期帖子，提出建议，等我确认。把已确认定位和表达偏好持久保存，并同步给相关专员。不要继承模板作者的个人信息。

像跟朋友分享：讲清发现、理由和具体用途，允许适量语气词，不堆口号。不编我的亲历、数字、测试结果或涨粉成绩。原帖保留归属，新闻核对来源和日期。默认沿用这些要求，我另有要求时再调整。
你交付前检查事实、来源、定位和可读性。来源和说明放在草稿外，方便我看，也方便复制正文。检查X可发布长度，超出则给短版或说明需要的账号功能。

6. 根据真实反馈改进
记录已发布内容和表现，提出下一轮调整。日常选题和写作规则的小改动留版本、可回退；账号定位、授权范围、发布权限、定时安排或新增收费服务变更先问我。小样本形成试验建议，不宣称已验证涨粉规律。

默认只起草。发帖、回复、点赞、关注和私信由我另行决定，不自动执行。
```

設定が完了すると、メインBotは配下の各BotのIDを記憶します。日常的にトピック選定から原稿作成までのタスクを依頼すると、メインBotが自動的に情報ディレクターを呼び出して素材を収集させ、それをショートポスト執筆に引き継ぎ、最終的な初稿を提出します。

### 検収基準

チャットウィンドウでメインBotにトピック選定と原稿作成のテストを1回実行させます。合格基準として次の2点を満たす必要があります。
- **マルチAgentの実稼働リレー**：メインBotと各担当Botのバックグラウンドログにおいて、タスクの割り当て、サブBotによる実際の実行、および結果の返却プロセスが確認できること。
- **下書きの品質とフォーマット規約**：返却された下書きに機械的なスローガンが含まれず、元の情報源や説明文が本文と混ざらずに本文の下に整然と配置されていること。

## 下書き作成に限定するヒューマンゲートウェイ設計と安全境界

![下書き作成に限定するヒューマンゲートウェイ設計と安全境界](/info/13-x-ops-s4.png)

自動投稿で万が一モデルのハルシネーション、日付の誤り、不適切なリプライが発生すると、取り返しのつかない損害をもたらします。**パイプラインの最終端には必ず安全のためのヒューマンゲートウェイを設け、投稿、いいね、フォロー、DM、削除の5つのアクションを完全にブロックし、モデルには下書き作成のみを行わせる必要があります。**

::: details 下書き作成に限定するヒューマンゲートウェイ設計と安全境界
```text
[微信一句话 / 定时触发] 
       │
       ▼
[主 Bot 调度中心] ───► [情报总监 / AI新闻雷达 抓取素材]
       │
       ▼
[推文二创 / 短推成稿 编写草稿]
       │
       ▼
[主 Bot 事实与长度校验]
       │
       ▼
[推送到手机微信 / 客户端对话框] ───► (停住：系统不具备自动发帖权限)
       │
       ▼
[人工审阅：修改、定夺] ───► [人工手动复制到 X 发布]
```

### 2層防御設定

1. **プロンプトでの厳格な指示**：メインBotおよび各担当Botのプロンプト末尾に次のように固定記述します：
   「デフォルトでは下書きのみを作成すること。投稿、リプライ、いいね、フォロー、DMはユーザーが別途判断するため、自動実行してはならない。情報源と説明文は、人間が確認しやすく本文のみをワンクリックでコピーできるよう、必ず下書きの外に配置すること」。
2. **システムレベルの遮断**：Grok Bot の Settings → Custom Rules（または Auto-review）で、**`send`、`post`、`buy`、`transfer`、`delete`、`permissions` を含む操作をすべて「Ask first」にチェックします**。ユーザーが明示的にクリックして承認しない限り、基盤側で実行されることは絶対にありません。

設定規約は『4.3 トリガーと自動化：定期実行、Webhook、Xでのタスク割り当て』[https://jcng5q8n0f3z.feishu.cn/wiki/HHmpwgN4qi86e0kgBvAc1156nkg](https://jcng5q8n0f3z.feishu.cn/wiki/HHmpwgN4qi86e0kgBvAc1156nkg) を参照してください。

### 検収基準

実際のテスト時に「この下書きを私のXプロフィールに直接投稿して」と指示を出し、合格基準として以下の2点を満たす必要があります：
- **遮断が機能すること**：Botが実行を明確に拒否するか、システム側で Ask first の承認遮断カードがポップアップしてAPI呼び出しを停止すること。
- **フォーマットの準拠**：下書き本文と参考リンクが分離されており、文字数がXプラットフォームの制限を厳格に遵守していること。

### 事例1：Hardy Chen の WeChat一言・5つのBot協調パイプライン

- **誰が**：Hardy Chen（@Chchenhao0129）、個人のコンテンツクリエイター。
- **何を行ったか**：特定機能に特化した5つのBotテンプレートを設定し、WeChat ClawBotプラグインと連携。WeChatで一言要望を送るだけで、Xのトピック発掘、AIニュースの一次選別、ポストの執筆、週次の投稿データ振り返りまでを全自動で完結させました。
- **どうやったか**：
  1. まずWeb版で公式共有されている5つのBotテンプレートを1つずつ追加し、メインBotを選定した上でシステム初期化プロンプトを送信。自身のアカウントのポジショニング、ターゲット読者、および5つの担当Botの永続ルーティングをメインBotへ一度に注入しました。
  2. 続いてWeChatインバウンドWebhookと常駐キープアライブリスナーを設定し、スマートフォンのQRコードスキャンでメインBotをWeChatに接続しました。
  3. 毎日のニュース更新用として、Asia/Shanghai タイムゾーンで毎朝7:30の定期タスクを設定し、AIニュースレーダーにAIHOTから情報を収集・元情報源を確認させ、WeChatへプッシュ通知するようにしました。
  4. 投稿データの分析時には、指示に従って管理画面のCSVファイルを提供し、データ分析担当Botにエンゲージメント実績を整理させ、翌週のアクション指針を策定させました。
- **参考にできるポイント**：
  - 単一の窓口によるスケジューリング体制を構築し、各担当Botに1つずつ個別に指示を出す手間を省く。
  - 初期化プロンプトでアカウントのポジショニングを固定し、指示を出すたびに文体を説明し直す手間を避ける。
  - 下書き納品メカニズムを徹底し、下書きの説明と本文を明確に分けてレイアウトする。
  - WeChatに接続しても返信がない場合は、「リスナープロセス → キープアライブタスク → メッセージ重複排除」の標準的な手順に沿って原因を特定し、無闇に連携解除や再スキャンを繰り返さない。
  - 詳細な振り返りは『WeChatで一言言うだけでXを運用できる：私の5つのBotテンプレートを公開』[https://jcng5q8n0f3z.feishu.cn/wiki/DJwawbQxeiUcIjkKbekcVkHRnye](https://jcng5q8n0f3z.feishu.cn/wiki/DJwawbQxeiUcIjkKbekcVkHRnye) を参照してください。

- **誰が**：SCOTTY BEAM（@ScottyBeamIO）、テクニカルソーシャルメディアクリエイター。
- **何を行ったか**：リサーチ担当、ビジュアルクリエイティブ担当、テキスト執筆担当の3つのAgentからなるクラウド自動更新システムを構築。トレンドの発掘、インフォグラフィックの作成、ポストの執筆を全工程自律連携させるとともに、Grok Bot、Buzz、OpenClaw、Hermesの4つのAgentアーキテクチャを横断比較・検証しました。
- **どうやったか**：
  1. Grok Bot のすべてのAgentが基盤のクラウドPCを共有するという特性をフル活用し、リサーチBotがバックグラウンドでXや公開リポジトリのトレンドを検索し、素材をローカルディスクに保存。
  2. ビジュアルクリエイティブBotには、あらかじめ学習させた参考インフォグラフィックのスタイルを適用し、リサーチ素材を直接読み込ませてトーンの統一された画像を生成。
  3. テキスト執筆Botが両者の成果物をまとめて投稿用の下書きを作成。日常的な定型作業については、操作レコーディング機能（Recording）を使ってBotに直接動作を学習させました。
- **参考にできるポイント**：
  - マルチAgentの連携時にクラウドPCの共有ディレクトリをデータハブとすることで、手動コピーやデータ中継の手間を削減する。
  - デザイン系Botに固定の参考画像を与えることで、ビジュアルのトンマナを統一する。
  - 複数Botが参加するチームチャットでは定期実行タスクを保存できないという制約に注意し、スケジューリングルーティンは単一Botの独立した個別セッションで設定する。

### 事例3：铁柱とAYiのXネイティブ検索とリプライ欄 @bot によるナレッジアーカイブ

- **誰が**：铁柱AGI（@cgnot996）と AYi（@AYi_AInotes）、ヘビーテクニカルリサーチャー。
- **何を行ったか**：2026-10-08にリリースされたネイティブの読み取り専用機能と、2026-10-11の v0.70.2 リプライ欄 `@bot` 連携機能を活用し、外部APIを一切使わずに業界インテリジェンスの監視とモバイル端末からのワンタップポスト知識アーカイブフローを構築しました。
- **どうやったか**：
  1. 日常的に対話ウィンドウから自然言語で指示を出し、有料コネクターを一切有効化することなく、任意のキーワードに関するXの過去7日間のトレンド推移や主要な議論ポストを抽出。
  2. スマートフォンでタイムラインを閲覧中に長文ポストや技術解説を見つけたら、リプライ欄で直接 `@bot` と返信し、アーカイブの要件を指示。
  3. スター付きメインBotがシステムイベントを受信すると、自動的にポストの全文を取得してナレッジベースでフォーマットを整形し、Markdownファイルとして仮想マシンの `/home/box` ディレクトリ配下に保存・蓄積。
- **参考にできるポイント**：
  - サードパーティ製スクレイパーの代わりに公式ネイティブの読み取り専用権限をうまく活用し、運用保守の複雑さとアカウントBANリスクを大幅に低減する。
  - モバイル端末でアプリを切り替えることなく、`@bot` を通じて軽量にタスクをトリガーする。
  - データのローカル保存を徹底し、クラウドPC内の主要パスを集約してリセットによるデータ消失を防ぐ。
  - 実践のポイントは『铁柱ポストまとめ②：プロダクト機能とバージョンの観察』[https://jcng5q8n0f3z.feishu.cn/wiki/ZRFQwIlNgiuJTVkGcJgcrZhsnKd](https://jcng5q8n0f3z.feishu.cn/wiki/ZRFQwIlNgiuJTVkGcJgcrZhsnKd) および『4.3 トリガーと自動化：定期実行、Webhook、Xでのタスク割り当て』[https://jcng5q8n0f3z.feishu.cn/wiki/HHmpwgN4qi86e0kgBvAc1156nkg](https://jcng5q8n0f3z.feishu.cn/wiki/HHmpwgN4qi86e0kgBvAc1156nkg) を参照してください。

## よくある落とし穴

### 定期実行タスクとクレジット消費
1. 複数のBotを同じTeam Chatに追加した場合、統一したRoutineを保存できません（SCOTTY BEAM による検証済み）。**必ず個別の個人セッションに戻って単体で設定してください**。
2. 一部のバージョンではデフォルトで平日のみ実行されるため、作成指示には「土日を含め、毎日決まった時間に実行」（铁柱 による検証済み）と明記する必要があります。
3. 北京時間の朝7:30が深夜として実行されてしまわないよう、システム設定でローカルタイムゾーンが Asia/Shanghai になっているか確認してください。
4. Botのクレジット枠はGrokやCursorと共有されており、5分ごとのポーリングでは更新がなくてもコンテキスト全体を読み込んでしまいます。**必ず2段階チェックまたは差分起動（Wake on Done）**に切り替えて一次選別を行ってください。29体のBotを運用する melvindvivas も、生産性の低いルーティンは定期的に整理することを推奨しています。

出典：[『4.3 トリガーと自動化：定期実行、Webhook、Xでのタスク割り当て』](https://jcng5q8n0f3z.feishu.cn/wiki/HHmpwgN4qi86e0kgBvAc1156nkg)

### WeChatとWebhookの接続トラブルシューティング
1. WeChatのQRコードスキャン後に応答がない場合、多くはリスナーのハングアップまたはキープアライブRoutineの停止が原因です。**アカウントの連携解除と再スキャンを無闇に繰り返さないでください**。Hardy Chen の経験則によれば、デスクトップ側からトラブルシューティングのコマンドを送信してプロセスとキューを確認し、新しいテストメッセージを送信して再疎通を図るのが有効です。
2. v0.68.1 時点でクライアントの詳細カードが開かない場合は、チャット欄にそのトリガーの直通リンクをBotに出力させて確認してください。

出典：[『铁柱ポストまとめ②：プロダクト機能とバージョンの観察』](https://jcng5q8n0f3z.feishu.cn/wiki/ZRFQwIlNgiuJTVkGcJgcrZhsnKd)

### プラットフォームのインタラクション制限とホスト環境
1. リプライ欄からのタスク指示は動画のみのポストに対応していません。`@grok` と `@bot` を同時にメンションすると応答しません。悪意あるプロンプトインジェクションを防ぐため、**リプライ欄からのタスク指示には外部への投稿権限を絶対に与えないでください**。
2. 仮想マシンのメンテナンスにより一時パスはリセットされるため、**スクリプト、ドキュメント、バックアップデータは必ず `/home/box` に統一して保存し**、自己修復スクリプトを用意しておいてください。

パス規約：[『铁柱ポストまとめ②：プロダクト機能とバージョンの観察』](https://jcng5q8n0f3z.feishu.cn/wiki/ZRFQwIlNgiuJTVkGcJgcrZhsnKd)

## 完了後の検収方法

1. メインBotに高評価ポストを3件取得させ、作成者ID、主張、投稿日時を確認し、エラーが発生しないこと。
2. コマンドを送信して履歴を確認し、代理執筆を厳禁とした上で、**5つの担当Botによるリレー形式で原稿が完成していることを確認**すること。
3. WeChatのClawBotに「初心者の視点でLLMツールに関するショートポストを1本書いて」と送信し、2分以内に下書きが返信されること。
4. 「先ほど生成した下書きを私のXアカウントに直接投稿して」と指示し、**必ずAsk firstが表示され**、承認しない限り外部へ投稿されないこと。
5. Routineの時刻を合わせる。空ファイルを渡し、振り返り担当Botが欠損をありのままに報告し、データをでっち上げないことを確認すること。
