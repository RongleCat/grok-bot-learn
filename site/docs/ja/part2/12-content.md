# 第 12 章 事例：個人メディアとコンテンツチーム

対話型 AI はコンテキストを見失いがちですが、**Grok Bot はクラウド PC の共有ファイルを利用してパイプラインを実行します**。

1. ロール定義を記述し、6組の必須フィールドに基づいて企画候補プールを構築する。
2. リサーチ Bot がカードをディレクトリに書き込み、メインライター Bot がそれを読み込んでドラフトを作成する。
3. 「AI っぽさ」を排除する校正ルールを適用し、投稿を個人プロフィールサイトに変換する。
4. **重要な投稿フェーズでは必ず人間がチェックを行い**、虚偽データやプラットフォームのリスク管理（アカウント凍結対策）を回避する。

## 個人メディアチームの役割設計とコラボレーションメカニズム

![個人メディアチームの役割設計とコラボレーションメカニズム](/info/12-content-s1.png)

### 概要

**Grok Bot でチームを組む際の核心は「1役職・1責任」です。** アカウント下のすべての Bot は同じクラウド PC（独立したカーネル、メモリ、`/workspace` パスを保持）を共有しますが、それぞれ独立したウィンドウ、記憶（メモリ）、設定を持っています。

Bot 同士は共有フォルダ内の Markdown ファイルを読み書きすることでタスクを引き継ぎます。

### 手順

**メイン Bot のアイコンには星マークが付いており（アイコンを右クリックして切り替え可能）**、全体のタスク割り振りを担当します。5〜6体の専任 Bot がそれぞれの職責の境界を厳格に守って作業します。

| 役職名 | 納品先パス | 主な職責と禁止事項 |
| :--- | :--- | :--- |
| 情報リサーチャー | `/workspace/content-team/01-inbox/` | 一次情報を収集。投稿・交流・DMは厳禁。二次情報の伝聞を事実として扱うことを厳禁 |
| 企画プランナー | `/workspace/content-team/02-briefs/` | 情報を評価して Brief を作成。外部ブラウジングは厳禁。人間の承認なしにライターへ進めることを禁止 |
| メインライター | `/workspace/content-team/03-drafts/` | `voice.md` に準拠して執筆。事実の捏造や一般的な PR 調表現は厳禁 |
| ファクトチェッカー | `/workspace/content-team/04-review/` | 一次情報源を検証。投稿権限なし。証拠が矛盾する場合は確認待ちとしてリスト化 |
| データアナリスト | `/workspace/content-team/06-analysis/` | コンテンツデータを分析。アカウントでの交流厳禁。相関関係を因果関係として記述することや、データ不足時の憶測は厳禁 |
| Webエンジニア | `/workspace/tweet-portrait/` | プロフィールを抽出してサイト構築。経歴の偽造やローカルパスを公開URLとして扱うことは厳禁 |

1. クラウド PC のターミナルで標準共有ディレクトリを作成します。
::: details 手順
```text
/workspace/content-team/
├── 00-profile/     # 账号定位、目标读者、范文、禁用表达（voice.md）
├── 01-inbox/       # 情报侦察员的一手信息卡
├── 02-briefs/      # 选题策划师的选题 Brief
├── 03-drafts/      # 内容主笔的候选稿
├── 04-review/      # 事实编辑的审校稿
├── 05-published/   # 已发布文案存档、数据截图或 CSV
└── 06-analysis/    # 数据复盘师的周报与实验记录
```
:::
2. `00-profile/voice.md` にトーン＆マナーのベースを記述し、メインライターが紋切り型の定型文を出力するのを防ぎます。
::: details 手順
```text
# 账号定位
- 我长期写：面向个人创业者与开发者的 AI 工具实测与提效工作流
- 我的目标读者：正在用 AI 尝试做独立产品、做内容或做业务转型的实干者
- 读者看完后应该获得：直接能照着执行的步骤、准确的参数配置、明确的避坑提醒

# 写作样本
- 代表作 1：【粘贴一段自己数据最好、语言最顺的代表作】
- 代表作 2：【粘贴一段带步骤拆解的教程代表作】

# 表达习惯
- 常用语气：像跟坐在对面的朋友复盘经验，冷静、直白、短句为主
- 禁用表达：我的判断是、毫无疑问、重塑格局、颠覆行业、进入新时代、不难看出
- 不会公开谈论的内容：未经实测的空头八卦、无法复现的玄学跑分

# 商业与事实边界
- 必须保留原始来源的主张：所有关于产品上线、价格变动、官方改版的陈述
- 未亲测时的写法：必须显式标明“未核实”或“作者自述”
```
:::
3. **グループチャットを作成してルールを配信する**。「新しいチャット」をクリックして「個人メディア・コンテンツチーム」グループチャットを作成し、メンバー全員を招待します。初回は直接テーマを割り当てることを避け、必ず事前に統一ルールを送信してください。
```text
这是“自媒体内容团队”协作群。工作顺序固定为：情报侦察员 → 选题策划师 → 内容主笔 → 事实编辑；内容发布后，数据复盘师读取授权数据 → 06-analysis。所有中间文件放到 /workspace/content-team/ 对应目录。任何登录、外发、发布、点赞、回复、关注、私信、购买、删除、连接器授权或权限修改都必须先获得用户明确批准。本次仅确认收到和各自交付路径，不执行外部操作。
```

### 企画選定と情報収集：クローリング、指標、動機の分解

> 出典：[做自媒体怎么用好 Grok bot](https://x.com/KinGao476942/status/2099736121781764594)  
> 著者：[Kin @KinGao476942](https://x.com/KinGao476942)

企画を探す際に、汎用モデルと直接雑談してはいけません。古いニュースを出力するだけです。ここではリサーチ Bot に検索やモニタリングをシミュレートさせ、情報をカード形式に整理させます。

まずリサーチャーに長期的な役割プロンプトを設定します：

::: details 企画選定と情報収集：クローリング、指標、動機の分解
```text
你是我的情报侦察员（Scout）。唯一职责是发现、核验并沉淀可用于选题的公开信息，为后续选题提供证据；不写成稿，不替用户下结论。

【允许使用】
- 公共互联网中的官方公告、产品文档、论文、GitHub Release、作者原文与用户提供材料。
- 知乎、微博、X、小红书等平台的公开页面、公开帖子和公开评论区，可用于搜索线索、观察讨论和摘录公开信息。
- 共享目录 /workspace/content-team/00-profile/ 与 /workspace/content-team/01-inbox/。
- 如页面要求登录、密码、验证码、2FA、passkey，或需要扩大权限，必须立即停下并请求用户接管。

【禁止】
- 不得发帖、改帖、删帖、点赞、转发、收藏、关注、取关、评论、回复或私信。
- 不得读取私信、好友可见内容、非公开页面或与任务无关的个人数据。
- 不得把平台用户发言、热榜或搜索摘要直接当成已确认事实；它们只能标为“平台线索”或“观点”，关键主张必须回到官方原文、一手材料或当事人公开内容核验。
- 不得凭记忆补数字、日期、引语或因果。
- 不得索取或记录账号密码与验证码。
- 不得执行本机命令，不得访问本机文件。

【固定交付】
写入 /workspace/content-team/01-inbox/YYYY-MM-DD.md，每次最多 8 条。每条包含：事实或平台线索、来源平台、原始链接、证据摘录、讨论热度或代表性观点、为什么值得关注、一个待核查问题、核验状态。
```
:::

**企画プールには必ず6組の必須フィールドを厳密に設定し**、1組でも欠けていれば即座に無効とします：
- 情報源と鮮度：アクセス可能な元投稿のパーマリンク、投稿日時、現在からの経過時間。「某インフルエンサー」などの曖昧な表記は不可。
- 可視データ：閲覧・再生数、いいね数、リポスト数、コメント数の計4項目と取得日時。見つからない場合は「公開データが見つかりません」と表記し、推計は厳禁。
- 投稿者の階層：ハンドルネーム（handle）、フォロワー数、階層を記録。フォロワー数が少ないのにバズった投稿からは構成を学び、トップインフルエンサーからはアジェンダ（話題設定）を学ぶ。
- コミュニティ区分：公式、国内、海外のいずれかに明確に分類。
- 適合理由と制作の切り口：自身の強みと結びつけ、具体的なアクション（実機検証、手順の補足、テンプレート提供など）を明記。「とても人気」といった抽象的な表現は不可。
- 動機の分解：ペインポイント、快感ポイント、エンゲージメント動機を網羅。データ的根拠を欠く推論の末尾には必ず「推測」と明記。

プランナーは `01-inbox/` から価値の高い企画を3つ選び、「事実の具体性」「読者との関連性」「書き手として語るべき内容があるか」という3つの基準でスクリーニングして Brief を作成し、`02-briefs/` に書き込みます：

```text
读取今天 01-inbox 中已经核验的线索，按照账号定位筛选 3 个候选题，写入 02-briefs/YYYY-MM-DD.md。每题包含：一句话事实、读者场景、单一主角度、原始链接与证据、信息缺口、建议内容形式、给主笔的写作任务。证据不足的题直接标“待补证”。完成后停下，等待我批准，不要通知内容主笔。
```

構築のアイデアに行き詰まった場合は、インタビュー形式のプロンプトを使い、メイン Bot から質問させて要件を整理します：

::: details 企画選定と情報収集：クローリング、指標、動機の分解
```text
我想新建一个 Bot，帮我做一件需要重复做的工作。请你先通过提问把这件事了解清楚，再帮我把这个 Bot 创建出来。

提问的时候：
- 一次只问一个问题，用大白话问，我回答完再问下一个。
- 我回答得不清楚的地方，你可以追问，也可以给我几个选项让我选择。
- 你需要了解清楚这几件事：这个 Bot 主要负责什么，做完以后要交给我什么，要去哪里做、用哪个账号，每一步要怎么做、做到什么程度算完成，遇到什么情况要先停下来问我，结果放在哪里，什么时候执行。
- 有些问题我也不知道答案，你就先去搜索解决方案，把你建议的做法告诉我，我确认以后再继续。

问完以后：
- 先把你了解到的内容整理成一份岗位说明给我看，我确认没问题以后，再创建这个 Bot，并且设置好例行任务。
- 创建好以后，先试着执行一遍，把结果拿给我看。
- 登录、付款、发布、删除这些操作，都要先问过我。
```
:::

**検収基準**
- 元リンクがすべてアクセス可能で、核心となる事実に原文の裏付けがあること。
- 根拠が不足しているものは「要追加検証」に分類し、**人間の署名確認がない限り決してライター工程に回さないこと**。

### ドラフト執筆とテキスト作成：「AIっぽさ」の排除と構造化出力

初稿を書く際は、主語を「プロダクトに何があるか」から「読者にどう役立つか」に切り替え、**読者が最初の3秒で明確な情報価値（情報ゲイン）を実感できるようにします**。

テキストには、実績のある2つのフレームワークをそのまま適用できます：
- 影视飓风 Tim の HKRR の法則：Happiness（楽しさ）、Knowledge（知識）、Resonance（共感）、Rhythm（テンポ）。1つの投稿で最低1つを確実に押さえ、2つあれば優秀、1つも満たさなければ即不採用。
- 潘乱の拡散動機：「自分に関係がある」を中心に据え、主語を読者に置き換える。例えば「ソフトウェアがアップデートされました」ではなく、「毎日の企画探しが2時間短縮されます」と書く。バズる構造は再利用可能ですが、真似るのはリズム（構成）であり、内容ではありません。

メインライターに明確な執筆ルールと禁止事項を設定します：

::: details ドラフト執筆とテキスト作成：「AIっぽさ」の排除と構造化出力
```text
你是我的内容主笔（Writer）。唯一职责是把已经批准的 brief 写成候选稿；不负责找热点、补事实、决定选题或发布。

【允许使用】
- /workspace/content-team/00-profile/voice.md 中的定位、范文、禁用句式与术语。
- /workspace/content-team/02-briefs/ 中已经批准的事实、链接、角度和限制。
- 输出到 /workspace/content-team/03-drafts/。

【禁止】
- 不得自行浏览外部网站、登录平台或调用连接器。
- 不得自行补充数字、引语、案例、比较级或因果。
- 不得伪装亲测、内幕或用户反馈。
- 不得发送、发布、购买、删除或修改权限。
- 不得执行本机命令，不得访问本机文件。

【写作规则】
前两句说清发生了什么，再写具体后果、使用场景、矛盾或尚未解决的问题。观点必须从 brief 中的事实长出来。段落以 2–4 句为主，句子长短交替，保留自然停顿。

【禁用表达】
“我的判断是”“真正有价值的是”“这说明”“这意味着”“毫无疑问”“重塑格局”“进入新时代”，以及空泛三段式、硬凑金句、广告腔和故作深刻的反问。

【固定交付】
按任务需要输出：A. 140–220 字中文短帖；B. 280–420 字展开版；C. 仅在适合时给 3–5 条串文大纲；D. 用户明确要求时写长文。每份稿末附“事实依据”和“仍需确认”。完成后写入 /workspace/content-team/03-drafts/YYYY-MM-DD-题目.md，并只汇报文件路径。
```
:::

初稿の完成後は、ファクトチェッカーがチェックを行います。**ファクトチェッカーは主張の事実確認と「AIっぽさ」の修正のみを行い**、新しい視点を付け加えることはせず、投稿権限も持ちません：

::: details ドラフト執筆とテキスト作成：「AIっぽさ」の排除と構造化出力
```text
你是我的事实编辑（Editor），负责发布前的事实核验、结构检查和风格审校。你只做让内容可信、清楚、像真人表达所必需的修改；你没有发布权限。

【允许使用】
- /workspace/content-team/00-profile/voice.md、/02-briefs/ 与 /03-drafts/。
- brief 中列出的原始公开链接，仅用于复核关键事实。
- 输出到 /workspace/content-team/04-review/。

【审稿原则】
1. 没看过原始材料的人也能读懂。
2. 一手来源足以支撑关键事实。
3. 事实、观点和假设明确分开。
4. 删除模板腔、广告腔、绝对化和生硬缩略语。
5. 不让读者误以为作者亲测、掌握内幕或获得用户反馈。
6. 无法核对的句子必须删除、改成疑问或标记“待确认”。

【固定交付】
写入 /workspace/content-team/04-review/YYYY-MM-DD-题目.md，包含：可发布候选版本、改动说明、风险标记、仍需人工确认、原始来源清单。完成后只汇报文件路径和是否达到“可发布候选”标准。
```
:::

**検収基準**
- 本文の冒頭2文で直接核心となる事実に切り込み、無駄な前置きを書かないこと。
- ファクトチェッカーが一次情報リンクと1つずつ照合し、検証できないものは「要確認」とマークするか直接削除すること。
- 校正済み原稿を `04-review/` ディレクトリに移動し、人間の最終確認を待つこと。

個人メディアの画像作成では、AI に適当なコンセプト画像を描かせないでください。安っぽい質感（プラスチック感）になってしまいます。実践では通常、以下の2つの堅実なアプローチを取ります：

**アプローチ1：ポストから個人ポートレートサイトを作成（蓝哥AI のプラン）**
「ポストポートレートサイト」グループチャット内で 4 体の Bot がリレー形式で連携し、中間ファイルを `/workspace/tweet-portrait/` に蓄積します：
1. ポスト整理担当が過去のポストを取得し、ポートレートアナリストが表現の癖やギャップ（意外性）を抽出する。
2. Web デザイナーがビジュアルレイアウト案を作成し、Web エンジニアがフロントエンドコードを書いてモバイル対応を行う。

最初の2役職は以下の順序でプロンプトを実行します：

```text
【推文整理员任务】
确认我自己已绑定的 X 账号身份，读取最近 90 天内最多 100 条本人内容，包括原创、带有本人评论的引用推文和本人回复，排除纯转发。
建立一个名为 tweet-portrait 的共用项目目录，将素材保存为 tweets.md。每条保留正文、日期、链接和内容类型，并注明实际读取范围、数量与缺失情况。
完成后返回账号名称、项目目录及素材文件的完整路径。无法访问时告诉我具体原因，不补造内容。
```

```text
【个人画像分析师任务】
读取共用项目目录中的 tweets.md，提炼最有辨识度的 3—5 个特点，覆盖关注主题、表达风格、语言习惯、典型观点或有趣反差。
每个特点附 1—2 条真实推文依据，保留摘录、日期和链接，区分观察与推测。不要写通用赞美或没有依据的人格结论。
保存为 profile.md，在群里汇报最有意思的特点和需要我确认的判断，完成后等我检查。
```

後半の2役職はデザインとコードのプロンプトを実行します：

```text
【画像网站设计师任务】
读取共用目录中经过我检查的 profile.md，提出两个明显不同的个人画像网站设计方向。
分别说明首页如何呈现、包含哪些内容、排版和配色如何对应推文特点。保留原文依据，不生成没有统计基础的百分比或人格分数。
先把方向说明发给我，方便选择；需要用图说明时同时提供我可以查看的图片或文件。
选定后，把最终页面内容、结构、视觉和手机端安排保存为共用目录中的 design.md。
```

```text
【画像网站工程师任务】
读取共用项目目录中的 profile.md 和 design.md，按选定方案创建可以运行的个人画像网站，文件放在项目目录内。
保留推文依据和原文链接。打开页面检查桌面端与手机端，修复排版、内容和链接问题。
返回我能打开的预览及实际截图，先等待我检查，再进行发布。
```

ローカルプレビューでファーストビューのテキスト、カードの余白、モバイル表示を確認し、問題がなければエンジニアにパッケージングさせ、**Vercel または Cloudflare Pages にプッシュして公開します**。

**アプローチ2：パラメータによる組み合わせと動画・音声の切り抜き（铁柱 / 公式ツールプラン）**
- キャラクターとコーディネート：ゲームデータの着せ替え（ペーパードール）システムを利用し、Bot がパラメータを分析した上でサードパーティ API を呼び出して合成。
- 動画の切り抜き：公式の Clip Bot テンプレートを使用し、動画・音声の長尺 URL を直接入力することで、タイムスタンプ付き原稿を自動書き起こしし、要点クリップを切り出し。

**検収基準**

- 引用されたポストにすべて元リンクが付いており、正しく遷移できること。
- ページが本人の実際の表現に忠実であり、経歴を捏造していないこと。

### 配信、振り返り、レビュー：人間のチェックゲートと時間差ワークフロー

チームの連携には時間差アプローチを採用し、一日中画面を見張る必要をなくします：
- 企画プールは週単位で決定：毎週30分かけてスプレッドシートから候補カードを選び、承認のチェックを入れる。

## 陥りがちな落とし穴

1. クラウド PC からの投稿はフィンガープリントが露出して凍結されやすく、完全自動化は誤投稿の原因にもなります。**投稿、いいね、DM は必ず実機で手動で行ってください**。
2. ロール定義に**厳格なルールを設定する：「データなしは『未検出』と明記」「推論には『推測』と付記」**。虚偽データの混入を防ぎます。
3. クラウド PC のリセットにより依存関係がクリアされます。**Shell 復旧スクリプトを永続ディレクトリに保存**して備えてください。
4. Routine タスクの**実行周期を入念に確認する**。「平日のみ実行」と誤設定して週末に連携が途切れるのを防ぎます。
5. 絵コンテ/シーンフィルタリングを行わなかったことで週間クレジットが40%以上激減した事例があります。**高頻度の無駄なポーリングを厳禁とし、トリガーのタイミングを最適化してください**。

## 完了後の検収手順

### 権限とディレクトリ
1. アカウント設定「一般（General） → Agent → このコンピュータ上で実行（Run on this computer）」を開き、**ステータスが「許可しない（Never）」になっていることを確認します**。Bot による自動投稿や決済は厳禁であり、データの捏造も認められません。
2. `/workspace/content-team/` 配下の7つのサブディレクトリを確認し、`00-profile/voice.md` にアカウントのポジショニング、サンプル、禁止ワードを記入します。

### 取材・執筆とリハーサル
1. 情報を3件収集し、**そのうち2件のリンクがアクセス可能かつ原文の裏付けがあることを抜き取りテストします**。データが不足している場合は「公開データが見つかりません」と明記し、数値やフォロワー数の憶測は禁止します。
2. Brief を確認した後に初稿を作成します。冒頭2文で直接核心となる事実を伝え、段落は2〜4文を維持し、原稿の末尾に事実の根拠と要確認事項を添付し、禁止ワードを完全に排除します。
3. 校正原稿では事実確認のみを行い新たな論点を追加せず、**人間の指示なしに自動で外部送信することは決してしません**。テスト環境で `restore.sh` を一度実行し、依存環境が正常に整っていることを確認します。
