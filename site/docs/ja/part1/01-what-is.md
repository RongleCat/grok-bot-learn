# 第1章 Grok Bot とは：専用PCを持つ AI 同僚

従来のWebチャットでは資産を蓄積できず、**ノートPCを閉じるとタスクが即座に中断**してしまいます。アプリをまたぐ連携や継続的な巡回監視に直面しても、人間は依然としてPCの前に縛り付けられ、機械的なクリック作業を強いられていました。

本章では、主に以下の4つの内容を扱います。
- その動作メカニズムと共有クラウドPCの物理的境界；
- 任せるのに適したタスクと適さないタスクの種類；
- 市販されている他の常駐型 Agent との選定基準・違い；
- **仕様に沿った職務定義を作成し、権限逸脱を防ぐ人間による承認ゲートを設けること**。


![Grok Bot とは：専用PCを持つ AI 同僚](/info/01-what-is.png)

## Grok Bot の基盤となる動作メカニズムとは？ {#产品机制-环境底座与思考模型拆分}

**Grok Bot の中核は、常駐型クラウド Linux 基盤とオンデマンドで呼び出される思考モデルを分離している点にあります。ターミナル、ブラウザ、永続ストレージを備えており、手元のPCの電源を切って画面を閉じても、バックグラウンドタスクはクラウドPC上でそのまま稼働し続けます。**

![プロダクトの仕組み：環境基盤と思考モデルの分離](/info/01-what-is-s1.png)

xAI と Cursor は 2026 年 8 月 11 日に Grok Bot をリリースしました。**その核心は、環境基盤と思考モデルを分離したことです**。

- **基盤（Harness）**：クラウド上に常駐し、Linux ターミナル、ブラウザ、永続ファイルを備えています。手元のPCをシャットダウンして閉じても、バックグラウンドタスクは通常通り稼働します。
- **モデル（Brain）**：オンデマンドでスケジューリングされ、特定の単一モデルに固定されておらず、確認や指定もできません。2026年10月7日以降、タスクは Claude Opus 5.5 などのモデルにルーティングされる可能性があり、Cursor Agent を派生させて協調コーディングを行うこともできます。

| ツール | 実行環境 | オフライン稼働と連携 |
| --- | --- | --- |
| チャットアシスタント | 一時的なWebページ | ページを閉じると中断、単一の対話 |
| コマンドライン Agent | ローカルターミナル | 終了すると停止、ローカルリポジトリに限定 |
| Grok Bot | 永続クラウドPC | **電源を切っても継続実行**、タスク間でのファイル受け渡し |

仕組みの詳細は [『1.1 Grok Bot とは：1ページで丸わかり』](https://jcng5q8n0f3z.feishu.cn/wiki/I04Gw3wEaisftUkBikxcg43rnpc) を参照してください。

## Grok Bot の共有クラウドPCはどのように分離・テイクオーバー（手動介入）するのか？ {#共享云电脑的物理边界与接管机制}

**同一アカウント内のすべての Bot は同じクラウドPCを共有しており、パスや Cookie を分離することはできません。タスク間の受け渡しは /workspace にファイルを保存して行い、パスワード入力や決済などの操作が発生した場合は「Take over」をクリックして手動で介入（テイクオーバー）できます。**

![共有クラウドPCの物理的境界とテイクオーバーの仕組み](/info/01-what-is-s2.png)

同一アカウント内のすべての Bot はクラウドPCを共有します。Heavy プランの実測値では Xeon 8コア/8スレッド、16GB メモリ、128GB ストレージ（未検証、公式情報準拠）であり、v0.68.1 では解像度が 1920×1200 に引き上げられました。

仕様の詳細は [Grok Bot 计算机和应用文档](https://cursor.com/cn/docs/grok-bot/work#the-computer-and-apps) を参照してください。

- 新規作成した Bot は**権限を分離できません**。パスやログイン状態は共有され、どれも Cookie を読み取ることができます。
- Bot 間の連携はファイルへの永続化に依存します。チャット自体は個別に独立しているため、引き継ぎを行うには `/workspace` にファイルを保存する必要があります。
- パスワード入力、2要素認証、決済などは Take over をクリックして処理し、**チャット欄に平文のパスワードを絶対に送信しないでください**。
- ローカルPCの操作には個別の権限付与が必要です。ローカル環境とは隔離されており、Settings → General → Agent → Execution on Local Computer から有効化すると、実行時に確認ポップアップが表示されます。

## Grok Bot に適しているタスク・適していないタスクとは？ {#适合与不适合的任务类型}

**Grok Bot は、情報巡回やバグ再現など、手順が固定化され、高頻度で繰り返され、複数のツール連携を要するタスクに適しています。一方で、即時Q&A、ローカルでのコーディング、人間による承認ゲートのない高リスク操作には適していません。**

![適しているタスクと適していないタスクの種類](/info/01-what-is-s3.png)

### タスクの選定基準
**タスクを Grok Bot に任せるべきかどうかは、3つの選定基準で判断できます。**
- Webブラウザ、ターミナル、または API 経由で最初から最後まで実行できること；
- 中間ファイルまたは最終レポートを人間が直接確認・検証できること；
- 高リスクで機微な操作の際に処理を止め、人間のポップアップ承認を待てること。

### 適しているタスク
**手順が固定され、高頻度で繰り返され、複数ツールの連携を必要とする業務に適しています。**
- 情報巡回：特定の公式サイトを定期的に訪問し、要約テーブルを作成する。
- リード精査：CRM から対象アカウントを抽出し、公開情報をもとにアウトリーチメールの文面を作成して確認に回す。
- 財務照合：毎週請求書を突き合わせ、未提出のものをマークして督促する。
- バグ再現：Issue を読み込んでステージング環境で再現させ、ログやスクリーンショットを抽出する。
- 経営デイリーレポート：毎日在庫指標を集計し、異常値を検出する。

### 適していないタスク
**不向きな作業を無理に任せると、週ごとのクォータを無駄に消費したり、予期せぬ動作を招いたりします。**
- 即時Q&A：エラーの調査なら通常のWebチャットモデルで数秒で解決するため、クラウドPCを使う必要はありません。
- ローカルでのコーディング：ブレークポイントデバッグや Git コンフリクトの解消は、ローカルの Codex CLI や Claude Code を使いましょう。
- 日常の雑務：スケジュール管理などは企業向けデータソースが不足しており、無理に任せてもうまくいきません。
- 差分のないポーリング：5分ごとの無条件リフレッシュなどは、推論クォータを無駄に浪費します。
- 高リスク操作：メールの一斉送信やデータベースの削除などには、必ず人間による承認ゲートを設ける必要があります。

プランニング方法の詳細は [『1.2 Grok Bot と Muse、Hermes、dots、Cue の選び方』](https://jcng5q8n0f3z.feishu.cn/wiki/BnH9wLTmyiQZ03kJhsecOrffnAd) を参照してください。

## 選定の比較：Grok Bot と主要な常駐型 Agent の横断比較

### 完成品（既製品）と自作機の形態

常駐型 Agent の選定は、手軽さを求めるか、自由なカスタマイズを好むかが主な基準となります。**導入してすぐに使える完成品**（Grok Bot、Muse）はデプロイの手間がかかりませんが、プラットフォームのクォータ制限を受けます。一方、自作機（Hermes）はオープンソースモデルを接続できるためクォータ制限がありませんが、環境のエラーは自力でトラブルシューティングする必要があります。

### 主要な常駐型 Agent の特徴と選定比較

| 製品 | 基盤と導入難易度 | 特徴と適用シーン |
| --- | --- | --- |
| Grok Bot | 共有 Linux クラウドPC。2026-10-12 より The X Subscription 統合プラン（Premium 月額$30、Super 月額$100、Ultra 月額$200）を適用、**Plus プランには Bot が含まれません**。クライアント v0.70.2 で専用メールアドレスと接続カードをサポート | 24時間365日常駐、ルーティンとスキルをサポート、複数 Bot による非同期ファイル受け渡しと X プラットフォーム検索の呼び出しが可能。運用保守不要、複数ロールでの協調作業や巡回・照合に最適 |
| OpenAI dots | 個人専用の常駐型クラウドPC、ChatGPT Pro および Business Premium に最初の dot が含まれる | GPT-6 Astra ベース（dots は 2026-09-29 にリリース）、バックグラウンドに常駐して4000以上のアプリと連携し、日常の寄り添いや軽量なタスク代行に特化 |
| Manus Cue | 独立したクラウドPC、アーリーアクセス段階 | 2026-09-29 に 铁柱 がハンズオンを体験。標準で独立した協調用メールアドレス、電話、ウォレットを備え、自律的な登録や調達代行が可能。極めて高い自律性を持つ一方、操作リスクも伴う |

## 代表的な実践事例の解説

### 金尘马 のインテリジェンスディレクター（個人リサーチ職）

金尘马（@jinchenma_ai）はかつて Edit Profile の Description に長期的な職務ルールを明記し（このメニューは現在削除されています。現行の手法は第3章を参照）、インテリジェンスリサーチャーとしての役割を定義していました。タスク指示では「結果」「情報源」「制限事項」「フォーマット」「確認ポイント」の5要素を徹底し、X プラットフォームの長文ポストを検索して動画ポストを区別し、インプレッションデータを明記させました。**一次情報がない場合は捏造を厳禁としました**。

初回にフォーマットの修正を行った後、Bot に指示を出して一連のフローを Skill「AI 教程情报搜集」として保存・定着させました。

2つ目の入力セットでテストを完了させた後、Routine を設定し、毎営業日の朝8:10に自動実行してレポートを送信するようにしました。さらに新規で「コンテンツディレクター」を作成して企画を審査させ、初稿を `/workspace/grokbot-demo/` に保存しました。

**職務定義で長期的なルールを定め、単発の要望はメッセージで指示し**、複数の Bot 間は `/workspace` へのファイル保存を介して疎結合にします。

詳細は [『万字长文｜Grok Bot 从入门到精通｜金尘马』](https://jcng5q8n0f3z.feishu.cn/wiki/MIKpwiUXpiE9mWkyG8ccFM6Znee) を参照してください。

### 金尘马 のEC運用チーム（マルチロール分業パイプライン）

チームは4つの Bot による協調体制で構成されています。まず「ショップ運営当番」を作成し、商品一覧、在庫表、注文表を読み取ってデイリーモーニングレポートを送信させました。**ここでは読み取り専用の厳格な制限（レッドライン）を設け、価格や在庫の変更、メール送信や返金処理は厳禁としました**。

当初の当番 Bot を「EC運用マネージャー」へ昇格させ、そこから「コンテンツグロース担当」「商品在庫アナリスト」「受注・アフターサポートアシスタント」を切り分け、データを `/workspace/ecommerce-ops/日期/` に保存するようにしました。ヒット商品の在庫が残り3日分になった場合は、コンテンツ担当がプロモーションを一時停止し、サポート担当が発送遅延時の案内スクリプトを準備し、マネージャーが意思決定リストを取りまとめます。

最初から大規模なチームを構築しようとせず、**資金、在庫、外部へのメッセージ送信に関わる操作はすべて人間による承認を必須にしてロックしてください**。

### 铁柱 のオープンソースリポジトリ管理者 Bot（運用の自動巡回監視）

铁柱AGI（@cgnot996）は常駐型 Bot を構築し、awesome-grok-bot ナレッジベースを保守しています。システムは X プラットフォームのポスト、公式の更新履歴（チェンジログ）、技術コミュニティを定期巡回し、新しい活用法、チュートリアル、公式ドキュメント、イベントなどを分類して収録します。

告知前の段階ですでに関連資料を自動収集しており、**2026年8月に130以上の Star を突破（作者談、未検証）**、公式関係者から申請フォームの案内を受けるに至りました。

### サブスクリプションプランの確認とクライアントのインストール

2026年10月12日より適用されている The X Subscription 統合プランに従ってプランを選択します：
- **Premium プラン**：月額$30（年払い$300）、4倍のクォータプール。個人の日常的な利用のスタートに適しています。
- **Super プラン**：月額$100（年払い$1000）、15倍のクォータプール。本格的な調査研究や複数のルーティン実行に適しています。
- **Ultra プラン**：月額$200（年払い$2000）、50倍のクォータプール。高頻度で稼働させるチームの主力用途に適しています。
- **月額$8（年払い$80）の Plus プランには Bot 機能が含まれていません**。絶対に間違えないよう注意してください。なお、すでに Cursor の有料個人版またはチーム版、SuperGrok サブスクリプション、あるいは Grok Business シートをお持ちの場合はそのまま利用できます。

  デスクトップ版は macOS、Windows、Linux をサポートし、モバイル版は iPhone、iPad、Android をサポートしています。インストール後にアカウントへログインしてください。

### Bot の作成とテストタスクの指示

1. サイドバーの **+**（または Cmd+N）をクリックして Bot を作成し、「競合インテリジェンス担当」と名前を付けます。個人用 Bot には Description がなくなったため、以下の6行をチャットで送信して記憶させます。共有 Bot の場合は詳細画面の About にある Description に記述します。
```text
Own: 负责监控目标清单的每周功能更新与定价变动
Sources: Notion 中的关注名单、目标官网 Changelog 页面
Output: 不超过 8 条核心动态，附带日期与原始链接，存入 /workspace/scan.md
Approval: 严禁对外发布任何内容，严禁主动发送任何邮件
Failure: 若目标页面无法打开，在报告中明确标为数据缺失，严禁推测或编造内容
Never: 在源系统可访问时，严禁依赖自身记忆给出概括
```
2. チャット欄でテスト指示を送信します。「目的」「情報源」「制限事項」「フォーマット」「確認ポイント」の5要素を明記してください。
```text
调研所附竞品清单中的前 3 个产品官网。
比对它们过去两周内的功能更新与价格调整。
跳过无任何变动的模块。
提取核心变动点，整理成 Markdown 表格，并直接保存到 /workspace/scan.md。
在对话框中仅回复处理状态与保存路径；不要对外发送任何通知，不要擅自更改系统设置。
```
3. **右側のクラウドPC画面を確認します**。Bot が自動的にクラウドブラウザを立ち上げてページ情報を抽出し、指定されたファイルに内容を書き込みます。

### セキュリティ承認と定期ルーティンの設定

1. Settings → General → Auto-review に移動し、**高リスク操作は必ずすべて Ask first を有効にします**。

   メッセージ送信（`send`）、投稿（`post`）、課金・決済（`buy`）、ファイル削除（`delete`、`/workspace` やローカルファイルを含む）、権限変更（`permissions`）を厳格に制限します。これらがトリガーされるとカード型のポップアップが表示されて処理が一時停止し、人間が手動で承認するまで待機します。
2. スクレイピングタスクが2回連続で安定して実行できたら、チャット欄で定着（スキル化）の指示を送信します。
```text
把刚才已经跑通的竞品页面抓取与格式整理流程保存为一个 Skill，名称叫「竞品动态巡检」。
写清调用条件、所需权限、抓取步骤、异常报错逻辑与产出文件格式。
```
3. 別の競合サイトのURLに変え、`/` を入力してこの Skill を呼び出してテストします。問題がないことを確認したら、**Routine（定期実行）を設定**し、毎週月曜日の朝9:00に自動実行されるようにします。結果の報告は現在のチャットに送信され、詳細レポートは `/workspace` に保存されます。

## よくある落とし穴・注意点

### アーキテクチャとセキュリティ

- コミュニティで話題の「29個の Bot 構成」（Melvin Vivas 氏談、未検証）を鵜呑みにして真似しないでください。似たような Bot を乱立させると混乱を招き、クォータを浪費します。**1つの役割が安定して運用できるようになるまでは、2つ目を作成してはいけません**。
- すべての Bot はクラウドPCとファイルシステムを共有しており、クローラーが `/workspace` や Cookie を読み取ることも可能です。**セキュリティ制御は Ask first による人間の承認ゲートに頼るしかありません**。
- チャット欄にアカウントのIDやパスワードを送信してはいけません。ログイン画面が表示されたら、**右側の画面を表示して Take over ボタンをクリックし、人間が手動でログインしてください**。

### リソースと期待値

- 月額$8の Plus プランには Bot の利用権限がありません。**必ず月額$30からの Premium プラン以上を選んでください**。
- Routine を5分または10分おきのポーリングに設定すると、週ごとのクォータプールを使い果たしてしまいます。**定期タスクの間隔を十分に空け、更新がない場合は即座に終了するロジックを追加してください**。
- Alex Finn 氏の収益化や 0xkvro 氏のコスト削減に関する誇大な話（本人談、未検証）を軽信せず、**実際のビジネスで検証された数値を基準にしてください**。

## 完了後の検収・動作確認方法

1. サイドバーで Bot をクリックしてチャットを開き、メッセージを送信して **1920×1200 のリアルタイムデスクトップ** を展開します。Usage & Billing にアクセスし、プランが Premium、Super、または Ultra であること、使用量プログレスバーが正常であることを確認します。
2. 6行の契約（指示文）には、役割、データソース、成果物、承認のレッドライン、データ欠損時のフォールバックを漏れなく記述する必要があります（**6行の厳格な制約**）。個人用 Bot ではチャットに送信して記憶させ、共有 Bot では詳細の About に記載します。リンク切れのURLを送信してテストし、データを勝手に捏造することなく**データ欠損を正しく報告すること**を確認してください。
3. Settings → General → Auto-review で、`send`、`post`、`buy`、`delete`、`permissions` を Ask first に設定します。メッセージ送信やファイル削除のテストを行い、**必ず承認カードがポップアップして人間の確認を待つ状態になること**を確認してください。
4. Routine を右クリックして Test run で正常に動作することを確認したら、PCを閉じてソフトウェアを終了します。予定時刻になったら再度開いて通知を確認し、クラウドPCの `/workspace` にアクセスして、**Markdown または CSV が最新のタイムスタンプで更新されていることを確認します**。
