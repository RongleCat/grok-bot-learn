# 第4章 タスクの指示：メッセージ、添付ファイル、そして適切な引き継ぎ

要件があまりに簡潔すぎると、Bot は無関係な Web ページを何十件も検索したり、ファイルを乱雑に変更したりしがちです。**メッセージの送信とは、クラウド PC に作業を引き継ぐことにほかなりません**。

- **タスクの境界を厳格に定め**、添付ファイルの用途を明記して、勝手な判断を防ぐ
- 明確な指示を出し、直接検収可能な成果物を受け取る
- 実行中も随時口を挟んで軌道修正するか、音声で背景情報を補足する


![タスクの指示：メッセージ、添付ファイル、そして適切な引き継ぎ](/info/04-handoff.png)

## 優れたリクエストの5大要素

![優れたリクエストの5大要素](/info/04-handoff-s1.png)

Grok Bot にタスクを指示する際は、**指示において目標とツールの範囲を明確にする必要があります**。仕様の詳細は [『Grok Bot』](https://cursor.com/cn/docs/grok-bot) ドキュメントを参照してください。

1. **アクションは具体的かつ単一にする**。「スクレイピングして比較」や「外部向けメールの下書き作成」のように明記し、「少し調べておいて」といった曖昧な表現は避けます。経路が短いほど無駄なステップを省けます。
2. **データソースを限定する**。Notion ページ、Slack の #sales-leads チャンネル、あるいは特定の URL を指定し、Web 全体を無作為に検索するのを防ぎます。
3. **承認のレッドラインを明確にする**。読み取りや比較は自動で実行させますが、**外部へのメール送信、オンライン決済、データの変更・削除を伴う場合は、必ず一時停止して承認を待たせます**。
4. **成果物の形式を固定する**。**口頭での報告は受け付けず**、`/workspace/leads/` にリンク付きの Markdown レポートまたは CSV テーブルを生成するよう要求します。
5. **エラー処理ルールと事実の境界を定める**。推測と客観的事実を区別させます。ログインが無効になった場合はスキップして記録を残し、**無限ループでの再試行を禁止します**。

## 添付ファイルの仕様と制限一覧

アップロードルールについては [『Grok Bot の使用』](https://cursor.com/cn/docs/grok-bot/work) を参照してください。

### 仕様制限

- デスクトップ版は1件につき**最大6個まで**（上限を超える場合はワークスペースに配置）。画像・テキスト・音声は 25MB まで、動画は 200MB まで。
- 処理が止まったりエラーが発生したりした場合は、まずローカルで PDF、CSV、または画像に変換してからアップロードしてください。

### 引き継ぎとグループチャット

1. **ファイルをドラッグ＆ドロップした後にすぐ Enter を押さないこと**。各ファイルの役割、関連ロジック、および保護に関する注意事項を明記してください。

```text
上传的 PDF 是已经签署的标准采购合同模板。上传的 Excel 是本月供应商提交的实际报价清单。
请对照合同模板中第 4 条关于各类物料的基准单价，逐行核验 Excel 里的实际报价。
标出单价超出基准价的所有条目，在附带的备忘中引用合同中的对应条款编号。
将核验结果另存为一份新的 Excel 表格，并输出一份简短的异常摘要。
请勿改动原始上传文件。
```

2. グループチャット内の Bot 間では**プレーンテキストのみをサポート**しています。後続の Bot に添付ファイルを参照させたい場合は、個別のダイレクトチャットで送信する必要があります。

## タスク引き渡しの実用プロンプト集

よくあるシナリオでは**テンプレートをそのまま流用**し、少し手を加えるだけですぐに使えます。

1. **リサーチとアウトリーチ**：リードの調査と資料の準備を行い、直接送信はしない。
```text
从我们的 CRM 系统中获取本周销售管道的重点评审列表。
请跳过当前已经处于活跃跟进序列中的联系人。
在指定公开网页和已授权的 Slack 相关频道中，深入调研排名前五的重点账户，找出负责采购或技术的对口联系人。
参考我在系统中历史邮件的口吻，为这五位联系人分别起草个性化的初次外联邮件。
将草稿保存在系统草稿箱中，并在明天上午 9 点前在此对话中列出清单供我审批。未经我的明确确认，绝不向外发送任何邮件。
```
2. **添付ファイルの検証**：複数テーブルの突き合わせと収支の確認。
```text

请逐项核对 CSV 中的每一笔申报项目：
1. 检查报销金额是否超过对应城市级别的住宿与餐饮标准。
2. 检查单笔超过 500 元的支出是否有对应的发票类别标记。
3. 提取所有不符合政策规定的异常申报，列明行号、申报人、金额、超标原因及违背的政策条款。
最后生成一份 Markdown 格式的核查报告，并列出通过与未通过的统计汇总。保持原始 CSV 文件不被改动。
```
3. **Webサイト巡回点検**：ページの巡回点検と証跡の保存。

## 長期ルールと単発タスク：「家訓」と「家事」を混同しない

![長期ルールと単発タスク：「家訓」と「家事」を混同しない](/info/04-handoff-s4.png)

**長期ルールと単発タスクを明確に区別し**（[『Grok Bot の使用』](https://cursor.com/cn/docs/grok-bot/work) を参照）、一時的なパラメータを長期設定に書き込んだり、毎回ゼロから最低限のルールを指示し直したりしないようにしましょう。

| タイプ | 有効期間と設定方法 | 例と制限 |
| --- | --- | --- |
| 長期ルール | セッションをまたいで有効。Bot Details で設定するか、「これを長期ルールとして記憶領域に記録してください」と入力 | 権限のレッドライン、日付フォーマット YYYY-MM-DD |
| 単発タスク | 単一ターンのみ有効で蓄積されない。直接指示を出す | 12件のアカウントまたは3件の音声の処理、10時の会議のアジェンダ抽出 |

すべての Bot は `/workspace` を共有します（[『10 条の必須経験：Grok Bot をより使いこなすために』](https://jcng5q8n0f3z.feishu.cn/wiki/Hfqxwy3zQiWkRPkVjRZcVCuHnbc) を参照）。

**記憶は業務システムの代わりにはなりません**。残高や在庫情報は必ず正規のソースから取得する必要があり、勝手な憶測は厳禁です。

## タスク進行中の介入：停止、割り込み、そして承認

![タスク進行中の介入：停止、割り込み、そして承認](/info/04-handoff-s5.png)

### 割り込みと停止
Bot が目標から外れた場合は、通常のメッセージを送信するだけで**即座に割り込み**が可能です。例えば「2026年10月更新の改訂版仕様に切り替えて再調査して」のように送信します。

操作に誤りがあったり高リスクな呼び出しが発生したりした場合は、入力欄に以下の4文字を送信して停止させます。
```text
立即停止
```

**停止は未実行のアクションを遮断するだけであり、保存済みのファイルや送信済みの API リクエストをロールバックすることは決してありません**。停止後は以下の3ステップで確認・対処します。
1. クラウド PC のプレビューパネルを開いて状態を確認する。
2. 作りかけの成果物や誤って書き込まれた内容をクリーンアップする。
3. 範囲を絞り込み、境界を明確にしてから再開する。

### 承認とタイムアウト
Auto-review を有効にしている場合や高リスクな操作がトリガーされた場合は、「操作のレビュー」カードが表示されます（[『Grok Bot 操作ガイド』](https://cursor.com/cn/help/grok-bot/how-to) を参照）。これには3つの選択肢が含まれます。
- 1回のみ許可：今回のみ承認し、次回以降の同種の操作では再度確認する。
- 常に許可：ホワイトリストに追加し、以降は通知を表示しない。
- 拒否：その操作を完全に遮断する。

| シナリオ | 待機メカニズム | タイムアウト時の結果 |
| --- | --- | --- |
| リアルタイム対話 | 保留して待機 | クリックして処理するまで待機を継続 |
| バックグラウンド無人実行 | 約10分で自動期限切れ（Expired） | **操作を実行せずにタスクを終了** |

### 認証情報の引き継ぎ（Action needed）
パスワード、2FA、CAPTCHA、または実際の決済が関係する場合、引き継ぎカードが表示されます。以下の3ステップで操作してください。
1. **Take over** をクリックしてクラウド PC 上で手動入力する。
2. 完了後、**I'm done** をクリックして制御権を返却する。
3. **通常の対話入力欄には絶対に平文のパスワードを入力しないこと**。

## 音声操作：リアルタイム音声通話と音声文字入力の使い分け

Grok Bot には音声入力（文字起こし）と通話という**2つの異なる音声機能**が備わっています。詳細については [『Bot との音声チャット』](https://cursor.com/cn/help/grok-bot/voice-chat) および [『Grok Bot 操作ガイド』](https://cursor.com/cn/help/grok-bot/how-to) を参照してください。

### 2つのモードの比較

| モード | 起動方法とショートカットキー | 出力と主な利用シーン |
| --- | --- | --- |
| 音声入力（ディクテーション） | デスクトップで「音声入力を開始」をクリック、Mac は Cmd+D、Win/Linux は Ctrl+D、スマートフォンでは「聞き取りを開始」をタップ | 入力欄にテキストが入力される。プロンプトの微調整やパラメータ追加に最適 |
| リアルタイム音声チャット | **入力欄を完全に空にした**後、波形アイコン（Start voice chat）をクリック | 双方向リアルタイム通話。アイデアの整理や迅速な引き継ぎに最適 |

### 開始手順と落とし穴の回避

1. 個別の Bot チャットを開く。
2. **入力欄は完全に空にする必要があります**。スペースや下書きが少しでも残っていると、波形アイコンが非表示になります。
3. 波形アイコンをクリックします。初回利用時はマイクのアクセス許可が必要です。
4. Connecting…（スマートフォン版では Calling…）と表示され、Bot が自発的に話し始めれば接続完了です。

### コントロールと制限事項

- 通話中はミュート、スクロール字幕の表示、話速や音色の調整が可能です。画面を切り替えて資料を確認する際は、上部バーの「音声チャットに戻る」をクリックすればすぐに復帰できます。
- **1対1の個別チャットのみ対応**しています。グループチャット、複数 Bot グループ、「チーム Bot」からは開始できません。
- **同時に維持できる通話は1つのみ**です。新しい Bot に切り替えるには、「終了してチャットを開始」を確認する必要があります。
- 通話を切断すると自動的に Voice chat カードが生成されて総通話時間が記録され、クリックして全文テキストを確認できます。その後のタスクはテキストチャット上でそのまま進められます。

## よくある失敗例と改善の対比

1. **実行パスの収束**：範囲と方法を定めていないと、Bot はコンソールを手当たり次第に操作し、**本番環境のコードを変更してしまうことすらあります**。
```text
  帮我维护一下网站，看看有没有什么 Bug。
  ```
対象ページと調査ステップを限定するように変更：
```text
  对站点清单（/workspace/sites.txt）中的三个静态展示页进行巡检。
  用云浏览器打开每个页面，检查控制台是否有 404 或 500 报错，检查顶部导航栏链接是否全部有效。
  将报错信息、对应页面 URL 及当时的屏幕截图写入 /workspace/logs/err-20261014.md。
  全程仅做只读检查，严禁点击任何带有提交或删除性质的表单按钮。
  ```

2. **承認の境界**：外部への送信権限を与えないこと。解釈が脱線した場合、**重要な顧客に誤った内容を送信してしまうリスクがあります**。
```text
  读取 Gmail 里的未读邮件，重要的直接帮我回一下。
  ```
重要なチェックポイントでは人間が承認を行うように変更：
```text
  读取 Gmail 中过去 12 小时的未读邮件。
  仅筛选出发件人属于我们现有企业客户、且正文包含售后或咨询诉求的邮件。
  根据产品常见问题手册，为每封邮件起草回复草稿并存入 Gmail 草稿箱。
  在当前对话中列出客户名称、邮件摘要与草稿正文，等待我的审批。未经我的明确确认，绝不点击发送。
  ```

3. **事実と推測の分離**：プロンプトに先入観を混ぜないこと。**Bot が仮説に迎合して、小規模なセールを価格競争だと誤認するのを防ぎます**。
```text
  去看看竞品今天的动态，总结一下他们是不是要跟我们打价格战。
  ```
客観的なデータと推測を分けるように変更：
```text
  访问竞品官网的公开定价页与首页横幅，获取他们当下的方案价格表。
  对照我们在 /workspace/competitor/last-month-price.json 中记录的旧价格：
  1. 事实列：标出哪些 SKU 的标价发生了变动，变动金额是多少，附带页面截图与访问时间。
  2. 推测列：基于该降价是限时促销还是永久调价，给出你的分析理由。
  两部分内容必须分开分栏呈现，不得将分析推论当作已知事实。
  ```

4. **読み取り専用の保護**：主テーブルと従属テーブルの関係や保持すべきフィールドを指示しないと、**元データが上書きされて破損するリスクが極めて高くなります**。
```text
  （直接拖入三个 Excel 表格）把这几个表整理一下。
  ```
どのテーブルを基準にするかを明確にし、読み取り専用として指定するように変更：
```text
  上传的三个表格分别是 7 月、8 月和 9 月的销售明细。
  以「订单编号」为唯一主键进行数据去重合并：
  1. 字段统一保留：订单号、成交日期、客户名称、销售代表、成交金额。
  2. 生成一份全新的 Q3_sales_summary.csv 文件，保存在当前工作区。
  3. 保持我上传的原始 7、8、9 月表格内容与文件名完全不变。
  ```

5. **単一の責務**：1つの Bot に複数のタスクを詰め込まないこと。記憶が混乱するだけでなく、**週間利用枠を急速に使い果たしてしまいます**。
```text
  你帮我写一篇关于新产品的推文，顺便把昨天的账目算了，然后再帮我看看竞品推特。
  ```
単一タスクに分割して役割分担させるように変更：
```text
  遵循一个 Bot 负责一项核心任务的原则。当前 Bot 仅承担社媒文案起草职责：
  依据 /workspace/product/spec.md 中的新功能说明，为 X 平台起草三条不同风格的发布文案。
  要求突出性能提升数据，字数控制在 280 字符以内。
  账目核算与竞品调研交由对应的专用 Bot 负责，不要在此会话中处理。
  ```

## 実際の業務引き継ぎ事例

### Webサイトの日常巡回点検と証跡の保存
サイト管理者の yishan 氏は、巡回点検の要件をそのまま検収基準として明文化しました。作業ディレクトリは厳格に `/workspace/site-check/` に限定し、トップページ、最新記事、購読エントリーのみの点検を許可し、無作為なクローリングは厳禁としています。
- レポートには完全なリンク、タイムスタンプ、当時のスクリーンショットを必ず残す必要があります。**直接確認できたエラーは事実として扱い、原因の分析は推測として扱い、必ず分けて記録します。**

## 陥りやすい落とし穴

1. **添付ファイルには説明を添える**：複数の画像や2つ以上のテーブルを送信する際は、**必ず用途を明記してください**。そうしないと主従関係を取り違えやすくなります。
2. **長期ルールは記憶領域に保存する**：単発の指示はセッションが変わると失われます。基本規範やレッドラインは **Bot の詳細にある「About / 役割」に記述する**か、記憶領域に保存してください。
3. **ローカル連携時はスリープを防止する**：純粋なクラウド実行ならノート PC を閉じても動き続けますが、ローカル PC と連携している場合はスリープすると接続が切断されます。**電源とスリープの設定を忘れずに確認してください**。
4. **Bot 間の画像受け渡しはパス経由で行う**：グループ内の Bot 間ではプレーンテキストのみがサポートされています。画像を渡す場合は、**共有パス `/workspace/` に保存して**相手に読み取らせる必要があります。
5. **音声ボタンが消えたらまずは入力欄を空にする**：入力欄に未消去の文字やスペースが残っていると波形ボタンが非表示になります。**入力欄を完全に空にすれば**元に戻ります。
6. **高リスクな操作では「1回のみ許可」を選択する**：メール送信やデータの変更・削除では「常に許可」を選ばず、安定して数週間運用できるまでは、**「1回のみ許可」を選び続けてください**。

## 完了後の検収方法

1. `/workspace/` または指定されたディレクトリに移動してファイルを確認し、**正常にプレビューでき、文字化けがないことを確認します**。一時的なテキスト表示だけで判断しないでください。
2. 2〜3箇所の重要なデータを無作為抽出し、リンクを開くかスクリーンショットを確認して、モデルによる作り話（ハルシネーション）を防ぎます。
3. 呼び出しログを確認し、**無断で外部通信を行っていないか、設定の変更や元ファイルの上書きをしていないかを確認します**。
4. 事実と推測を明確に区別し、ページ上の原文は事実エリアに、推論や提案は備考エリアに記載させ、混同している場合はその場で修正します。
5. 例外一覧を確認し、**無効な Web ページや欠損フィールドがあった場合は理由を記録した上で最後まで実行されていること**を確認します。エラーが出たからといって即座に中断させないようにします。
