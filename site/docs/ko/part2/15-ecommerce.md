## 사례 1: 시엔위 등록 담당자 (중고 매물 정보 보드 및 상담 초안)

Miles Ma(@miles_mazy, @0xlangeai 영감)가 제작한 Bot입니다. 중고 상품을 AI에 바로 넘기면 **완전 새 제품 스펙으로 엉뚱하게 지어내기 쉽습니다**. 이 Bot은 실제 상태와 공식 웹사이트의 스펙을 분리하여 2단 정보 보드와 문의 응답 초안을 생성합니다.

### 단계 및 검수

1. 전면, 하자 클로즈업 및 라벨 사진을 촬영하고 구성품, 직접 수령 방식, 판매가를 정리합니다.
2. Grok Bot 사이드바에서 `+`를 클릭하고 '새 Bot 만들기'를 선택한 뒤, 이름을 '시엔위 등록 담당자'로 지정합니다.
3. 실물 사진을 업로드하고 프롬프트를 전송합니다. 가격 89위안의 중고 로지텍 K380s 키보드를 예로 듭니다.

```text
帮我做一份闲鱼上架资料。商品是罗技 K380s，黑色，用了 8 个月，空格键有轻微磨痕，逐键输入正常，没拆过机；附两节在用电池，无包装，卖 89 元，支持自提，邮费待确认。查官方型号资料，整理标题、商品描述、需要补拍的照片和常见咨询回复，做成可打开的资料板，并附可复制的上架正文。没提供的信息标为待确认。
```

4. Bot이 인터넷을 통해 공식 웹사이트 스펙을 조회하고, HTML 정보 보드와 일반 텍스트 초안을 생성합니다.

## 사례 2: 샤오홍슈 에디터 (주제 선정부터 6장의 지식 카드 뉴스 및 갤러리까지)

![사례 2: 샤오홍슈 에디터 (주제 선정부터 6장의 지식 카드 뉴스 및 갤러리까지)](/info/15-ecommerce-s2.png)

### 제작 단계

1. Grok Bot 사이드바에서 새 Bot을 만들고, 이름을 '샤오홍슈 에디터'로 지정합니다.
2. 주제와 핵심 포인트를 확정하고, 카드를 6장으로 구성하며, 1080×1440 해상도와 메인/보조 색상 배색을 설정합니다.
3. 대화 인터페이스에 들어가 프롬프트를 전송합니다:

```text
给电脑新手做一套小红书图文，主题是“Windows 截图后，图片去哪了”。查微软官方资料，做 6 张 1080×1440 的图：封面、框选截图、整屏保存、当前窗口、剪贴板历史、快捷键对照表。用米白、深蓝和亮黄，文字清楚，配操作示意。直接交 PNG 成图、SVG 源文件和配套发布正文，再做一个能看全套图片的画廊。
```

4. **Bot이 공식 문서를 조회하여 단축키를 대조 확인**한 뒤, SVG를 생성하고 PNG로 렌더링하여 HTML 갤러리로 통합합니다.

### 검수 및 주의사항

| 카드 | 콘텐츠 및 레이아웃 |
| :--- | :--- |
| 1번째 장 | 표지, 중앙에 큰 글씨로 캡처 관련 불편/궁금증 제시 |
| 2~5번째 장 | 단계별 카드, 영역 지정 캡처, 전체 화면 캡처 등 방식 도해 |
| 6번째 장 | 요약 카드, 4가지 캡처 방식 및 저장 위치 정리 표 |

- 전체 카드는 미색(아이보리) 배경에 짙은 파란색 텍스트, 밝은 노란색 포인트 색상을 사용합니다. **반드시 6장의 1080×1440 PNG, SVG 소스 코드, 태그가 포함된 본문 문구 및 온라인 갤러리를 전달받아야 합니다**.
- 스크린샷 자동 저장은 시스템 앨범 설정에 의존하며, **`Win + V` 클립보드 기록 조회를 사용하려면 사전에 해당 기능 스위치를 켜두어야 하고**, 기록이 덮어쓰기 되지 않았어야 합니다.
- 오탈자 수정은 텍스트 에디터에서 SVG 파일을 직접 수정하면 되므로, **이미지를 다시 생성할 필요가 없습니다**.

## 사례 3: 도구 정보 브리핑 담당자 (용도별 필터링을 지원하는 소프트웨어 분석 브리핑)

Miles Ma가 제작한 '도구 정보 브리핑 담당자' Bot은 오픈소스 저장소와 문서를 전문적으로 수집하여, 카테고리별 필터링을 지원하는 웹 카드 형식의 브리핑을 생성합니다.

### 도구 제한 사항 및 권장 작업

| 도구 | 진입 장벽 및 의존성 | 주요 제한 사항 | 권장 작업 |
| :--- | :--- | :--- | :--- |
| **PowerToys** | Windows 설치 프로그램으로 즉시 실행 가능 | Windows 전용, 일부 실험적 기능의 간헐적 불안정성 | 단축키로 텍스트 추출 또는 창 항상 위에 고정 |
| **MarkItDown** | Python 또는 커맨드라인 환경 필요 | 복잡한 그래픽/텍스트 레이아웃의 인식률 한계 | Word 및 PDF 파일을 Markdown으로 일괄 변환 |
| **changedetection.io** | Docker 또는 서버 환경 필요 | 운영/관리(DevOps) 기본 지식 필요, 크롤링 방지 제약 받음 | 전자상거래 가격 태그 변동 모니터링 |

### 작업 단계

1. Grok Bot 사이드바에서 새 Bot을 만들고 이름을 '도구 정보 브리핑 담당자'로 지정합니다.
2. 조사 대상 타깃과 분석할 도구 목록을 확정합니다.
3. 대화 인터페이스에 들어가 프롬프트를 전송합니다.

```text
帮内容工作室整理 PowerToys、MarkItDown 和 changedetection.io，查官方仓库和文档。每个工具写清能帮忙做什么、上手需要什么、主要限制，再给一个具体使用例子。做成能按用途筛选的网页简报，附来源链接。
```

4. Bot이 저장소 설명과 의존성 정보를 수집한 후, **필터링 스크립트가 포함된 HTML 브리핑을 작성**하여 워크스페이스에 저장합니다.

### 검수 기준 및 주의사항

- 각 카드는 도구의 포지셔닝, 시작 시 의존성뿐 아니라 주요 제한 사항, 실전 작업 및 공식 웹사이트 링크를 포함하는 **6가지 핵심 요소를 갖추어야 합니다**.
- 웹페이지 상단에 카테고리 버튼을 배치하여 카드를 매끄럽게 필터링할 수 있어야 합니다.
- 제한 사항 설명은 반드시 객관적이어야 하며, changedetection.io에 Docker나 서버가 필요함을 명확히 명시하고 진입 장벽이 전혀 없다고 과장하지 않아야 합니다.
- 이는 데스크 리서치 기반의 선별 단계이므로, **Bot이 전체 프로세스 실측 테스트를 진행하지 않으며**, 주로 요구 조건에 맞지 않는 후보 소프트웨어를 빠르게 걸러내는 데 사용됩니다.

## 사례 4: 비디오 튜토리얼 제작자 (인터랙티브 학습 도구 및 자막 포함 숏폼 영상)

Miles Ma(@miles_mazy, @0xlangeai 란거 AI 영감)의 활용법입니다. 루빅스 큐브의 시계/반시계 회전 및 4회 회전 원위치 복귀는 글만으로 설명하기 어렵고, 직접 촬영하기에는 시간이 많이 소요됩니다. **Grok Bot은 클라우드에서 인터랙티브 웹페이지를 작성하고 화면을 자동 녹화하여 자막을 인코딩할 수 있습니다**.

### 제작 방법

1. 사이드바에서 새 Bot을 만들고 이름을 '비디오 튜토리얼 제작자'로 지정합니다.
2. 전체 해법 알고리즘은 피하고, **한 번에 기본 동작 하나만 다룹니다**.
3. 프롬프트를 전송합니다:

```text
给孩子做一个魔方入门小工具，能认识六个面、点按钮演示右面顺转和逆转，再展示右面连续转四次回到原位。把实际操作录成一分钟左右的教学视频，加中文配音和字幕，交付视频和工具文件。
```

4. Bot이 자동으로 웹페이지를 작성하고, 클릭을 시뮬레이션하여 화면을 녹화한 뒤 중국어 자막이 포함된 영상을 생성합니다.

## 사례 5: 북마크 정리 담당자 (소셜 미디어 북마크를 콘텐츠 소재 저장소로 변환)

Miles Ma(@miles_mazy)가 북마크를 주제 소재 라이브러리로 변환하기 위해 제작한 Bot입니다.

1. 사이드바에서 새 Bot을 만들고 이름을 '북마크 정리 담당자'로 지정합니다.

```text
整理这几条 X 收藏链接，按主题分类，每条留下作者、原链接、核心观点和可以借鉴的写法。再围绕“给新手的 AI 实操教程”提出三个具体选题，做成 Markdown 素材库和选题清单。
```

## 사례 6: 아마존 팀 구축 (스토어 프런트 순찰 점검부터 '1+12' 다직무 협업까지)

### 배경 및 역할 포지셔닝

- **누가**: Zach(@1999Zach22).
- **무엇을 했는가**: 기존에 로컬 Claude/Codex에서 실행하던 Skill을 Grok Bot으로 전면 마이그레이션하여, 공유 클라우드 PC 상에서 '1명의 해외 진출 선장 + 12개 비즈니스 직무'로 구성된 아마존 크로스보더 이커머스 AI 운영팀을 구축했습니다.

### 개요

Codex CLI와 같은 로컬 도구는 컴퓨터를 항상 켜두어야 하므로 외출 시 확인할 수 없습니다. **Grok Bot은 24시간 상시 가동되는 미국 클라우드 PC를 기본 제공**하여 모바일과 PC 간 연동이 가능하며, 실제 구매자 계정으로 아마존 스토어 프런트를 둘러보고 질문할 수도 있습니다.

Zach는 **'1명의 선장 + 12개 비즈니스 직무'** 아키텍처를 도입했습니다. 사용자는 오직 해외 진출 선장과만 소통하며, 선장이 각 직무를 총괄 조율합니다.

**모든 직무는 셀러 백오피스(관리자 화면)를 직접 수정하는 것이 엄격히 금지**되어 있으며, 사람이 직접 확인할 수 있도록 승인 대기 목록만 출력합니다.

| 직무 | 담당 업무 | 엄격히 금지된 한계선 |
| :--- | :--- | :--- |
| 해외 진출 선장 | 하위 팀원 총괄 조율, 주간 보고서 및 목록 보고 | 사람을 거치지 않고 직접 비즈니스 의사결정 금지 |
| 어시스턴트 / 파이럿(해적) / VOC | 매칭 판매(Buy Box 가로채기) 모니터링, 상품 발굴 조사 및 부정 리뷰 분석 | 셀러 백오피스 로그인 금지, 임의 프로젝트 착수 금지 |
| 재무 / 광고 담당자(바이어) | 단일 상품 마진 계산 및 광고 최적화 제안 제공 | 백오피스에 로그인하여 입찰가를 수정하거나 제외 키워드를 추가하는 행위 절대 금지 |
| 카피라이터 / 디자이너 / 게이트키퍼 | 카피라이팅, 이미지 제작 및 컴플라이언스 최종 심사 | 직접 사이트에 게시 금지, 사람 대신 최종 결정 금지 |
| 리뷰(피드백) 봇 | 주간 산출물 취합 및 경험 데이터베이스 업데이트 | 운영상 문제 축소/은폐 금지, 성과 날조 금지 |

### 실행 방법

#### 1. 구독 플랜 및 환경 준비
- **입문 시 월 30달러 Premium 플랜을 선택**하며(월 8달러 Plus 플랜에는 Bot 기능이 전혀 없음), 필요에 따라 100달러 Super 플랜이나 200달러 Ultra 플랜으로 업그레이드합니다.
- PC와 모바일에서 동일 계정으로 로그인하여 **클라우드 PC가 정상 작동하는지 확인**합니다. 자세한 내용은 [Grok Bot 方案与用量指南](https://cursor.com/cn/help/grok-bot/plans)를 참조하세요.

#### 2. 먼저 단일 Bot으로 세 가지 작업을 검증
클라우드 PC의 미국 IP와 브라우저를 활용해 다음 3가지 검증을 완료합니다:
1. **자사 Listing 일상 순찰 점검**: 대표 이미지, 가격, 옵션(Variant) 및 매칭 판매를 점검하고, 이상 발견 시 대조 증빙 자료를 첨부하여 보고합니다.
2. **Alexa 쇼핑 Q&A 테스트**: 구매자 계정으로 로그인하여 질의하며, 실측 기준 약 8분 만에 8가지 시나리오를 테스트하고 최근 30일간의 가격 변동 내역을 조회합니다.
3. **경쟁 상품 정기 모니터링**: 가격과 쿠폰을 기록하며, **변동이 있을 때만 알림을 발송**하고 변동이 없으면 불필요한 알림을 보내지 않습니다.

```text
每天固定时间去前台检查自家 Listing：主图和价格是否正确，变体是否正常挂载，核心关键词是否能搜索到，是否存在跟卖。只记录指定商品和关键词，有异常才发提醒，并附带与前一日的对比数据和页面截图证据。不登录店铺后台，不执行任何写操作。
```

```text
从消费者的角度，尽可能多地把 Alexa for Shopping 体验一遍，最后给我一份报告。
```

#### 3. 기능 및 직무 경계 세분화
- 검증을 마친 후 작업을 12개 비즈니스 직무로 나눕니다.
- 광고 및 신상품 등록 등 **민감한 직무는 백오피스에 직접 데이터를 입력하는 것을 명문으로 금지**하고, 무조건 '승인 대기 목록'을 제출하도록 하며 명확한 승인 요청 기준을 설정합니다.

```text
你是合理烧钱的广告投手。负责分析广告效率、搜索词转化率、出价与预算建议。
边界约束：
1. 绝对不登录广告后台，不直接修改出价，不调整预算，不添加否定关键词，不新建广告活动；
2. 所有优化建议必须生成「待批清单」，每条建议必须附带调整依据和预期影响；
3. 待批清单单线交付给出海船长，由船长提报给业务负责人审核，严禁自主执行。
```

#### 4. '1+N' 인수인계 체인 구성
- **절대 여러 Bot이 참여하는 단체 대화방(그룹 채팅)을 만들지 마세요**. 단체 대화방은 컨텍스트를 중복 수신하여 Token을 매우 빠르게 소모합니다.
- **1+N 아키텍처를 채택**하여, 사람은 오직 '해외 진출 선장'과만 소통하고, 선장이 작업을 배분하고 결과를 취합하도록 합니다.

```text
你是出海船长，负责统筹 12 个业务岗位。日常接收业务负责人的目标，拆解为具体子任务派发给对应岗位。所有下属岗位向你单线汇报，由你汇总结果、审核质量；不达标的打回重做，需要人工决策的整理为带选项和依据的待批清单汇报给人。严格遵守交接链规则：
1. 巡检链：助理上报异常与证据，派给数据或广告岗位做归因分析；
2. 选品链：海盗提交机会报告，财务测算单品利润，由你整理为立项建议书提报给人；
3. 上新链：文案出草稿，设计出图，守门员审核，你做终检后交给人确认，由人工在后台发布；
4. 复盘链：收齐各岗位经验，复盘机器人写周报并更新经验库，据此编排下周计划。
所有岗位严禁直接登录店铺后台或执行未授权的修改操作。
```

#### 5. 자산 공유 및 로컬 제어
- 모든 Bot은 **동일한 클라우드 PC 및 디스크를 공유**하므로, 스크립트를 워크스페이스에 복사해 두면 전원이 함께 사용할 수 있습니다.
- 로컬 파일을 읽으려면 설정의 '컴퓨터' 페이지에서 **'이 컴퓨터에서 실행'(Execution on Local Computer)을 활성화**하고 복사할 디렉터리를 지정해야 합니다.

  자세한 내용은 [Grok Bot 计算机和应用文档](https://cursor.com/cn/docs/grok-bot/work)와 [Grok Bot 设置说明](https://cursor.com/cn/docs/grok-bot/settings)을 참조하세요.

## 자주 빠지는 함정

- **셀러 백오피스 수정 권한을 절대 부여하지 마세요**: 가격 오기재나 계정 정지를 방지하기 위해 민감한 작업은 Bot이 '승인 대기 목록'을 출력하게 하고 사람이 직접 실행해야 합니다.
- **시엔위 상태 자의적 추측 방지**: 공식 사이트의 새 제품 스펙이 섞여 들어가 반품이 발생하는 일이 없도록 '판매자가 제공한 정보를 기준으로 하며, 제공되지 않은 항목은 확인 필요로 표기'할 것을 요구해야 합니다.
- **12개의 Bot을 하나의 단체방에 넣지 마세요**: 몇 번의 대화만으로도 일주일 치 사용 한도를 모두 소진할 수 있습니다. 대신 '1+N' 주종(마스터-슬레이브) 아키텍처를 도입하고, 파일 디스크 저장을 통해 중계하세요.
- **경쟁사 데이터 수집은 일일 1회가 적당합니다**: 몇 분 단위로 폴링하면 IP가 쉽게 차단되고 사용 한도가 금방 소진됩니다. 빈도가 높은 작업은 공식 API나 MCP를 이용하세요.
- **월 30달러의 Premium 플랜을 확인하세요**: 월 8달러의 Plus 플랜에는 Bot 진입 경로가 없습니다. 2026-10-12부터 적용되는 The X Subscription을 확인하세요.
- **로컬 제어 시 반드시 경로를 제한하세요**: '항상 허용'을 켜지 마시고, 제어 전에 파일 경로를 지정하고 팝업 확인 창을 유지하여 개인 파일이 실수로 변경되는 것을 방지하세요.

## 완료 후 검수 방법

**결과물 전달 후 기준에 따라 항목별로 꼼꼼히 확인**하고 방심하지 마세요.

- **시엔위 정보 보드**: 하자 사항과 공식 스펙을 분리하고, 확인되지 않은 항목은 '확인 필요'로 표기해야 합니다. 직접 수령 주소를 임의로 지어내거나 배터리 상태를 허위 기재하는 것은 엄격히 금지됩니다.
- **샤오홍슈 카드 뉴스**: 6장의 1080×1440 이미지 카드 및 SVG 소스 코드를 제출하고, 단계별 설명에 단축키 및 시스템 전제 조건을 명확히 강조해야 하며 배색을 어지럽히지 않아야 합니다.
- **도구 브리핑**: 단일 페이지 HTML에 필터링 기능과 공식 링크가 포함되어야 하며, Docker 환경 요구 조건을 사실대로 명시해야 합니다. 배포 과정을 무조건 쉽다고 과장해서는 안 됩니다.
- **튜토리얼 영상**: 완성 영상은 약 1분 분량으로 화면과 음성이 동기화되어야 하며, 웹 도구 소스 코드가 반드시 동봉되어야 합니다. 자막과 영상 싱크가 어긋나지 않아야 합니다.
- **소재 저장소**: 원작자와 원본 게시물 링크를 보존하고, 주제는 한 번의 실전 작업으로 실행할 수 있게 구체화해야 합니다. 막연한 요약이나 타인의 사례를 자신의 것으로 둔갑시켜서는 안 됩니다.
- **전자상거래 협업**: 1+N 아키텍처 하에서 선장과만 소통하고, 가격 조정 및 등록 시 반드시 승인 대기 목록을 작성해야 합니다. 임의로 가격을 수정하거나 무한 루프로 사용량을 탕진하는 것을 엄격히 금지합니다.
