# 제12장 사례: 1인 미디어 및 콘텐츠 팀

대화형 AI는 문맥을 놓치기 쉽지만, **Grok Bot은 클라우드 컴퓨터의 공유 파일로 파이프라인을 실행합니다**.

1. 역할 설명을 작성하고 6개 필수 필드에 따라 소재 라이브러리를 구축합니다.
2. 리서치 Bot이 카드를 디렉터리에 기록하고, 메인 작가 Bot이 이를 읽은 후 카피를 작성합니다.
3. AI 특유의 말투를 제거하는 교정 규칙을 적용하고, 트윗을 개인 웹사이트로 변환합니다.
4. **핵심 발행 단계는 반드시 사람이 직접 검토하여** 허위 데이터 및 플랫폼 위험 관리(어뷰징 제재)를 회피해야 합니다.

## 1인 미디어 팀의 직무 설계 및 협업 메커니즘

![1인 미디어 팀의 직무 설계 및 협업 메커니즘](/info/12-content-s1.png)

### 개념

**Grok Bot에서 팀을 구성할 때 핵심은 '1인 1역(단일 직무 단일 책임)'입니다.** 계정 내 모든 Bot은 동일한 클라우드 컴퓨터(독립적인 커널, 메모리 및 `/workspace` 경로 보유)를 공유하지만, 각자 독립된 창, 메모리 및 설정을 갖습니다.

Bot 간에는 공유 폴더에서 Markdown 파일을 읽고 쓰며 업무를 인수인계합니다.

### 진행 방법

**별표가 표시된 메인 Bot(프로필 사진 우클릭으로 전환 가능)**이 전체 작업을 총괄 및 배분하고, 5~6개의 전담 Bot이 엄격한 직무 경계에 따라 작업합니다.

| 직무명 | 산출물 경로 | 핵심 책임 및 금지 작업 |
| :--- | :--- | :--- |
| 정보 정찰원 | `/workspace/content-team/01-inbox/` | 1차 소스 단서 수집. 게시글 인터랙션 및 DM 발송 엄격 금지, 2차 발언을 사실로 취급하는 행위 엄격 금지 |
| 소재 기획자 | `/workspace/content-team/02-briefs/` | 단서 평가 및 Brief 작성. 외부 웹 서핑 엄격 금지, 사람의 승인 없이 메인 작가에게 전달 금지 |
| 콘텐츠 메인 작가 | `/workspace/content-team/03-drafts/` | `voice.md`에 기반한 작성. 사실 날조 및 진부한 PR 어투 엄격 금지 |
| 팩트 에디터 | `/workspace/content-team/04-review/` | 1차 출처 검증. 발행 권한 없음, 근거 충돌 시 확인 대기 항목으로 나열 |
| 데이터 분석가 | `/workspace/content-team/06-analysis/` | 콘텐츠 데이터 분석. 계정 인터랙션 엄격 금지, 상관관계를 인과관계로 작성 금지, 데이터 부족 시 임의 추측 엄격 금지 |
| 웹 엔지니어 | `/workspace/tweet-portrait/` | 페르소나 추출 및 사이트 구축. 경력 위조 엄격 금지, 로컬 경로를 공개 웹 링크로 처리 금지 |

1. 클라우드 컴퓨터 터미널에서 표준 공유 디렉터리를 생성합니다.
::: details 진행 방법
```text
/workspace/content-team/
├── 00-profile/     # 账号定位、目标读者、范文、禁用表达（voice.md）
├── 01-inbox/       # 情报侦察员的一手信息卡
├── 02-briefs/      # 选题策划师的选题 Brief
├── 03-drafts/      # 内容主笔的候选稿
├── 04-review/      # 事实编辑的审校稿
├── 05-published/   # 已发布文案存档、数据截图或 CSV
└── 06-analysis/    # 数据复盘师的周报与实验记录
```
:::
2. `00-profile/voice.md`에 스타일 베이스를 작성하여 메인 작가가 상투적인 문구를 생성하지 않도록 합니다.
::: details 진행 방법
```text
# 账号定位
- 我长期写：面向个人创业者与开发者的 AI 工具实测与提效工作流
- 我的目标读者：正在用 AI 尝试做独立产品、做内容或做业务转型的实干者
- 读者看完后应该获得：直接能照着执行的步骤、准确的参数配置、明确的避坑提醒

# 写作样本
- 代表作 1：【粘贴一段自己数据最好、语言最顺的代表作】
- 代表作 2：【粘贴一段带步骤拆解的教程代表作】

# 表达习惯
- 常用语气：像跟坐在对面的朋友复盘经验，冷静、直白、短句为主
- 禁用表达：我的判断是、毫无疑问、重塑格局、颠覆行业、进入新时代、不难看出
- 不会公开谈论的内容：未经实测的空头八卦、无法复现的玄学跑分

# 商业与事实边界
- 必须保留原始来源的主张：所有关于产品上线、价格变动、官方改版的陈述
- 未亲测时的写法：必须显式标明“未核实”或“作者自述”
```
:::
3. **그룹 생성 및 규칙 배포**. '새 채팅'을 클릭하여 '1인 미디어 콘텐츠 팀' 그룹 채팅을 생성하고 전원을 초대합니다. 처음에는 절대로 소재를 바로 배정하지 말고, 반드시 먼저 통일된 규정을 배포해야 합니다.
```text
这是“自媒体内容团队”协作群。工作顺序固定为：情报侦察员 → 选题策划师 → 内容主笔 → 事实编辑；内容发布后，数据复盘师读取授权数据 → 06-analysis。所有中间文件放到 /workspace/content-team/ 对应目录。任何登录、外发、发布、点赞、回复、关注、私信、购买、删除、连接器授权或权限修改都必须先获得用户明确批准。本次仅确认收到和各自交付路径，不执行外部操作。
```

### 소재 및 정보: 수집, 지표 및 동기 분석

> 출처: [1인 미디어 운영에 Grok Bot 잘 활용하는 법](https://x.com/KinGao476942/status/2099736121781764594)  
> 작성자: [Kin @KinGao476942](https://x.com/KinGao476942)

소재를 찾을 때 범용 모델과 직접 잡담하지 마세요. 구시대의 지난 뉴스만 쏟아낼 뿐입니다. 여기서는 정찰 Bot이 검색을 시뮬레이션하거나 모니터링하여 단서를 카드로 정리하게 합니다.

먼저 정찰원에게 장기 직무 프롬프트를 설정합니다:

::: details 소재 및 정보: 수집, 지표 및 동기 분석
```text
你是我的情报侦察员（Scout）。唯一职责是发现、核验并沉淀可用于选题的公开信息，为后续选题提供证据；不写成稿，不替用户下结论。

【允许使用】
- 公共互联网中的官方公告、产品文档、论文、GitHub Release、作者原文与用户提供材料。
- 知乎、微博、X、小红书等平台的公开页面、公开帖子和公开评论区，可用于搜索线索、观察讨论和摘录公开信息。
- 共享目录 /workspace/content-team/00-profile/ 与 /workspace/content-team/01-inbox/。
- 如页面要求登录、密码、验证码、2FA、passkey，或需要扩大权限，必须立即停下并请求用户接管。

【禁止】
- 不得发帖、改帖、删帖、点赞、转发、收藏、关注、取关、评论、回复或私信。
- 不得读取私信、好友可见内容、非公开页面或与任务无关的个人数据。
- 不得把平台用户发言、热榜或搜索摘要直接当成已确认事实；它们只能标为“平台线索”或“观点”，关键主张必须回到官方原文、一手材料或当事人公开内容核验。
- 不得凭记忆补数字、日期、引语或因果。
- 不得索取或记录账号密码与验证码。
- 不得执行本机命令，不得访问本机文件。

【固定交付】
写入 /workspace/content-team/01-inbox/YYYY-MM-DD.md，每次最多 8 条。每条包含：事实或平台线索、来源平台、原始链接、证据摘录、讨论热度或代表性观点、为什么值得关注、一个待核查问题、核验状态。
```
:::

**소재 라이브러리는 반드시 6개 필수 필드를 엄격히 고정해야 하며**, 하나라도 누락되면 즉시 폐기합니다:
- 출처 및 신선도: 열람 가능한 원본 게시글의 영구 링크, 게시 시간 및 경과 시간 기록. '어떤 블로거' 등으로 모호하게 쓰지 않음.
- 공개 데이터: 조회/재생 수, 좋아요 수, 리트윗(공유) 수, 댓글 수 등 총 4개 항목 및 수집 시간. 찾을 수 없는 경우 '공개 데이터 없음'으로 표기하며, 임의 추정 엄격 금지.
- 작성자 등급 분류: handle, 팔로워 수 및 계층 기록. 낮은 팔로워 대비 고조회수 게시글은 구조를 벤치마킹하고, 메가 인플루언서는 어젠다(의제)를 관찰.
- 커뮤니티 분류: 공식, 국내, 해외로 명확히 분류.
- 적합한 이유 및 실행 관점: 자신의 강점과 결합하고, 구체적인 실행 방안(예: 실제 테스트 진행, 세부 단계 보완, 템플릿 제공 등)을 명시하며, 막연히 '인기 많음'이라고 쓰지 않음.
- 동기 분석: 페인 포인트(통증점), 소구점(만족감), 인터랙션 동기 포함. 데이터 뒷받침이 없는 추론 끝에는 반드시 '추정'이라고 표기.

기획자는 `01-inbox/`에서 가치가 높은 소재 3개를 선별하고, 사실의 구체성·독자와의 관련성·작성자가 할 말이 있는가의 3단 관문을 거쳐 Brief를 추출한 후 `02-briefs/`에 작성합니다:

```text
读取今天 01-inbox 中已经核验的线索，按照账号定位筛选 3 个候选题，写入 02-briefs/YYYY-MM-DD.md。每题包含：一句话事实、读者场景、单一主角度、原始链接与证据、信息缺口、建议内容形式、给主笔的写作任务。证据不足的题直接标“待补证”。完成后停下，等待我批准，不要通知内容主笔。
```

구축 방향이 막힌다면, 인터뷰형 프롬프트를 사용하여 메인 Bot이 질문을 통해 요구사항을 정리하도록 합니다:

::: details 소재 및 정보: 수집, 지표 및 동기 분석
```text
我想新建一个 Bot，帮我做一件需要重复做的工作。请你先通过提问把这件事了解清楚，再帮我把这个 Bot 创建出来。

提问的时候：
- 一次只问一个问题，用大白话问，我回答完再问下一个。
- 我回答得不清楚的地方，你可以追问，也可以给我几个选项让我选择。
- 你需要了解清楚这几件事：这个 Bot 主要负责什么，做完以后要交给我什么，要去哪里做、用哪个账号，每一步要怎么做、做到什么程度算完成，遇到什么情况要先停下来问我，结果放在哪里，什么时候执行。
- 有些问题我也不知道答案，你就先去搜索解决方案，把你建议的做法告诉我，我确认以后再继续。

问完以后：
- 先把你了解到的内容整理成一份岗位说明给我看，我确认没问题以后，再创建这个 Bot，并且设置好例行任务。
- 创建好以后，先试着执行一遍，把结果拿给我看。
- 登录、付款、发布、删除这些操作，都要先问过我。
```
:::

**검수 기준**
- 원본 링크가 모두 열리며, 핵심 사실을 뒷받침하는 원문이 존재해야 함.
- 근거가 부족한 경우 '근거 보완 대기'로 분류하며, **사람의 서명 승인 없이는 절대로 메인 작가 단계로 넘어가지 않아야 함**.

### 초안 및 원고 작성: AI 어투 제거와 구조화된 출력

초안을 작성할 때는 먼저 주어를 '제품에 무엇이 있는가'에서 '독자에게 어떤 도움이 되는가'로 전환하여, **독자가 처음 3초 안에 명확한 정보적 가치(정보 증분)를 볼 수 있도록 해야 합니다**.

원고는 이미 검증된 두 가지 프레임워크를 그대로 적용할 수 있습니다:
- 스톰 필름(影视飓风) Tim의 HKRR 공식: 재미(Happiness), 지식(Knowledge), 공감(Resonance), 리듬(Rhythm)을 포괄. 한 편당 최소 한 항목은 확실히 충족해야 하며, 두 항목을 충족하면 우수하고, 하나도 충족하지 못하면 즉시 폐기합니다.
- 판루안(潘乱)의 공유(리트윗) 동기: '나와 관련 있음'을 중심으로 주어를 독자로 바꿉니다. 예를 들어 "소프트웨어가 업데이트되었습니다"라고 쓰지 말고, "매일 소재 찾기에 쓰던 시간을 2시간 절약했습니다"로 작성합니다. 바이럴 구조는 재사용할 수 있으며, 리듬을 차용하되 내용을 모방하지는 않습니다.

메인 작가에게 명확한 작성 규칙과 금지 사항을 입력합니다:

::: details 초안 및 원고 작성: AI 어투 제거와 구조화된 출력
```text
你是我的内容主笔（Writer）。唯一职责是把已经批准的 brief 写成候选稿；不负责找热点、补事实、决定选题或发布。

【允许使用】
- /workspace/content-team/00-profile/voice.md 中的定位、范文、禁用句式与术语。
- /workspace/content-team/02-briefs/ 中已经批准的事实、链接、角度和限制。
- 输出到 /workspace/content-team/03-drafts/。

【禁止】
- 不得自行浏览外部网站、登录平台或调用连接器。
- 不得自行补充数字、引语、案例、比较级或因果。
```

## 주의해야 할 함정

1. 클라우드 컴퓨터에서 게시글을 작성하면 지문이 노출되어 계정이 차단될 수 있으며, 전자동 방식은 잘못된 내용을 무차별 게시하기 쉽습니다. **게시글 작성, 좋아요 및 DM 발송은 반드시 실제 기기에서 수동으로 수행해야 합니다**.
2. 역할 설명에 **'데이터가 없으면 「찾을 수 없음」으로 표기하고, 추론에는 「추정」을 붙인다'는 규칙을 고정하여** 가짜 데이터가 입력되는 것을 방지합니다.
3. 클라우드 컴퓨터가 재설정되면 의존성이 모두 지워집니다. **Shell 복구 스크립트를 영구 디렉터리에 저장해 두고** 대비하세요.
4. Routine 작업의 **실행 주기를 꼼꼼히 확인하여**, '평일만 실행'으로 잘못 설정해 주말에 파이프라인이 끊기는 일이 없도록 하세요.
5. 샷 필터링을 하지 않아 주간 쿼터의 40% 이상이 급감한 적이 있으므로, **고주파 공회전 폴링을 엄격히 금지하고 트리거 시점을 최적화하세요**.

## 완료 후 검수 방법

### 권한 및 디렉터리
1. 계정 설정 '일반 → Agent → 이 컴퓨터에서 실행'으로 이동하여 **상태가 반드시 '허용 안 함'이어야 합니다**. Bot의 자동 게시글 작성 및 결제는 엄격히 금지되며, 데이터 날조도 허용되지 않습니다.
2. `/workspace/content-team/` 아래의 7개 하위 디렉터리를 확인하고, `00-profile/voice.md`에 계정 포지셔닝, 예시 템플릿 및 금지 단어를 작성합니다.

### 취재·작성 및 리허설
1. 단서 3개를 수집하고, **2개 링크를 샘플링 검사하여 접속 가능 여부 및 원문 뒷받침 여부를 확인합니다**. 데이터가 부족한 경우 '공개 데이터 없음'으로 표기하며, 수치나 팔로워 수를 임의로 추측해서는 안 됩니다.
2. Brief 확인 후 초안을 작성하며, 첫 두 문장에서 핵심 사실을 바로 제시하고, 문단은 2~4문장을 유지하며, 원고 말미에 사실 근거와 확인 대기 항목을 첨부하고 금지 단어를 완전히 배제합니다.
3. 교정본은 검증만 수행하고 새로운 논점을 추가하지 않으며, **사람의 명령 없이는 절대로 자동 외부 발송하지 않습니다**. 테스트 환경에서 `restore.sh`를 한 번 실행하여 의존성 환경이 정상적으로 준비되는지 확인합니다.
