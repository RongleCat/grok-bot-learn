# 제 13 장 사례: X에서 콘텐츠 제작 및 운영하기

스크립트를 직접 작성해 포스팅 API를 고빈도로 호출하면 이상 감지(리스크 제어)에 걸려 계정이 정지되기 쉽고, 며칠 만에 일주일 치 크레딧을 전부 소진하게 됩니다.

- 클라우드 가상 머신 파이프라인을 구축하여, 위챗에서 메시지 한 줄만 보내면 자동으로 주제를 발굴하고 초안을 작성합니다.
- **초안만 생성하고 직접 클릭하여 발행**하는 원칙을 고수하여, 계정 보안을 유지하면서도 단순 반복 작업을 자동화했습니다.

## X 플랫폼 네이티브 기능: 읽기 전용 검색부터 댓글 창 작업 할당까지

2026-10-11의 v0.70.2부터 계정 연동 없이 공개 트윗 검색을 지원합니다. [기록](https://jcng5q8n0f3z.feishu.cn/wiki/ZRFQwIlNgiuJTVkGcJgcrZhsnKd)을 참고하세요.

|외부 트리거|댓글 창 @bot 추출 및 아카이빙|즐겨찾기(별표) 메인 Bot으로 라우팅, 자동 답글 게시 엄격히 금지|

### 진행 방법
1. **대화창**: "지난 3일간 사람들이 XX 주제에 대해 어떻게 평가했는지 검색해 줘"라고 입력하거나, 링크를 붙여넣고 "이 트윗의 핵심 관점과 독자 인터랙션의 논쟁점을 추출해 줘"라고 지시합니다.
2. **댓글 창**: `@bot 提取本帖核心逻辑并存入选题库`라고 답글을 남깁니다. [설명](https://jcng5q8n0f3z.feishu.cn/wiki/HHmpwgN4qi86e0kgBvAc1156nkg)을 참고하세요.

### 검수 기준
- **완전한 추출**: 원본 출처, 게시 시간 및 토론 맥락을 함께 가져옵니다.
- **응답 경계**: 작업 할당 후 **30초 이내에 로그 출력**, 초안만 작성하고 대리 발행하지 않으며, 절대 자동으로 마음에 들어요를 누르거나 트윗을 게시하지 않습니다.

### 스케줄링 설정 단계

1. 5개 템플릿을 본인 계정에 추가합니다.
2. 메인 Bot 하나를 골라 스케줄링 진입점으로 삼습니다.
3. **초기화 프롬프트를 메인 Bot에 직접 전송하여 계정 포지셔닝, 에이전트 라우팅 및 작성 규격을 영구 컨텍스트에 기록합니다.**

프롬프트 내용은 《위챗에서 한마디로 X 운영하기: 나의 5가지 Bot 템플릿 공개》[https://jcng5q8n0f3z.feishu.cn/wiki/DJwawbQxeiUcIjkKbekcVkHRnye](https://jcng5q8n0f3z.feishu.cn/wiki/DJwawbQxeiUcIjkKbekcVkHRnye)에서 인용했습니다.

::: details 스케줄링 설정 단계
```text
我已经添加五个 X 运营专员：情报总监、AI新闻雷达、推文二创、短推成稿、X数据复盘。请保留你的原有功能，作为这套团队的统一入口，完成一次初始化。

1. 先检查能力和连接
确认当前环境能发现 Bot、向 Bot 发任务并接收回执。找到五个专员的实际 Bot ID，核对名称、职责和来源，遇到同名先消歧。保存持久的“角色—名称—ID”路由，让后续聊天和微信入站任务都能读取。缺 Bot 或缺工具时明确告诉我，不凭名称宣称连接成功。

2. 确认我的账号定位
一次只问一个关键问题，了解主题、目标读者、我能提供的价值和不写的话题。也可以分析我授权提供的主页和近期帖子，提出建议，等我确认。把已确认定位和表达偏好持久保存，并同步给相关专员。不要继承模板作者的个人信息。

3. 自动理解需求、安排任务
找选题、热点、爆款拆解交情报总监；AI新闻交AI新闻雷达；原帖回复、引用、二创交推文二创；短推写稿、改稿交短推成稿；发帖数据分析交X数据复盘。

像跟朋友分享：讲清发现、理由和具体用途，允许适量语气词，不堆口号。不编我的亲历、数字、测试结果或涨粉成绩。原帖保留归属，新闻核对来源和日期。默认沿用这些要求，我另有要求时再调整。
你交付前检查事实、来源、定位和可读性。来源和说明放在草稿外，方便我看，也方便复制正文。检查X可发布长度，超出则给短版或说明需要的账号功能。

5. 真正跑一次
给五个专员各派一个小任务，检查接收、完成、回传，再跑“找素材→短推成稿→你检查→返回草稿”。保留可核对的任务记录。数据复盘没有真实数据就报告缺口，不编数字。汇报通过项、失败项和恢复办法，不把发出任务当完成。

6. 根据真实反馈改进
记录已发布内容和表现，提出下一轮调整。日常选题和写作规则的小改动留版本、可回退；账号定位、授权范围、发布权限、定时安排或新增收费服务变更先问我。小样本形成试验建议，不宣称已验证涨粉规律。

默认只起草。发帖、回复、点赞、关注和私信由我另行决定，不自动执行。
```

설정이 완료되면 메인 Bot은 하위 에이전트의 ID를 기억합니다. 평소에 주제를 발굴하고 원고를 작성해 달라는 요구를 전달하면, 메인 Bot이 자동으로 정보 총괄(情报总监)을 스케줄링하여 소재를 수집하고, 이를 단문 트윗 작성(短推成稿) 에이전트에 전달한 뒤 최종적으로 초안을 제출합니다.

### 검수 기준

채팅 창에서 메인 Bot에게 주제 탐색 및 원고 작성 테스트를 한 번 실행하도록 지시했을 때, 합격 결과는 다음 두 가지를 만족해야 합니다.
- **멀티 Agent 간 실제 릴레이 확인**: 메인 Bot과 전문 에이전트의 백그라운드 기록에서 작업 전달, 서브 Bot의 실제 실행 및 결과 반환 과정을 확인할 수 있어야 합니다.
- **초안 품질 및 서식 규격**: 반환된 초안에 기계적인 구호가 포함되지 않아야 하며, 원본 출처 및 설명 텍스트가 본문 하단에 깔끔하게 배치되어 본문과 뒤섞이지 않아야 합니다.

## 위챗 한마디로 운영하기: 모바일 송수신 루프 연동

1. 데스크톱에서 메인 Bot에 설정 요구 사항을 보내 환경 내 리스너 프로그램과 Routine을 점검하도록 합니다.

   프롬프트 내용은 《위챗에서 한마디로 X 운영하기: 나의 5가지 Bot 템플릿 공개》[https://jcng5q8n0f3z.feishu.cn/wiki/DJwawbQxeiUcIjkKbekcVkHRnye](https://jcng5q8n0f3z.feishu.cn/wiki/DJwawbQxeiUcIjkKbekcVkHRnye)에서 인용했습니다:

2. 모바일 위챗에서 순서대로 "나(我) → 설정(设置) → 플러그인(插件)"을 탭하고, "위챗 ClawBot(微信 ClawBot)"을 활성화합니다. 진입점을 찾을 수 없다면 메인 Bot에 현재 위챗 버전을 전달하여 확인 지원을 받으세요.

## 초안만 생성하는 휴먼 게이트 설계와 보안 경계

![초안만 생성하는 휴먼 게이트 설계와 보안 경계](/info/13-x-ops-s4.png)

자동 게시 중 모델의 환각(Hallucination), 잘못된 날짜 기재, 부적절한 답글 등이 발생하면 되돌릴 수 없는 피해를 초래합니다. **파이프라인의 종단에는 반드시 안전을 위한 '휴먼 게이트'를 두고, 발행(포스팅), 마음에 들어요, 팔로우, 쪽지(DM), 삭제의 5가지 동작을 완전히 차단하여 모델이 오직 초안만 작성하도록 해야 합니다.**

::: details 초안만 생성하는 휴먼 게이트 설계와 보안 경계
```text
[微信一句话 / 定时触发] 
       │
       ▼
[主 Bot 调度中心] ───► [情报总监 / AI新闻雷达 抓取素材]
       │
       ▼
[推文二创 / 短推成稿 编写草稿]
       │
       ▼
[主 Bot 事实与长度校验]
       │
       ▼
[推送到手机微信 / 客户端对话框] ───► (停住：系统不具备自动发帖权限)
       │
       ▼
[人工审阅：修改、定夺] ───► [人工手动复制到 X 发布]
```
:::

### 2단계 이중 보호 설정

1. **프롬프트 강제 명령**: 메인 Bot 및 전문 에이전트 프롬프트 끝에 다음과 같이 고정 명시합니다:
   "기본적으로 초안만 작성합니다. 포스팅, 답글, 마음에 들어요, 팔로우, 쪽지는 사용자가 별도로 결정하며 자동 실행하지 않습니다. 출처와 설명 텍스트는 사람이 읽고 본문만 원클릭으로 복사할 수 있도록 반드시 초안 바깥에 배치합니다."
2. **시스템 레벨 차단**: Grok Bot의 Settings → Custom Rules(또는 Auto-review)에서 **`send`, `post`, `buy`, `transfer`, `delete`, `permissions`가 포함된 작업을 모두 "Ask first"로 체크**합니다. 사용자의 명시적 클릭 승인이 없으면 백엔드에서 절대 실행되지 않습니다.

설정 규격은 《4.3 트리거 및 자동화: 스케줄링, Webhook, X에서 작업 할당》[https://jcng5q8n0f3z.feishu.cn/wiki/HHmpwgN4qi86e0kgBvAc1156nkg](https://jcng5q8n0f3z.feishu.cn/wiki/HHmpwgN4qi86e0kgBvAc1156nkg)을 참고하세요.

### 검수 기준

실제 테스트 시 "이 초안을 내 X 프로필에 바로 올려줘"라고 지시했을 때, 합격하려면 다음 두 가지를 만족해야 합니다:
- **차단 활성화**: Bot이 실행을 명확히 거부하거나, 백엔드에서 Ask first 승인 차단 카드가 팝업되어 호출을 중단해야 합니다.
- **서식 규격 준수**: 초안 본문과 참고 링크가 분리되어 있고, 길이가 X 플랫폼의 글자 수 제한을 엄격히 준수해야 합니다.

1. 여러 Bot을 동일한 Team Chat에 추가하면 통합 Routine이 저장되지 않으므로(SCOTTY BEAM 실제 테스트 확인), **반드시 개별 1:1 대화 세션으로 전환하여 따로 설정해야 합니다**.

3. 시스템 설정에서 로컬 시간대가 Asia/Shanghai로 되어 있는지 확인하여 베이징 시간 아침 7시 30분이 한밤중(새벽)에 실행되는 일을 방지하세요.
4. Bot 크레딧은 Grok, Cursor와 공유되며, 5분 단위 폴링은 업데이트가 없더라도 전체 컨텍스트를 읽어옵니다. **반드시 2단계 점검이나 증분 웨이크업(Wake on Done) 방식으로 전환**하여 1차 필터링을 수행해야 합니다. 29개의 Bot을 운영 중인 melvindvivas 역시 성과가 낮은 루틴을 주기적으로 정리할 것을 권장합니다.

### 위챗 및 Webhook 연결 트러블슈팅
1. 위챗 QR 코드 스캔 후 응답이 없는 원인은 대부분 리스너 중단이나 킵얼라이브 Routine의 일시정지 때문이므로, **계정 연동을 반복해서 재스캔하지 마세요**. Hardy Chen의 노하우에 따르면 데스크톱에서 점검 명령을 보내 프로세스와 대기열을 확인하고, 새로운 테스트 메시지를 보내 다시 연결을 활성화하는 것이 좋습니다.

### 플랫폼 인터랙션 제한 및 호스트 머신 환경
1. 댓글 창 작업 할당은 순수 동영상 형식은 지원하지 않으며, @grok과 @bot을 동시에 멘션하면 응답하지 않습니다. 악의적인 프롬프트 인젝션을 방지하기 위해 **댓글 창 작업 할당에는 절대 외부 포스팅 권한을 부여하지 마세요**.
2. 가상 머신 유지보수 시 임시 경로가 리셋되므로, **스크립트, 문서 및 백업 데이터는 반드시 `/home/box`에 일원화하여 저장**하고 자체 복구 스크립트를 준비해 두어야 합니다.

## 작업 완료 후 검수 방법

1. 메인 Bot에 트윗에서 좋아요 상위 3개를 수집하도록 지시하여 작성자 ID, 관점 및 작성 시간을 확인하고 오류가 없는지 검증합니다.
2. 명령을 내려 기록을 확인하고, **5명의 에이전트가 순차적으로 릴레이하여 원고를 완성했는지 확인**하며 메인 Bot의 단독 대리 작성을 엄격히 방지합니다.
3. 위챗 ClawBot에 "초보자 관점에서 거대 언어 모델(LLM) 툴에 관한 단문 트윗 하나 써줘"라고 전송하고 2분 내에 초안이 회신되는지 확인합니다.
4. "방금 생성된 초안을 내 X 계정에 바로 발행해 줘"라고 보냈을 때, **반드시 Ask first 확인 창이 떠야 하며** 승인 없이는 외부에 게시되지 않아야 합니다.
5. Routine 실행 시간을 일치시킵니다. 빈 파일을 입력했을 때 데이터 분석 에이전트가 누락 사실을 있는 그대로 보고하고 억지로 지어내지 않는지 확인합니다.
