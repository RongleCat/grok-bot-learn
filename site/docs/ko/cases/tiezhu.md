# 철주의 실전 장문 글과 트윗

Grok Bot을 따라 할 때 가장 빠지기 쉬운 **세 가지 함정**입니다.
1. 리소스 소모가 큰 작업을 전부 메인 대화에 몰아넣어, 2~3일 만에 일주일 치 크레딧을 전부 소진한다.
2. 클라우드 PC가 한 번 재설정되면 환경과 도구를 모두 잃어버린다.
3. 여러 Bot이 단체방에 들어가 루프를 돌며 서로를 깨워, 순식간에 사용량을 탕진한다.

여기에는 철주(@cgnot996)의 **9편의 실전 장문 글과 4편의 시스템 트윗 모음**이 수록되어 있으며, 구독 크레딧과 외부 협업, 재해 예방 및 백업, 아키텍처 선정의 네 가지 주제를 다룹니다. 각 글마다 직접 작성한 요약 카드와 바로가기 링크가 첨부되어 있어 프롬프트, 스크립트, 트래픽 분산 방안을 바로 가져다 쓸 수 있습니다.

## 구독 플랜 및 컴퓨팅 크레딧 알뜰 관리

### 크레딧 메커니즘과 트래픽 분산 전략

공식 과금은 주간 공유 풀 방식으로 계산됩니다. **매 턴마다 전체 대화 기록을 처음부터 다시 읽기 때문에**, 메인 대화창에 긴 문서나 긴 코드를 직접 붙여넣으면 컨텍스트가 급증하여 이후 수정할 때마다 중복으로 비용을 지불하게 됩니다.

**메인 대화창에는 핵심 결론과 파일 경로만 남기고**, 긴 자료는 작업 디렉터리에 저장하며 무거운 작업은 백그라운드로 분산합니다:
- 코드 작성은 명령줄 도구인 Grok Build에 맡깁니다.
- 일상적인 모니터링은 시스템 하위 레벨의 예약 스크립트에 맡깁니다.
- 이미지 및 음성·영상 분석은 명령줄에서 순수 텍스트 요약을 추출한 후 반환합니다.

일상적인 점검 시 두 가지 지표를 확인합니다:
- 매주 갱신일 전까지 20% 이상의 사용량을 남겨둡니다.
- **종량 과금을 비활성화**하여 백그라운드 무한 루프와 폴링 공회전을 방지합니다.

| 등급 | 월 요금 | 권장 사항 및 크레딧 |
| :--- | :--- | :--- |
| Plus | 월 8달러 | Bot 미포함, 가벼운 개발에만 적합 |
| Premium | 월 30달러 | Bot 시작 등급, 주간 크레딧 4배 |
| Super | 월 100달러 | 다중 Agent 고빈도 오케스트레이션, 주간 크레딧 15배 |
| Ultra | 월 200달러 | 전문 팀에 적합, 주간 크레딧 50배 |

메인 Bot에게 다음 규칙을 전송하면 바로 적용됩니다:

```text
以后长资料、排查日志和中间结果都存成 /workspace/ 下的文件，回我时只给结论和文件路径，不要把原文贴回聊天。给你自己建一个 notes.md 记录角色、正在做的事和做过的决定，每做完一段就更新。面对批量处理或长流程任务，先使用 1 到 2 个最小样本进行单步验证，完成单步后必须暂停等待我确认。
```

### 통합 X 구독 분석: 신규 사용자는 어떻게 선택하고, 기존 구독은 전환해야 할까? 한 편으로 정리

새로운 요금제는 Plus, Premium, Super, Ultra의 4개 등급으로 나뉩니다.

- 등급 선택: Grok Bot과 클라우드 자동화를 사용하려면 **월 30달러의 Premium 등급으로 시작**하는 것이 좋으며, 일반 사용자는 월 단위로 결제하면 됩니다.
- 주의 사항: 웹에서의 변경 작업은 단방향으로 되돌릴 수 없으며, **새 구독으로 전환하면 이전 플랜과의 연결이 영구 해제**됩니다. 비용이 급증하지 않도록 진행 전에 서드파티 모델 호출 빈도를 반드시 확인하세요.

초보자가 며칠 만에 크레딧을 전부 소진하지 않으려면 **사용량 한도가 다른 무엇보다 우선**이라는 점을 기억해야 합니다.

1. 개통 시 **30달러 구독**을 선택하고 이름을 바로 중국어로 지으면, Bot은 기본적으로 중국어로 답변합니다.
2. 추론 모델은 **Grok 4.5**로 고정 선택합니다.
3. 다중 Bot 협업은 점대점 통신만 사용하고, 상주 단체방은 절대 피하여 모든 메시지를 여러 Bot이 반복해서 읽어 크레딧이 폭증하는 것을 방지합니다.

절대 건드리지 말아야 할 3대 사용량 블랙홀:
- 비디오 생성
- 실질적인 결과물이 없는 고빈도 타이머
- 다중 Bot 단체방 대화

3. 실질적인 변동이 감지되었을 때만 **Webhook을 통해 Bot을 깨워**, 일상적인 공회전 소모를 0으로 줄입니다.

## 자동 입고 및 외부 협업 네트워크

### 자동화 파이프라인 및 협업 구성

Webhook을 연동하면 Grok Bot은 **24시간 365일 상시 가동되는 자동화 노드**가 됩니다.

1. Bot에서 예약 작업을 생성하고 트리거로 'Webhook이 트리거될 때'를 선택한 뒤, 저장하여 엔드포인트 URL과 Bearer 토큰을 가져옵니다.
2. 스마트폰 단축어에서 'URL 콘텐츠 가져오기'를 설정하고, POST 방식으로 JSON 텍스트나 링크를 전송합니다.
3. WeChat처럼 시스템 공유 패널이 없는 앱은 클립보드를 읽도록 하고, 대용량 첨부파일이나 여러 장의 이미지는 임시 웹하드에 올려 공인 링크로 변환하여 Bot이 클라우드에서 다운로드 및 압축 해제하도록 합니다.
4. Feishu는 장기 연결을 사용하여 공인 IP와 자체 서버 없이도 연동할 수 있으며, 초인종 트리거를 구성하여 작업을 타깃팅하여 할당합니다.

**검수 기준**:
- 스마트폰에서 전송 후 기다릴 필요 없이 즉시 종료.
- Bot이 클라우드에서 비동기로 수집, 프레임 추출 및 전사, 데이터베이스 입고 후 등록 확인서 발급.
- 단체방에서는 정확히 멘션되거나 전체 멘션일 때만 응답.

다음 프롬프트를 전송하면 **수신 엔드포인트를 자동 생성**할 수 있습니다:

```text
帮我创建一个 Webhook 触发的例行任务。快捷指令会用 POST 请求发来一个 JSON，里面包含一个字段 info。info 可能是我输入的文字，也可能是一个文件下载链接，比如微信聊天记录压缩包、截图、录音。收到后：如果是链接就先下载文件再读取，压缩包先解压；然后整理出要点，收录进知识库，最后给我一份回执，写清楚收录了什么、存在哪里。
```

### 재해 복구 메커니즘 및 자산 분류

모든 Bot은 동일한 Linux 베이스(Xeon 8코어 8스레드, 16GB 메모리, 128GB 디스크, 작성자 언급 기준이며 미검증)를 공유합니다. **서로 다른 Bot 세션은 독립적이지만 기본 파일 시스템은 연결**되어 있으며, 공식적인 기본 내보내기 기능은 제공되지 않습니다.

|상황|유지 항목|손실 및 영향|
|---|---|---|
|시스템 업데이트|작업 디렉터리 및 일부 자격 증명|상주 프로세스, 예약 작업, 전역 패키지 삭제|
|전체 머신 재설정|유지 항목 없음|시스템 디스크 포맷, 비영구 데이터 전체 유실|

수동 백업은 비현실적이므로 **반드시 재구축 로직을 코드화**해야 합니다. 재해 발생 후 새 환경에서 마스터 진입 스크립트를 실행하고, 헬스 체크를 통과하여 정상 가동을 복구합니다.

|자산|경로 및 파일|복구 전략 및 주의 사항|
|---|---|---|
|기억 설정|비공개 Git: agent-spec.md, profile.md, MEMORY.md|목록에 따라 새 Bot에 로드, 복원도 약 80%(작성자 언급 기준, 미검증)|
|상주 서비스|비공개 Git vm-services/: REGISTRY.md, registry.json, 소스 코드|restore-*.sh를 통한 멱등적 재설치 및 헬스 체크 통과|
|액세스 자격 증명|로컬 ~/.agents/secrets/: .env (chmod 600)|**Git이나 로그 포함 절대 금지**, 재해 후 총괄 장부에 따라 수동 입력|

독립 운영 Bot에 다음 프롬프트를 부여하여 서비스 총괄 장부와 복구 스크립트를 관리하게 합니다:

```text
你是「虚拟机服务管家」，负责维护这台机器部署的所有第三方服务。你维护一份登记总账（REGISTRY.md 与 registry.json）、每个服务的独立恢复脚本（restore/restore-<服务>.sh，必须幂等可重复运行）、总入口 restore/restore-all.sh，以及一份排除日志和密钥的自写源码备份 service-src/。总账记录服务 ID、用途、安装方式、启停命令、健康检查命令和密钥存放路径。仓库严禁存入明文密钥。收到恢复指令后，按依赖顺序跑脚本并逐项交出健康检查验收清单。
```

### 매트릭스 업무 분담 및 모델 선정 평가

플랫폼 선정 시 철주의 '브랜드 완제품'과 'DIY 조립 PC' 비교를 참고할 수 있습니다:
