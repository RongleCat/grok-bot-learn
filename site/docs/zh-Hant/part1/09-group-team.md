# 第 9 章 群聊與團隊 Bot：從一個 Bot 到一組 Bot

別把活全塞給一個 Bot，也**別拉多個 Bot 進群**。多 Bot 容易互相接話、迴圈喚醒並耗盡整週額度，個人 Bot 進 Slack 也無法協同。

1. 用**統籌 Bot 作單一入口**，靠本地與雲電腦共享檔案交接任務。
2. 需要全員共享經驗時，釋出團隊 Bot。
3. 依 2026-10-12 生效的 The X Subscription 統一訂閱機制控好用量。


![群聊與團隊 Bot：從一個 Bot 到一組 Bot](/info/09-group-team.png)

## 群聊機制與互動規則：多 Bot 如何在同一對話中協作

![群聊機制與互動規則：多 Bot 如何在同一對話中協作](/info/09-group-team-s1.png)

群聊可拉多 Bot，但**團隊 Bot 無法與本地 Bot 放同一群**。

發訊息預設全員回，指定用 `@Bot名称`。複雜任務中 Bot 的私聊交接不同步到群裡。

怕私聊太散，直接立規矩：
- **臨時約束**：群裡發指令。
```text
就在群里回复，这件事不要私信我。
```
- **長期約束**：讓它記入長期記憶。
```text
记住：在群组聊天中，要在群里回复。
```

系統沒有一鍵禁互聊開關，防連環呼叫浪費額度有這幾招：
1. **臨時禁令**：群裡發指令。
```text
不要给其他 Bot 发消息，先问我。
```
2. **長期規則**：要求未經確認嚴禁私下喚醒其他 Bot。
3. **緊急叫停**：停不下來時，**進它的專屬私聊叫停**。
4. **輔助靜音**：關通知，或側邊欄右鍵 Hide from sidebar。

管理與限制：
- **改名與換方向**：右鍵 Rename chat（手機端點群名 Edit name）；換方向直接群裡說明。
- **功能限制**：**群聊完全不支援語音**（只能單聊），無法對單個 Bot 開關通知。

驗收標準：
- 成員在 3 個以內，職責無重疊。
- 提問用 `@` 精確喚起。
- 輸出集中在群內，無多餘私聊。
- 未出現 Bot 間連環喚醒。

## Bot 間通訊與 Slack 許可權路由

**Bot 只有在代表具體某個人時，才能跨機器人發訊息。** 個人 Bot 在公開 Thread 裡沒有代表權，無法喚醒其他 Bot；團隊 Bot 在被 @ 時承接提問者身份，把任務轉交給他自己的專屬 Bot，再把結果發回同個 Thread。

| Bot 型別 | 提問位置 | 跨 Bot 許可權 | 代表誰 | 回覆位置 |
| --- | --- | --- | --- | --- |
| 個人 Bot | 應用內私聊 / Slack 私信 | 能發 | 個人 | 應用內聊天視窗（非 Slack） |
| 個人 Bot | Slack 公開 Thread | 不能發（提示無法執行） | 無人 | 原訊息串 |
| 團隊 Bot | Slack 頻道 / 私信 | 能發（轉給提問者專屬 Bot） | 提問成員 | 發回同個 Slack 訊息串 |

[詳細規則可見官方文件](https://cursor.com/cn/help/grok-bot/group-chats)。

### 團隊 Bot 接入與排坑

1. 團隊 Bot 釋出後，所有者點選聊天頂部 Bot 名稱，在 Bring to your team's Slack 點選 Connect（未釋出時顯示灰色的 Connect after publishing）。
2. 介面若提示 Awaiting admin approval，說明開啟了安全管控，聯絡管理員審批；狀態變為 Connected 即繫結成功。
3. **團隊成員使用前須在客戶端 Settings > General > Team Bots 點選 Link 繫結賬號。** 未關聯就直接在 Slack 發訊息，Bot 只會回覆繫結提示。

### 驗收標準

- Slack 頻道內的多 Bot 協作由團隊 Bot 統一排程。
- 團隊成員完成賬號 Link。
- **任務在 Thread 內部閉環，沒有脫節或許可權報錯。**

## 團隊 Bot 全流程配置：建立、釋出與跨人共享

團隊 Bot 由成員建立並全員共享，私聊相互隔離。**它只在雲端執行，不能綁在本地**。[參考官方指南](https://cursor.com/cn/help/grok-bot/shared-bots.md)。

### 建立與轉為團隊 Bot

1. 側邊欄點 New chat（+），選 Create new Team Bot。
2. 交代需求，配置公開外掛、Secrets 與檔案。
3. 改名並填寫 About。**若保留預設名且描述為空，其他成員在列表裡搜不到該 Bot**。
4. 點選卡片上的 Publish to Team。

已有個人 Bot 可在介面點 Share > 釋出到團隊克隆獨立副本，生成 Slack 賬號，按需遷移機密、記憶與例程（Routines）。

### 查詢與呼叫

- **搜尋與列表**：在 New chat（+）選團隊 Bot 瀏覽，或在搜尋框輸入名稱前 3 個字元。
- **連結直達**：右鍵選 Copy link。全員共用底座與記憶，非克隆模板。
- **批次派發**：管理員在儀表盤 Manage Team Bots 勾選 Auto-add。**被勾選成員側邊欄自動置頂且無法隱藏**。

### 許可權與執行機制

呼叫個人賬戶時觸發 Allow 授權（Allow once 僅本次，Always allow 始終允許，Skip 跳過）。重置進 Settings > General > Team Bots 點 Clear。

**審批卡片只在所有者私聊彈出**。群聊與 Slack 中 Bot 只能自主執行。

| 場景 | 執行環境 |
|---|---|
| 私聊 | 預設個人云電腦（隱私嚴則分隔離機） |
| Slack / 群聊 | 專屬共享虛擬機器 |

### 驗收標準

- 名稱與崗位描述清晰。
- 所有者機密隔離完好。
- 3 字元檢索或連結可喚起。
- 跨人呼叫觸發 Allow 授權，無越權隱患。

## 1+N 主 Bot 派活模式：單入口與履約章程

![1+N 主 Bot 派活模式：單入口與履約章程](/info/09-group-team-s4.png)

別讓所有 Bot 都對接使用者，免得你在視窗間傳話，群聊也白耗 Token。

**推薦採用 1+N 模式，你只跟統籌主 Bot 溝通**，由它拆解、派活與彙總，詳見 [《從一個 Bot 到一整個組織，Grok Bot 的進階用法分享：本地電腦、AI 分工和知識庫怎麼接起來》](https://jcng5q8n0f3z.feishu.cn/wiki/DdqFwLmn7i8cV1kYtDwc840enLg)。

### 主 Bot 六行章程與專職邊界

**主 Bot 只負責路由與監督，絕不能親自寫長程式碼或長文。** 個人 Bot 把六行章程發在對話裡並讓它記住；共享 Bot 寫入詳情 About 的 Description。無事靜默、有事派活，超長彙報存為檔案。

團隊組織規範參考 [《4.2 團隊編排：章程、崗位與放權》](https://jcng5q8n0f3z.feishu.cn/wiki/POTrwwThoiQxIakFDIDcUcKjnmh)。

```text
Own: 负责需求的统一拆解、分派、汇总与五行简报汇报。
Sources: 人工下发的指令、项目看板文件。
Output: 纯文本状态摘要，超出五行时输出为指定文件路径。
Approval: 任何对外通信、采购、删除操作必须暂停等待确认。
Failure: 下游专职 Bot 报错时如实上报，不使用过期数据假装完成。
Never: 永远不直接编写业务代码，不擅自修改生产配置。
```

專職 Bot 須把負向邊界發給它記住（共享 Bot 寫在詳情 About）：
- 廣告投手 Bot：分析資料並出具待批清單，**絕不碰後臺與出價，不調預算，也不加詞或建組**。
- 文案創作 Bot：只出草稿檔案，嚴禁調介面直接上線公開內容。
- 競品調研 Bot：前臺只看不動，嚴禁下單加購，也不留評或向賣家提問，防反爬封禁。

投放專員直接套用提示詞模板。

```text
Own: 负责广告投放数据诊断与策略输出。
Sources: 运营分析文件 /workspace/project/ad_data.json。
Output: 待批操作清单 /workspace/project/pending_actions.md，列出出价建议与预期影响。
Approval: 绝不直接写入广告后台，不修改出价，不修改预算，不加否定词，所有操作必须等待人工审批。
Failure: 数据缺失时明确标注缺失字段，不推测填充。
Never: 绝不执行任何后台写入与线上提交操作。
```

### 待批清單與驗收

**專職 Bot 只輸出結構化待批清單，把決定權留給人工。** 比如主 Bot 彙總出 5 條廣告出價衝突項，你回覆“確認建議”或批註修改後才觸發下一步。

系統達標後按三項標準驗收：

| 驗收項 | 達標標準 |
| --- | --- |
| 互動與主 Bot | 單入口清晰執行；主 Bot 不寫長程式碼、不寫長文章 |
| 專職 Bot | 各司其職，只產出結構化清單 |
| 高風險動作 | 不可逆操作均有明確人工確認卡點 |

## 交接檔案約定：以共享檔案系統替代對話歷史

![交接檔案約定：以共享檔案系統替代對話歷史](/info/09-group-team-s5.png)

別讓 Bot A 在聊天窗貼結果再給 Bot B 讀。**視窗互動會快速撐爆上下文且容易丟失歷史**，各 Bot 對話在底層邏輯隔離，根本沒法互相檢索。

| 維度 | 特徵與包含內容 |
| :--- | :--- |
| **物理共享層** | 同賬號下所有 Bot 共用虛擬機器、`/workspace` 目錄、聯結器與公共 Skill 庫。 |
| **邏輯隔離層** | 對話歷史互不可見，Bot A 無法調取 Bot B 與使用者的私人對話。 |

物理磁碟既然共享，傳遞任務就靠本地結構化檔案，對話方塊只用來同步狀態與路徑。

### 檔案交接流水線標準

標準交接包含落盤、傳路徑，再到讀取與歸檔。

::: details 檔案交接流水線標準
```
[用户指令] ──> (主调度 Bot)
                   │
         1. 派发任务 (指定输出路径)
                   │
                   ▼
             [专职 Bot A] ──> 写入 /workspace/proj/data.json
                   │
         2. 交付：仅返回文件绝对路径
                   │
                   ▼
             (主调度 Bot)
                   │
         3. 调度下发 (附带输入路径)
                   │
                   ▼
             [专职 Bot B] ──> 读取 data.json ──> 写入 output.md
                   │
         4. 汇总简报至用户
```
:::

1. **任務派發**：主 Bot 明確指定交付絕對路徑，如 `/workspace/project-alpha/data.json`。
2. **資料落盤**：專職 Bot A 跑完清洗寫入檔案，在對話方塊只回一句話通知儲存路徑。
3. **路徑傳遞與讀取**：主 Bot 喚醒 Bot B 並傳遞路徑，Bot B 讀盤分析後把結論寫入 `/workspace/project-alpha/report.md`。
4. **交付呈現**：主 Bot 提煉摘要，附上本地或雲文件連結供審查。

推文畫像流水線也是這套模式，整理員抓取存入 `tweets.md`，分析師讀檔案提煉標籤寫入 `profile.md`，設計師輸出 `design.md`，工程師據此寫程式碼並給預覽截圖。

實操參考 [《4.2 團隊編排：章程、崗位與放權》](https://jcng5q8n0f3z.feishu.cn/wiki/POTrwwThoiQxIakFDIDcUcKjnmh)。

### 接入飛書雲文件實現可追溯交付

需要團隊協作或批註時，給虛擬機器配飛書 CLI 把 Markdown 發為雲文件。它自帶獨立連結方便分發，支援逐段批註，也能**保障企業資料安全**。

工作流達標包含這幾項要求：
- 鏈路中每個 Bot 都能獨立讀寫 `/workspace` 下的固定檔案。
- **對話方塊只傳輸狀態提示與檔案絕對路徑**。
- 出現異常時，檢查對應磁碟檔案即可復現定位。

## 用量影響與額度控制：The X Subscription 下的多 Bot 治理

2026-10-12 起 Grok Bot 納入 The X Subscription，**統一按周共享額度**。

| 檔位 | 價格 |
| :--- | :--- |
| Premium | $30/月 |
| Super | $100/月 |
| Ultra | $200/月 |

### 規則與防燒策略

1. **回覆與握手訊息都計費**。私聊團隊 Bot 扣自己額度，群聊扣發起方的，周初耗盡整週停擺。
2. 群聊 Bot 壓在 3 個以內，**堅決用 1+N 序列替代自由群聊**。
3. 清洗等輕任務用基礎模型，核心推導才用頂級推理模型。
4. 沒跑穩前**別設半小時或每小時的定時例程**，防夜間重試上百次耗盡額度。

### 驗收標準

- **周額度平穩消耗**，沒有夜間死迴圈。
- 模型分層分明，費用分攤到具體提問者。

## 實戰案例：企業專家經驗固化與跨境團隊 1+N 落地

### SpaceXAI 團隊 Bot
n2parko 團隊**讓業務專家親自配 Bot 規則**，做成全員共享助手。
1. 抓高頻節點：資料團隊做 Databot 查資料湖，避免重複打擾專家。
2. 擴充崗位：配置 10x Engineer、Marketing 及查 Salesforce 的 Sales Assistant（輔助 SDR/AE）。
3. 記憶分層：全域性沉澱通用規則且保留個人偏好，詳見 [《Meet your Team Bots｜n2parko》](https://jcng5q8n0f3z.feishu.cn/wiki/KS9Cwan52idy1xkLbnTcSC3xnxb)。

### 跨境 1+12 編排
Zach（@1999Zach22）以 1 船長帶 12 崗位，**自動化閉環必須設待批清單**，嚴控寫許可權。
1. 本地部署：專用 Skill 在本地調順後，統一部署到雲電腦。
2. 負向邊界：投手嚴禁操作後臺僅提建議；調研買家號嚴禁加購、提問和留評。
3. 單入口互動：每天彙總簡報，遇衝突出 5 處衝突待批單，確認後執行。
4. 報表沉澱：用飛書 CLI 把報表落成雲文件持久連結，詳見 [《從一個 Bot 到一整個組織，Grok Bot 的進階用法分享：本地電腦、AI 分工和知識庫怎麼接起來》](https://jcng5q8n0f3z.feishu.cn/wiki/DdqFwLmn7i8cV1kYtDwc840enLg)。

## 容易踩的坑

1. 用三個詞界定不了獨特技能的，**收攏為主 Bot 的 Skill**。別一口氣建七八個職能模糊的助手，免得整天在視窗間切換。
2. 同賬號所有 Bot 共享雲電腦虛擬機器、本地路徑和瀏覽器登入態，**共享 Bot 切勿存個人私有憑證**。
3. 群指令別太寬泛。Bot 互相客套確認會狂扣額度，**可能半天耗完一週呼叫量**。
4. 別留著 `New team bot` 預設名且不寫描述就釋出，**其他成員在搜尋列表完全看不到它**。
5. 團隊 Bot 和本地 Bot 進不了同個群，群裡也沒語音入口。**有這類需求必須切到單 Bot 私聊**。
6. 寫上千行程式碼會填滿上下文並失去全域性視野。**主 Bot 必須只負責排程與督辦**，落地動作交由專職 Bot 執行。

## 做完怎麼驗收

1. **主 Bot 路由**：發跨模組業務指令，主 Bot 須**準確複述目標並列出專職 Bot 路徑**，無外部狀態變化時保持靜默。
2. **群聊防互發**：下令要求“不要給其他 Bot 發訊息”，**Bot 只在群內回覆**，絕不私聊視窗彈訊息，也不私下互喚。
3. **檢索與授權**：換成員 Cursor 賬號在 **New chat** > **團隊 Bot** 搜**前 3 個字元**；調外掛必彈出含 **Allow once**、**Always allow** 與 **Skip** 的授權卡片。
4. **檔案交接**：A 將中間檔案存入 `/workspace`，**Bot B 只憑絕對路徑獨立跑完**，全程無需人工複製。
5. **人閘攔截**：下達釋出、後臺修改或刪除指令，**Bot 必須中止執行並輸出待批清單**，未經人工審批絕不線上寫入。
