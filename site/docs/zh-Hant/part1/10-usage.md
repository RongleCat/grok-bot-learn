# 第 10 章 額度與成本：讓一週用量撐滿一週

週二額度用盡、被扣上百美元，常因算力空轉。**Bot 每次喚醒都重讀完整歷史**，幾小時就脹到數十萬 token。

想穩撐一週，做好這三項。
1. 關掉後臺按需付費。
2. 減少高頻輪詢與多 Bot 互聊。
3. 收緊會話，少往聊天框塞大檔案。

## Grok Bot 的額度扣費原理是什麼？ {#扣費原理-額度是怎麼被花掉的}

**Grok Bot 按呼叫 token 計費，核心機制是單會長對話，每次回覆或喚醒都會全量重讀歷史上下文，總消耗等於喚醒次數乘每次重讀的上下文長度。**

![扣費原理：額度是怎麼被花掉的](/info/10-usage-s1.png)

Grok Bot 按模型實際呼叫的 token 計費。**它的核心機制是單會長對話，每次回覆或定時喚醒，都會把全部歷史重新讀取一遍。**

```
每周总消耗 = Bot 唤醒的总次数 × 每次唤醒时重读的上下文长度
```

會話堆積大量日誌或網頁時，單次重讀可達數十萬 token，回一句也是全量計算。

## 省額度四步工作流：從止損到分流

![省額度四步工作流：從止損到分流](/info/10-usage-s3.png)

### 鎖定計費與安全底線
1. 進 Settings > Usage & Billing 核對套餐（Premium $30/月 或 Super $100/月）、用量與倒計時；卡住點 Stop 強制結束。
2. **除錯時關 Additional Usage / On-demand**；若開，去 cursor.com/dashboard > 支出 > Monthly Limit 設月限額（$10-$20）。
3. 進 Settings > General > Auto-review，**把 send、post、buy、transfer、delete、permissions 設為 Ask first 人工批准**。

### 規範會話與互動
- **單任務單會話**，做完立即歸檔。
- 日誌長文存進 `/workspace/`，只回結論和路徑，嚴禁貼回。
- X 搜尋限每分 30 次、每天 1000 次（不扣周額度），**約束 Bot「提取核心事實，以 3 到 5 條要點輸出」**。
- 會話臃腫時用 Duplicate 重置，先讓舊 Bot 寫 10 行內總結，複製發給新 Bot 接手，隱藏舊 Bot。

### 能力路由與分流
- 主 Bot 只負責拆解、派發與彙總，不寫長程式碼或轉大檔案。
- **寫程式碼走 Cursor 雲端 Agent**（走 Cursor 額度不扣周額度），或在虛擬機器無頭跑 Grok Build CLI / Codex CLI。
- 截圖與音影片由雲電腦命令列處理，或用免費模型轉文字再餵給 Bot。

### 定時任務改造
1. Details > Routines 裡，**暫停或刪除過去一周天天報「沒有變化」的例程**。
2. 換 Linux 指令碼低成本輪詢，有變動再發 Webhook 喚醒 Bot。
3. **保留例程寫入靜默指令**：「檢查後若無變化，直接結束任務，嚴禁輸出任何文字」。

## 例程與輪詢深度最佳化：告別無效空轉

例程是隱蔽的額度黑洞，高頻輪詢**一天就能用掉整週用量**。

### 頻率收斂與執行視窗控制

客戶端先核對 Bot 的 Timezone 是否與本地一致。不同排程設定消耗如下：

| 排程設定 | 每週執行次數 | 適用場景 |
| :--- | :--- | :--- |
| 每 15 分鐘一次（全天候） | 672 次 | 極易在 1 到 2 天耗盡額度，極少需要 |
| 每小時一次（全天候） | 168 次 | 關鍵基礎設施故障監控 |
| 工作日 9:00 至 17:00 每小時一次 | 45 次 | 看板跟蹤、工單處理與郵件分揀 |
| 每個工作日 3 次 | 15 次 | 每日收件箱早中晚初篩、進展跟進 |
| 每週 1 次 | 1 次 | 行業週報、技術動態總結與文件歸檔 |

限定工作時間可用標準 cron 格式：

```text
CRON_TZ=Asia/Shanghai 0 9-17 * * 1-5
```

**這行規則把喚醒量降低了 93%**。在上海時區工作日 9:00 至 17:00 整點執行，一週僅觸發 45 次。

### 指向技能並嚴格執行沉默規則

例程提示詞只指向技能，不展開細節：
- 斜槓命令指定具體技能名與檢查物件
- 給出判定閾值、停止條件與單次重試限制
- **無變化時保持完全靜默，不發任何訊息**

純靜默容易掩蓋中途故障。搭配方案參考[Cursor 官方指南：例程](https://cursor.com/cn/help/grok-bot/routines)：高頻例程保持靜默；低頻例程每天 18:00 發單行心跳日誌，確認過去一天正常執行。

### 雙角色分離：Linux cron 指令碼巡檢加 Webhook 喚醒

Bot 休眠時底層 Linux 雲電腦還在執行，**別讓大模型去幹機械比對**。
- 檢查角色：系統自帶 cron 排程 Python 或 Shell 指令碼比對，耗時幾秒，消耗額度為零。
- 判斷角色：指令碼檢測到變動再發 Webhook 喚醒 Bot 進行邏輯判斷與報告。

Webhook 喚醒步驟與驗收標準：
1. 在例程 Webhook 區域獲取 `POST to` 地址與 `key`。
2. 向該 URL 傳送帶有 `Authorization: Bearer <key>` 頭的 POST 請求。
3. 檢查響應狀態碼，返回 200 即代表喚醒成功。

### 實戰案例與避坑

- **鐵柱改造營銷總監 Bot 的 6 條例程**：4 條交付類例程保留不變；2 條純等回覆與審 PR 的空轉任務換成系統 cron 指令碼加 Webhook。指令碼工作日白天每半小時檢查一次，有新變動才喚醒。

  **改造耗時約 23 分鐘，每週減少 8 到 10 次多餘喚醒**，新動態發現速度提到了半小時內。

## 群聊與多 Bot 控制：杜絕互相喚醒

**千萬別把多個 Bot 拉進同一個群聊。** 新訊息會全員廣播，每個 Bot 都會重讀全量歷史並回復。鐵柱自述 4 個 Bot 互聊迅速吃掉了 25% 周配額（未核）。

多 Bot 協作要堅持**中心輻射、禁止橫向串聯**。

- 唯一主導：只保留一個主導 Bot 作為互動入口。
- 單向派活：主導 Bot 啟動 Subagents 或 A2A 單點交接，子智慧體跑完自動退出，不在群裡接話。
- 成果落盤：上游把資料寫入 `/workspace/` 下的檔案，下游直接讀取，不在聊天框推敲。
- 清理閒置：確認無掛載例程後及時刪除閒置 Bot，防止被誤喚醒。

## Grok Bot 如何做用量審計與耗盡應急？ {#用量審計與應急機制-守住每週節奏}

**每週重置前一天花 15 分鐘排查例程記錄與扣費，若額度耗盡前端鎖定，底層 Linux 雲電腦不會銷燬，可直接開啟終端接管程式碼並手動提交推送。**

### 每週 15 分鐘審計流程

建議在每週重置日前一天花 15 分鐘核查：
1. 開啟 Settings > Usage & Billing 檢視已用百分比。若消耗超前，調出前幾天任務定位異常日期。
2. 進入 Details > Routines 檢視近 20 次執行記錄（Running、Succeeded 或 Failed），排查報錯重試或頻繁空轉的例程。
3. 針對 v0.66.0 起的星標主 Bot，**在描述中明確禁止主動接活**，防它自行攬下瑣事。
4. 訪問 cursor.com/dashboard，核對 Monthly Limit 與實際按需扣費，確認無異常扣款。

### 監控盲區與應對

系統不提供單個 Bot、例程、會話或模型的消耗明細，20 條執行歷史也不記錄 token 和金額。**測試新流程必須採用控制變數法**：
1. 每次只新建或修改一個 Bot 或例程。
2. 執行前後各查一次 Usage & Billing 的百分比對比增量，切忌同時上線多個新例程。

### 額度耗盡時的雲電腦接管應急

周額度 100% 耗盡且前端對話鎖定後，底層的 Linux 雲電腦並沒有銷燬，透過客戶端開啟桌面或系統終端即可接管：
1. 檢視 `/workspace/` 目錄下未交付的程式碼與檔案。
2. 手動執行 `git commit` 和 `git push` 推送到遠端倉庫。
3. 用本地命令列工具在終端接替除錯，**絕不需要花錢購買附加用量**。

## 直接發給 Bot 的省額度提示詞庫

### 上下文防膨脹
- 規則讓 Bot 提煉後記住，**省去聊天重複交代**；共享 Bot 可寫入詳情 About。
```text
请回顾我们至今的协作流程，执行两项沉淀工作：
1. 把你需要长期遵守的行为边界、汇报格式与约束规矩，提炼成一段不超过 300 字的精简文本，我将直接粘贴到你的描述（Description）中；
2. 把我们刚才已经跑通的标准操作流程，封装为一个可复用的技能（Skill），供后续例程直接调用。
完成提取后直接在对话中给出文本，不要展开多余闲聊。
```
- 原始日誌與長資料強制存檔，不直接貼進會話。
```text
从现在起执行上下文瘦身规则：
所有抓取的长篇网页、接口调试日志、大批原始数据和阶段性中间产物，一律直接保存为 /workspace/ 目录下的文本文件。在聊天窗口中回复我时，严格只提供核心结论、关键变动要点以及对应的文件绝对路径。严禁将大段原始文本或日志代码贴回对话。
```
- 多模態圖片轉命令列解析，**避開聊天框高消耗**。
```text
遇到查看多张截图、分析视频画面、逐帧拉片、音频转写或处理长扫描件的任务时，严禁在当前对话框中直接读取原始多模态文件。
你应当在云电脑终端中调用系统已配置的命令行工具（如 Grok Build 或相关转录 CLI）在后台执行，并输出简明的结构化文字摘要；你只需阅读生成的文字结论。如果当前环境无法执行命令行解析，请停下提醒我先在网页端转换成文字后再发给你。
```

### 任務與程式碼分流
- 監控例程無變化時靜默退出。
```text
请列出当前你名下的全部例行任务（Routines），注明每条任务的触发频率、每周预计运行次数以及没有变化时的处理逻辑。
找出其中运行最频繁、消耗最大的任务，向我提出降低频率的具体建议；同时为所有监控类例程添加硬性约束：执行检查后若目标无实质变动，立刻静默退出，严禁向我发送「一切正常」或「没有新消息」等无有效信息的通报。
```
- 任務走單聊派發，**嚴禁 Bot 私自拉群互聊**。
```text
严格执行独立单聊工作模式：
只接收并执行我本人下达的直接指令。严禁在没有得到我明确授权的情况下，主动在会话中唤醒、提及或联络其他 Bot 开展群聊协同；如果任务涉及多个专业环节，请将结果写成文件并由我来负责跨 Bot 调度，或者将其派发给云电脑内的后台 CLI 工具独立运行。
```
- Bot 專注排程，長程式碼編寫與除錯**分流給 Grok Build 後臺 CLI**。
```text
明确你的角色定位是任务调度主管，核心职责是理解目标、拆解方案、组织逻辑和验收结果。
不要在聊天窗口中直接编写整段的长篇代码，也不要通读整个大型仓库做全量重构。涉及代码编写、项目调试和环境排查的工作，统一在后台调用云电脑内已经授权的 Grok Build 命令行工具执行。执行完毕后，你仅需检查其退出状态码并将最终结论同步给我。
```

### 搜尋、風控與交接
- X 平臺搜尋結果存檔，對話只彙報精簡要點。
```text
在检索 X 平台的推文、观点或动态时，使用你自带的免费搜索能力。
搜索到的批量推文原文，请直接写入 /workspace/ 下的对应 markdown 文件中保存。在聊天框中向我汇报时，严格限制为 3 到 5 条提炼后的核心事实与推文对应链接，严禁把多条推文的大段原文搬运回聊天中。
```
- 自動化與介面必須設重試上限，**異常時強制中斷人工審批**。

## 容易踩的坑

- Details > Routines 點選 Test 會跑真機流程，**每次都扣真金額度**。
- Cursor 與 SuperGrok **額度不累加**，只算周用量高的一方，另一方閒置。
- grok.com 與 Grok Bot 計費獨立，網頁版充值**不能抵扣且不退款**。
- 聊天框貼 API Key 或 Webhook 佔 token 且危險，**必須用安全彈窗寫環境變數**。
- 點「更新電腦」會抹掉 Linux cron，`/workspace/` 保留，**更新後得重灌 cron**。
- Duplicate 會丟棄對話、learned memory 與附件，**得手動給新 Bot 喂上下文**。
- Monthly Limit 觸發後不殺程序，**長任務會跑完**，死迴圈可能超額。

## 做完怎麼驗收

1. 進 Settings > Usage & Billing 和 cursor.com/dashboard 查賬單，確認看到已用百分比與重置倒計時，**關掉 Additional Usage 或把 Monthly Limit 設在安全低位**。
2. 讓 Bot 模擬刪檔案或對外發網路請求，必須彈出 **Ask first** 審批卡片並掛起等待，絕不能靜默執行。
3. 檢查當前會話並下發多推文 X 搜尋，側邊欄不留數十輪長會話，只返回 3 到 5 條簡報，長文字落盤至 `/workspace/`，對話方塊不刷原文。
4. 去 Details > Routines 給無變動的監控例程點 Test，檢查後直接靜默退出，不發多餘的「無更新」閒聊。
5. 讓 Bot 編寫多檔案依賴程式碼，看它在後臺呼叫 Grok Build 或雲端 Agent，**只輸出最終狀態與執行摘要**，聊天框不貼整屏程式碼。
