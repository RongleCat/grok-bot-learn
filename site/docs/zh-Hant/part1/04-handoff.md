# 第 4 章 交代任務：訊息、附件與一次好的交接

需求給得太簡短，它容易搜幾十個無關網頁、改亂檔案。**發訊息就是給雲端電腦交接工作**。

- **設死任務邊界**並說明附件用途，防止它自作主張
- 給出明確指令，換回可直接驗收的交付物
- 執行中隨時插話糾偏，或用語音補充背景


![交代任務：訊息、附件與一次好的交接](/info/04-handoff.png)

## 好請求的五要素

![好請求的五要素](/info/04-handoff-s1.png)

跟 Grok Bot 交代任務，**指令必須明確目標與工具範圍**，規範見 [《Grok Bot》](https://cursor.com/cn/docs/grok-bot) 文件。

1. **動作具體單一**。寫明「抓取比對」或「起草外信」，別用「研究一下」，路徑越短越省步數。
2. **限定資料來源**。指定 Notion 頁面、Slack #sales-leads 頻道或網址，防全網亂搜。
3. **劃清審批紅線**。讀取比對自動跑；**涉及發外信、線上支付或刪改資料，必須暫停等審批**。
4. **鎖定交付形態**。**拒收口頭彙報**，要求在 `/workspace/leads/` 生成帶連結的 Markdown 報告或 CSV 表格。
5. **定好報錯規則與事實邊界**。區分推測與客觀事實；遇到登入失效跳過並記錄，**禁止死迴圈重試**。

## 附件規格與限制清單

上傳規則見 [《使用 Grok Bot》](https://cursor.com/cn/docs/grok-bot/work)。

### 規格限制

- 桌面端每條**限 6 個**（超額放工作區）；圖文音訊限 25MB，影片限 200MB。
- 遇阻或報錯，先在本地轉 PDF、CSV 或圖片再傳。

### 交接與群聊

1. **拖入後別直接回車**，寫清各檔案身份、關聯邏輯與保護宣告。

```text
上传的 PDF 是已经签署的标准采购合同模板。上传的 Excel 是本月供应商提交的实际报价清单。
请对照合同模板中第 4 条关于各类物料的基准单价，逐行核验 Excel 里的实际报价。
标出单价超出基准价的所有条目，在附带的备忘中引用合同中的对应条款编号。
将核验结果另存为一份新的 Excel 表格，并输出一份简短的异常摘要。
请勿改动原始上传文件。
```

2. 群聊中 Bot 間**僅支援純文字**。下游要看附件必須私聊發它。

## 任務交付實用提示詞庫

常用場景**直接套模板**，改改就能用。

1. **調研外聯**：查線索備料，不直接傳送。
```text
从我们的 CRM 系统中获取本周销售管道的重点评审列表。
请跳过当前已经处于活跃跟进序列中的联系人。
在指定公开网页和已授权的 Slack 相关频道中，深入调研排名前五的重点账户，找出负责采购或技术的对口联系人。
参考我在系统中历史邮件的口吻，为这五位联系人分别起草个性化的初次外联邮件。
将草稿保存在系统草稿箱中，并在明天上午 9 点前在此对话中列出清单供我审批。未经我的明确确认，绝不向外发送任何邮件。
```
2. **附件核驗**：對齊多表並核查收支。
```text
附件中的 PDF 为《2026 年度差旅与报销政策细则》，CSV 表格为本月部门提交的待审批费用报销流水。
请逐项核对 CSV 中的每一笔申报项目：
1. 检查报销金额是否超过对应城市级别的住宿与餐饮标准。
2. 检查单笔超过 500 元的支出是否有对应的发票类别标记。
3. 提取所有不符合政策规定的异常申报，列明行号、申报人、金额、超标原因及违背的政策条款。
最后生成一份 Markdown 格式的核查报告，并列出通过与未通过的统计汇总。保持原始 CSV 文件不被改动。
```
3. **網站巡檢**：巡查頁面並留存證據。
::: details 任務交付實用提示詞庫
```text
你负责检查我的网站运行状态。本次只访问我提供的以下三个页面：首页、最新更新日志页、用户注册页。
逐一核验各页面是否能正常打开、关键按钮是否响应、文本信息是否存在断链或明显过期内容。
排查过程中必须执行以下要求：
1. 发现任何显示异常或报错时，保存完整的页面 URL、检查时间戳以及当时的屏幕截图。
2. 区分页面直接看到的事实与你的推测，事实写在证据栏，分析写在备注栏。
3. 检查受阻或遇到需要验证码时，记录阻碍原因并继续检查下一个页面，不要重复尝试。
4. 检查结果报告保存在 /workspace/site-check/ 目录下，命名为 check-report.md。
你仅有只读检查与生成报告的权限，严禁更改后台设置或提交任何表单。
```
:::
4. **方案排查**：複雜操作前審邏輯防走偏。
::: details 任務交付實用提示詞庫
```text
我准备让你整理过去一个季度跨 Notion、Gmail 和 GitHub 的客户产品缺陷反馈。
在正式开始执行数据读取与整理之前，请先不要调用任何批量工具，先在对话中向我提交一份执行计划：
1. 列出你准备按顺序访问的系统、模块与具体检索词。
2. 说明你打算提取哪些关键字段，以及如何去重。
3. 标明整个流程中哪些环节可能涉及对外部状态的更改。
4. 说明你打算将阶段性文件保存在云电脑的哪个路径，以及遇到权限不足时如何处理。
我确认并批准你的计划后，你再开始执行。
```
:::
5. **收件通報**：提取要點並分類轉交。
::: details 任務交付實用提示詞庫
```text
使用已连接的邮箱插件，读取收件箱过去 24 小时内收到的全部新邮件。
按照以下业务逻辑进行分类处理：
1. 属于系统续费、订阅扣款账单的邮件，提取服务商、扣款金额与下次续费时间。
```

## 長期規則與單次任務：別把家規當家務

![長期規則與單次任務：別把家規當家務](/info/04-handoff-s4.png)

**分清長期規則與單次任務**（參見 [《使用 Grok Bot》](https://cursor.com/cn/docs/grok-bot/work)），別把臨時引數寫進長期設定，也別每次重打底線。

| 型別 | 週期與設定 | 示例與限制 |
| --- | --- | --- |
| 長期規則 | 跨會話生效；Bot Details 配置或輸入“請將這條作為你的長期規則記入你的記憶區” | 許可權紅線、日期 YYYY-MM-DD |
| 單次任務 | 單輪生效不沉澱；直接下達 | 處理 12 個賬戶或 3 個音訊，提取十點會議清單 |

所有 Bot 共用 `/workspace`（參考 [《10 條必備經驗，讓你的 Grok Bot 變得更好用》](https://jcng5q8n0f3z.feishu.cn/wiki/Hfqxwy3zQiWkRPkVjRZcVCuHnbc)）。

**記憶不能替代業務系統**，餘額與庫存必須回源拉取，嚴禁腦補。

## 任務進行時的干預：停止、插話與審批

![任務進行時的干預：停止、插話與審批](/info/04-handoff-s5.png)

### 插話與停止
Bot 偏離目標時發普通訊息就能**即時插話**，比如發“換成 2026 年 10 月更新後的新版規範再查”。

操作出錯或遇高風險呼叫，在輸入框發四個字停下。
```text
立即停止
```

**停止只阻斷未執行動作，絕不回滾已儲存的檔案或發出的 API 請求**。停下後按三步排查。
1. 開啟雲電腦預覽面板看狀態。
2. 清理半成品或錯誤寫入。
3. 縮小範圍並明確邊界後再重啟。

### 審批與超時
開啟 Auto-review 或觸發高風險操作會彈出「評審操作」卡片（參見 [《Grok Bot 操作指南》](https://cursor.com/cn/help/grok-bot/how-to)），包含三個選項。
- 允許一次：僅批准本次，後續同類繼續詢問。
- 始終允許：加入白名單並不再提醒。
- 拒絕：徹底攔截該操作。

| 場景 | 等待機制 | 超時結果 |
| --- | --- | --- |
| 實時互動 | 掛起等待 | 持續等待直到點選處理 |
| 後臺無人值守 | 約 10 分鐘自動過期（Expired） | **不執行操作並結束任務** |

### 憑據接管（Action needed）
涉及密碼、2FA，以及 CAPTCHA 或真實支付時彈出接管卡片，按三步操作。
1. 點選 **Take over** 在雲電腦手動輸入。
2. 完成後點選 **I'm done** 交還控制權。
3. **切勿在普通對話方塊輸入明文密碼**。

## 語音互動：實時語音通話與語音聽寫的區分使用

Grok Bot 包含聽寫與通話**兩套不同的語音功能**，詳情參考 [《與 Bot 語音聊天》](https://cursor.com/cn/help/grok-bot/voice-chat) 與 [《Grok Bot 操作指南》](https://cursor.com/cn/help/grok-bot/how-to)。

### 兩種模式對比

| 模式 | 觸發與快捷鍵 | 輸出與場景 |
| --- | --- | --- |
| 語音輸入（聽寫） | 桌面點「開始語音輸入」，Mac 按 Cmd+D，Win/Linux 按 Ctrl+D，手機點「開始聽寫」 | 文字填入輸入框，適合精改提示詞或補引數 |
| 實時語音聊天 | **清空輸入框**後點波形圖示（Start voice chat） | 雙向實時通話，適合梳理思路或快速交接 |

### 開啟步驟與避坑

1. 開啟單個 Bot 對話。
2. **輸入框必須徹底清空**，殘留空格或草稿都會隱藏波形圖示。
3. 點選波形圖示，首次使用需允許麥克風許可權。
4. 顯示 Connecting…（手機端 Calling…），Bot 主動開口即連通。

### 控制與硬性限制

- 通話中能靜音，能看滾動字幕，也可調語速和音色；切屏檢視資料時，點頂欄「返回語音聊天」即可切回。
- **僅支援一對一單聊**，群聊、多 Bot 群與「團隊 Bot」均無法發起。
- **同一時間只能維持一個通話**，切到新 Bot 需確認「結束並聊天」。
- 結束通話後自動生成 Voice chat 卡片記錄總時長，點選查閱完整文字，後續任務在文字流繼續推進。

## 常見失敗寫法與最佳化對照

1. **收斂路徑**：沒定範圍與方法，Bot 會亂點控制檯，**甚至修改生產環境程式碼**。
```text
  帮我维护一下网站，看看有没有什么 Bug。
  ```
改成限定頁面與排查步驟：
```text
  对站点清单（/workspace/sites.txt）中的三个静态展示页进行巡检。
  用云浏览器打开每个页面，检查控制台是否有 404 或 500 报错，检查顶部导航栏链接是否全部有效。
  将报错信息、对应页面 URL 及当时的屏幕截图写入 /workspace/logs/err-20261014.md。
  全程仅做只读检查，严禁点击任何带有提交或删除性质的表单按钮。
  ```

2. **審批邊界**：別給對外傳送許可權，一旦理解跑偏，**容易給重要客戶發錯內容**。
```text
  读取 Gmail 里的未读邮件，重要的直接帮我回一下。
  ```
關鍵節點讓人來審批：
```text
  读取 Gmail 中过去 12 小时的未读邮件。
  仅筛选出发件人属于我们现有企业客户、且正文包含售后或咨询诉求的邮件。
  根据产品常见问题手册，为每封邮件起草回复草稿并存入 Gmail 草稿箱。
  在当前对话中列出客户名称、邮件摘要与草稿正文，等待我的审批。未经我的明确确认，绝不点击发送。
  ```

3. **事實分立**：提示詞別夾帶偏見，**防止 Bot 迎合假設把小促銷當成價格戰**。
```text
  去看看竞品今天的动态，总结一下他们是不是要跟我们打价格战。
  ```
要把客觀資料和推測分開：
```text
  访问竞品官网的公开定价页与首页横幅，获取他们当下的方案价格表。
  对照我们在 /workspace/competitor/last-month-price.json 中记录的旧价格：
  1. 事实列：标出哪些 SKU 的标价发生了变动，变动金额是多少，附带页面截图与访问时间。
  2. 推测列：基于该降价是限时促销还是永久调价，给出你的分析理由。
  两部分内容必须分开分栏呈现，不得将分析推论当作已知事实。
  ```

4. **只讀保護**：沒交代主從表與保留欄位，**原始資料極易被覆蓋損壞**。
```text
  （直接拖入三个 Excel 表格）把这几个表整理一下。
  ```
必須明確以哪張表為準、設為只讀：
```text
  上传的三个表格分别是 7 月、8 月和 9 月的销售明细。
  以「订单编号」为唯一主键进行数据去重合并：
  1. 字段统一保留：订单号、成交日期、客户名称、销售代表、成交金额。
  2. 生成一份全新的 Q3_sales_summary.csv 文件，保存在当前工作区。
  3. 保持我上传的原始 7、8、9 月表格内容与文件名完全不变。
  ```

5. **單一使命**：別在一個 Bot 塞多個任務，既搞亂記憶，**還會快速耗盡每週額度**。
```text
  你帮我写一篇关于新产品的推文，顺便把昨天的账目算了，然后再帮我看看竞品推特。
  ```
拆成單任務分工流轉：
```text
  遵循一个 Bot 负责一项核心任务的原则。当前 Bot 仅承担社媒文案起草职责：
  依据 /workspace/product/spec.md 中的新功能说明，为 X 平台起草三条不同风格的发布文案。
  要求突出性能提升数据，字数控制在 280 字符以内。
  账目核算与竞品调研交由对应的专用 Bot 负责，不要在此会话中处理。
  ```

## 真實業務交接案例

### 網站日常巡檢與證據留存
站長 yishan 把巡檢要求直接寫成驗收規範。工作目錄嚴格限定在 `/workspace/site-check/`，只准檢查首頁、最新文章與訂閱入口，嚴禁漫遊爬取。
- 報告必須留存完整連結、時間戳和當時截圖。**直接看到的報錯算事實，排查原因算推測，必須分開記錄。**
- 遇到登入失效或死鏈就記下缺口直接跳過，嚴禁反覆死磕。具體做法見 [《如何在一個小時內深入使用 Grok Bot》](https://jcng5q8n0f3z.feishu.cn/wiki/GBV8wdZOaijukikjO0pcYFWKnbg)。

### 收件箱中轉與業務分流
一澤Eze 專門設了一個收件箱 Bot 接管 Gmail，沒給下游各個 Bot 分別開放郵箱許可權。
- 收到反饋郵件私聊轉給「產品反饋 Bot」，賬單轉給「訂閱管理 Bot」。
- 純數值對比直接交給命令列指令碼跑。**只給 Bot 同步增量資料，能省下每週使用額度。**
- 高許可權工具不要到處接，先用專職入口做初篩最穩當。

  經驗總結見 [《10 條必備經驗，讓你的 Grok Bot 變得更好用》](https://jcng5q8n0f3z.feishu.cn/wiki/Hfqxwy3zQiWkRPkVjRZcVCuHnbc)。

### 幕僚長摸底與建 Bot
CyrilXBT 先讓幕僚長 Bot 讀團隊 Notion 與 Slack，排查出耗時最長、重複最高且卡點最多的前三項任務，分三步推進。
1. 幕僚長 Bot 手動帶跑，人在旁監督輸出質量。
2. 確認無誤後沉澱為技能，建獨立專屬 Bot。
3. 最後配置定時自動跑。
**涉及傳送、採購、釋出或修改線上系統的節點，必須嚴格保留人工審批。

## 容易踩的坑

1. **傳附件帶說明**：傳多張圖或兩個以上表格時，**務必寫明用途**，否則容易搞反主從關係。
2. **長期規則存入記憶**：單次指令換會話就丟，底線規範要**寫進 Bot 詳情的關於/職責**或存入記憶。
3. **本地聯動防休眠**：純雲端合蓋能跑，但聯動本地電腦休眠會斷連，記得**檢查電源與休眠設定**。
4. **跨 Bot 傳圖走路徑**：群裡 Bot 間只支援純文字，傳圖必須**存到 `/workspace/` 共享路徑**讓對方讀取。
5. **語音按鈕消失先清空**：輸入框留有未清空的文字或空格時波形按鈕會隱藏，**徹底清空輸入框**即可恢復。
6. **高危操作選允許一次**：發郵件或刪改資料別選「始終允許」，穩定跑數週前，**堅持選「允許一次」**。

## 做完怎麼驗收

1. 去 `/workspace/` 或指定目錄核驗檔案，**確認能正常預覽且無亂碼**，別隻看臨時文字。
2. 抽 2 到 3 處核心資料點開連結或截圖，防模型憑空臆測。
3. 翻呼叫日誌，**確認沒私自外發通訊，也沒改配置或覆蓋原檔案**。
4. 分清事實與推測，頁面原話放事實區，推論建議放備註區，混淆的當場糾正。
5. 查異常清單，**遇到失效網頁或缺欄位要記明原因並跑完**，別一報錯就中斷。
