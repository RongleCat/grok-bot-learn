# 第 15 章 案例：電商與生活實操

單開網頁對話方塊容易丟記錄，還得多頭切軟體搬運。**這章帶你用現成方案跑通流程**。

- 生活與內容：拿成熟提示詞生成閒魚文案、小紅書排版和 SVG 圖卡，不再手動對齊。
- 跨境電商：從單機巡檢起步，搭出 **「1 船長 + 12 崗位」團隊**，用待批清單人工把關。

## 案例 1：閒魚上架員（二手閒置資料板與諮詢草稿）

Miles Ma（@miles_mazy，靈感源自 @0xlangeai）做了這個 Bot。賣二手直接丟給 AI **容易被瞎編成全新配置**。它把實況與官網引數分流，生成雙欄資料板和回覆草稿。

### 步驟與驗收

1. 拍好正面、瑕疵特寫和銘牌，理清配件、自提方式與售價。
2. 在 Grok Bot 側邊欄點 `+` 選「新建 Bot」，起名「閒魚上架員」。
3. 上傳實拍圖發提示詞，以標價 89 元二手羅技 K380s 鍵盤為例。

```text
帮我做一份闲鱼上架资料。商品是罗技 K380s，黑色，用了 8 个月，空格键有轻微磨痕，逐键输入正常，没拆过机；附两节在用电池，无包装，卖 89 元，支持自提，邮费待确认。查官方型号资料，整理标题、商品描述、需要补拍的照片和常见咨询回复，做成可打开的资料板，并附可复制的上架正文。没提供的信息标为待确认。
```

4. Bot 聯網查官網引數，生成 HTML 資料板與純文字草稿。

## 案例 2：小紅書編輯（從選題到六張知識圖卡與畫廊）

![案例 2：小紅書編輯（從選題到六張知識圖卡與畫廊）](/info/15-ecommerce-s2.png)

### 製作步驟

1. 在 Grok Bot 側欄新建 Bot，取名「小紅書編輯」。
2. 敲定選題與知識點，把卡片定為 6 張，設好 1080×1440 尺寸與主輔配色。
3. 進入對話介面，傳送提示詞：

```text
给电脑新手做一套小红书图文，主题是“Windows 截图后，图片去哪了”。查微软官方资料，做 6 张 1080×1440 的图：封面、框选截图、整屏保存、当前窗口、剪贴板历史、快捷键对照表。用米白、深蓝和亮黄，文字清楚，配操作示意。直接交 PNG 成图、SVG 源文件和配套发布正文，再做一个能看全套图片的画廊。
```

4. **Bot 會查閱官方文件核對快捷鍵**，生成 SVG 並渲染 PNG，整合成 HTML 畫廊。

### 驗收與避坑

| 卡片 | 內容與排版 |
| :--- | :--- |
| 第 1 張 | 封面，大字居中點出截圖痛點 |
| 第 2-5 張 | 步驟卡，圖解框選、全屏等截圖方式 |
| 第 6 張 | 總結卡，4 種截圖方式與去向表 |

- 全套卡片採用米白底色配深藍文字，亮黃點綴。**必須交付 6 張 1080×1440 PNG、SVG 原始碼、帶標籤正文與線上畫廊**。
- 截圖自動落盤依賴系統相簿設定，**Win + V 查歷史必須提前開啟開關**，且記錄未被覆蓋。
- 改錯別字直接在文字編輯器裡改 SVG，**不用重新生圖**。

## 案例 3：工具情報員（按用途篩選的軟體分析簡報）

Miles Ma 做的「工具情報員」Bot，專門抓取開源倉庫與文件，生成支援分類篩選的網頁卡片簡報。

### 工具限制與推薦任務

| 工具 | 門檻與依賴 | 主要限制 | 推薦任務 |
| :--- | :--- | :--- | :--- |
| **PowerToys** | Windows 安裝包直接執行 | 僅限 Windows，部分實驗功能偶發不穩定 | 快捷鍵提取文字或置頂視窗 |
| **MarkItDown** | 依賴 Python 或命令列 | 複雜圖文版面識別率有限 | 批次轉 Word 與 PDF 為 Markdown |
| **changedetection.io** | 需 Docker 或伺服器環境 | 需運維基礎，受反爬限制 | 監控電商價格標籤變動 |

### 操作步驟

1. 在 Grok Bot 側欄新建 Bot，命名為「工具情報員」。
2. 確定調研受眾與目標工具清單。
3. 進入對話介面傳送提示詞。

```text
帮内容工作室整理 PowerToys、MarkItDown 和 changedetection.io，查官方仓库和文档。每个工具写清能帮忙做什么、上手需要什么、主要限制，再给一个具体使用例子。做成能按用途筛选的网页简报，附来源链接。
```

4. Bot 抓取倉庫說明與依賴，**編寫包含篩選指令碼的 HTML 簡報**存入工作區。

### 驗收標準與避坑

- 每張卡片**包含 6 項核心要素**，覆蓋工具定位、上手依賴，以及主要限制、實操任務與官網連結。
- 網頁頂部設定分類按鈕，能平滑篩選卡片。
- 限制說明務必客觀，明確指出 changedetection.io 需 Docker 或伺服器，不誇大為零門檻。
- 這屬於案頭篩選，**Bot 不跑全流程實測**，主要用來快速排除不符合門檻的候選軟體。

## 案例 4：影片教程師（可互動教學工具與帶字幕短影片）

這是 Miles Ma（@miles_mazy，靈感源自 @0xlangeai 藍哥 AI）的玩法。魔方順逆轉動與四次復位很難文字講清，人工實拍又耗時。**Grok Bot 能在雲端寫出互動網頁，並自動錄屏壓制字幕**。

### 怎麼做

1. 側欄新建 Bot，命名為「影片教程師」。
2. **每次只講一個基礎動作**，避開全套還原演算法。
3. 傳送提示詞：

```text
给孩子做一个魔方入门小工具，能认识六个面、点按钮演示右面顺转和逆转，再展示右面连续转四次回到原位。把实际操作录成一分钟左右的教学视频，加中文配音和字幕，交付视频和工具文件。
```

4. Bot 自動寫網頁、模擬點選並錄屏，生成帶中文字幕的影片。

### 做到什麼程度算好

| 交付項 | 驗收標準 |
| :--- | :--- |
| **互動網頁** | 留存 HTML/JS 原始碼，點 R 換色，點 R' 復原，復位按鈕四次歸位，可離線開啟 |
| **影片成片** | 約 51 秒 MP4 與 SRT 字幕，畫面動作與字幕對齊 |

做後臺演示或單點功能教學都能套用這個套路。

## 案例 5：收藏整理員（把社媒收藏轉化為選題素材庫）

![案例 5：收藏整理員（把社媒收藏轉化為選題素材庫）](/info/15-ecommerce-s5.png)

Miles Ma（@miles_mazy）做此 Bot，把收藏轉成選題庫。

### 操作步驟

1. 側欄新建 Bot，命名「收藏整理員」。
2. 挑 5 類代表連結（如 115 期播客、圖文轉換）。
3. 傳送提示詞：

```text
整理这几条 X 收藏链接，按主题分类，每条留下作者、原链接、核心观点和可以借鉴的写法。再围绕“给新手的 AI 实操教程”提出三个具体选题，做成 Markdown 素材库和选题清单。
```

4. Bot 整理生成「收藏素材庫」與「選題建議」**兩份 Markdown 檔案**。

### 驗收與限制

- 驗收：**保留原作者與原連結**，拆解行文邏輯，3 個選題收斂到單次任務可直接做。
- 限制：**嚴禁將他人實操與資料捏造成親歷**，只學結構思路。

## 案例 6：亞馬遜團隊搭建（從前臺巡檢到「1+12」多崗協同）

![案例 6：亞馬遜團隊搭建（從前臺巡檢到「1+12」多崗協同）](/info/15-ecommerce-s6.png)

### 背景與角色定位

- **誰**：Zach（@1999Zach22）。
- **做了什麼**：將原先在本地 Claude/Codex 執行的 Skill 全面遷移至 Grok Bot，在共享雲電腦上搭建起「1 個出海船長 + 12 個業務崗位」的亞馬遜跨境電商 AI 運營團隊。

### 是什麼

Codex CLI 這類本地工具得一直開機，出門沒法看。**Grok Bot 自帶全天候美國雲電腦**，手機電腦互通，還能用真實買家賬號在亞馬遜前臺瀏覽提問。

Zach 採用 **「1 個船長 + 12 個業務崗位」** 架構。你只對接出海船長，由船長統籌排程各崗位。

**所有崗位嚴格禁止直接改動店鋪後臺**，只輸出待批清單供人工確認。

| 崗位 | 負責什麼 | 嚴禁觸碰的邊界 |
| :--- | :--- | :--- |
| 出海船長 | 統籌排程下屬，彙報週報與清單 | 不越過人直接做業務決策 |
| 助理 / 海盜 / VOC | 巡檢跟賣、調研選品與分析差評 | 不登入賣家後臺，不擅自立項 |
| 財務 / 廣告投手 | 測算單品利潤與出具廣告建議 | 絕不登入後臺改出價或加否詞 |
| 文案 / 設計 / 守門員 | 輸出文案、圖片與合規終審 | 不直接釋出上線，不替人拍板 |
| 覆盤機器人 | 彙總周產出並更新經驗庫 | 不粉飾運營問題，不編造業績 |

### 怎麼做

#### 1. 訂閱方案與環境準備
- **入門選每月 30 美元 Premium 檔**（8 美元 Plus 檔完全無 Bot），按需升 100 美元 Super 檔或 200 美元 Ultra 檔。
- 電腦手機登入同賬號，**確認雲電腦正常執行**。詳見 [Grok Bot 方案與用量指南](https://cursor.com/cn/help/grok-bot/plans)。

#### 2. 先用單 Bot 跑通三件事
用雲電腦美國 IP 與瀏覽器跑通三項驗證：
1. **自家 Listing 日常巡檢**：查主圖、價格、變體與跟賣，異常帶對比證據彙報。
2. **測試 Alexa 購物問答**：登入買家號提問，實測約 8 分鐘測完 8 類場景、查 30 天曆史價格。
3. **競品定時盯盤**：記錄價格與優惠券，**變動才發通知**，無變動不打擾。

```text
每天固定时间去前台检查自家 Listing：主图和价格是否正确，变体是否正常挂载，核心关键词是否能搜索到，是否存在跟卖。只记录指定商品和关键词，有异常才发提醒，并附带与前一日的对比数据和页面截图证据。不登录店铺后台，不执行任何写操作。
```

```text
从消费者的角度，尽可能多地把 Alexa for Shopping 体验一遍，最后给我一份报告。
```

#### 3. 拆解功能與崗位邊界
- 跑通後將任務拆給 12 個業務崗。
- 廣告與上新等**敏感崗位明文禁止寫入後臺**，一律交付「待批清單」，並設清請示邊界。

```text
你是合理烧钱的广告投手。负责分析广告效率、搜索词转化率、出价与预算建议。
边界约束：
1. 绝对不登录广告后台，不直接修改出价，不调整预算，不添加否定关键词，不新建广告活动；
2. 所有优化建议必须生成「待批清单」，每条建议必须附带调整依据和预期影响；
3. 待批清单单线交付给出海船长，由船长提报给业务负责人审核，严禁自主执行。
```

#### 4. 編排「1+N」交接鏈
- **千萬別建多 Bot 群聊**，群聊會重複接收上下文，極速消耗 Token。
- **採用 1+N 架構**，人只對接「出海船長」，由船長派活並收攏結果。

```text
你是出海船长，负责统筹 12 个业务岗位。日常接收业务负责人的目标，拆解为具体子任务派发给对应岗位。所有下属岗位向你单线汇报，由你汇总结果、审核质量；不达标的打回重做，需要人工决策的整理为带选项和依据的待批清单汇报给人。严格遵守交接链规则：
1. 巡检链：助理上报异常与证据，派给数据或广告岗位做归因分析；
2. 选品链：海盗提交机会报告，财务测算单品利润，由你整理为立项建议书提报给人；
3. 上新链：文案出草稿，设计出图，守门员审核，你做终检后交给人确认，由人工在后台发布；
4. 复盘链：收齐各岗位经验，复盘机器人写周报并更新经验库，据此编排下周计划。
所有岗位严禁直接登录店铺后台或执行未授权的修改操作。
```

#### 5. 資產共用與本地接管
- 所有 Bot **共用同臺雲電腦與磁碟**，指令碼拷入工作區全員可用。
- 讀本地檔案需在設定「電腦」頁**開啟「在這臺電腦上執行」**（Execution on Local Computer）並交代複製目錄。

### 可以借鑑什麼

- 先用單 Bot **跑順 SOP** 再拆分。
- 走 **「1+N」主從派發**，防群聊把 Token 跑崩。
- **只出待批清單**，必須人工後臺確認。

## 容易踩的坑

- **絕不給賣家後臺修改許可權**：敏感動作讓 Bot 出「待批清單」由人工執行，防錯標價格或封店。
- **閒魚防腦補成色**：要求「以賣家提供為準，未提供的標待確認」，防混入官網全新引數致退貨。
- **別把 12 個 Bot 拉進一個群**：幾輪對話就耗光整週額度。改用「1+N」主從架構，靠檔案落盤中轉。
- **競品抓取以每日 1 次為宜**：幾分鐘輪詢一次極易封 IP 且吃光額度，高頻走官方 API 或 MCP。
- **認準 30 美元/月的 Premium 檔**：8 美元/月的 Plus 沒有 Bot 入口；認準 2026-10-12 起的 The X Subscription。
- **本地接管必須限路徑**：別開始終允許，接管前指定檔案路徑並保留彈窗確認，防誤動私人檔案。

## 做完怎麼驗收

**交付後對照標準逐項核驗**，別大意。

- **閒魚資料板**：瑕疵與官方引數分列，未知項標「待確認」；嚴禁編自提地址或虛標電池。
- **小紅書圖文**：交 6 張 1080×1440 圖卡與 SVG 原始碼，步驟突出快捷鍵及系統前提；別弄亂配色。
- **工具簡報**：單頁 HTML 須帶篩選與官方連結，據實寫明 Docker 環境限制；禁把部署吹成零門檻。
- **教學影片**：成片約 1 分鐘且音畫同步，必須附帶網頁工具原始碼；字幕畫面別脫節。
- **素材庫**：留原作者與原帖連結，選題收斂到單次實操；別空泛總結或把他人案例當自己的。
- **電商協同**：1+N 架構下只對接船長，調價刊登必出待批清單；嚴禁私自改價或死迴圈耗盡用量。
