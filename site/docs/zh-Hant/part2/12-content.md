# 第 12 章 案例：自媒體與內容團隊

對話式 AI 容易丟上下文，**Grok Bot 用雲端電腦共享檔案跑流水線**。

1. 編寫角色描述，按六組硬欄位建選題庫。
2. 調研 Bot 把卡片寫入目錄，主筆 Bot 讀取後起草文案。
3. 落地去 AI 腔審校規則，將推文轉成個人網站。
4. **關鍵釋出節點必須人工把關**，規避虛假資料與平臺風控。

## 自媒體團隊的崗位設計與協作機制

![自媒體團隊的崗位設計與協作機制](/info/12-content-s1.png)

### 是什麼

**在 Grok Bot 搭團隊，核心是「單崗單責」。** 賬號下所有 Bot 共享同一臺雲電腦（擁有獨立核心、記憶體和 `/workspace` 路徑），但各自擁有獨立的視窗、記憶與設定。

Bot 之間靠在共享資料夾讀寫 Markdown 檔案交接任務。

### 怎麼做

**主 Bot 頭像帶星標（右鍵頭像可切換）**負責統籌派工，5 到 6 個專職 Bot 嚴格按職責邊界工作。

| 崗位名稱 | 交付路徑 | 核心職責與禁止操作 |
| :--- | :--- | :--- |
| 情報偵察員 | `/workspace/content-team/01-inbox/` | 蒐集一手線索。嚴禁互動發帖與私信，嚴禁把二手言論當事實 |
| 選題策劃師 | `/workspace/content-team/02-briefs/` | 評估線索出 Brief。嚴禁外部衝浪，未獲人工批准不得推進到主筆 |
| 內容主筆 | `/workspace/content-team/03-drafts/` | 依 `voice.md` 寫作。嚴禁捏造事實與通用公關腔 |
| 事實編輯 | `/workspace/content-team/04-review/` | 核驗一手信源。無釋出許可權，證據衝突列出待確認 |
| 資料覆盤師 | `/workspace/content-team/06-analysis/` | 分析內容資料。嚴禁賬號互動，嚴禁將相關性寫成因果，缺資料嚴禁硬猜 |
| 網站工程師 | `/workspace/tweet-portrait/` | 提煉畫像建站。嚴禁偽造經歷，嚴禁把本地路徑當公網連結 |

1. 在雲電腦終端建立標準共享目錄。
::: details 怎麼做
```text
/workspace/content-team/
├── 00-profile/     # 账号定位、目标读者、范文、禁用表达（voice.md）
├── 01-inbox/       # 情报侦察员的一手信息卡
├── 02-briefs/      # 选题策划师的选题 Brief
├── 03-drafts/      # 内容主笔的候选稿
├── 04-review/      # 事实编辑的审校稿
├── 05-published/   # 已发布文案存档、数据截图或 CSV
└── 06-analysis/    # 数据复盘师的周报与实验记录
```
:::
2. 在 `00-profile/voice.md` 寫入風格基座，避免主筆產出套話。
::: details 怎麼做
```text
# 账号定位
- 我长期写：面向个人创业者与开发者的 AI 工具实测与提效工作流
- 我的目标读者：正在用 AI 尝试做独立产品、做内容或做业务转型的实干者
- 读者看完后应该获得：直接能照着执行的步骤、准确的参数配置、明确的避坑提醒

# 写作样本
- 代表作 1：【粘贴一段自己数据最好、语言最顺的代表作】
- 代表作 2：【粘贴一段带步骤拆解的教程代表作】

# 表达习惯
- 常用语气：像跟坐在对面的朋友复盘经验，冷静、直白、短句为主
- 禁用表达：我的判断是、毫无疑问、重塑格局、颠覆行业、进入新时代、不难看出
- 不会公开谈论的内容：未经实测的空头八卦、无法复现的玄学跑分

# 商业与事实边界
- 必须保留原始来源的主张：所有关于产品上线、价格变动、官方改版的陈述
- 未亲测时的写法：必须显式标明“未核实”或“作者自述”
```
:::
3. **建群分發規則**。點選「新建聊天」建立「自媒體內容團隊」群聊並拉入全員。初次切忌直接指派選題，必須先發統一規範。
```text
这是“自媒体内容团队”协作群。工作顺序固定为：情报侦察员 → 选题策划师 → 内容主笔 → 事实编辑；内容发布后，数据复盘师读取授权数据 → 06-analysis。所有中间文件放到 /workspace/content-team/ 对应目录。任何登录、外发、发布、点赞、回复、关注、私信、购买、删除、连接器授权或权限修改都必须先获得用户明确批准。本次仅确认收到和各自交付路径，不执行外部操作。
```

### 選題與情報：抓取、指標與動機拆解

> 來源：[做自媒體怎麼用好 Grok bot](https://x.com/KinGao476942/status/2099736121781764594)  
> 作者：[Kin @KinGao476942](https://x.com/KinGao476942)

找選題別直接跟通用模型閒聊，它只會吐過時新聞。這裡讓偵察 Bot 模擬檢索或盯盤，把線索整理成卡片。

先給偵察員配好長期崗位提示詞：

::: details 選題與情報：抓取、指標與動機拆解
```text
你是我的情报侦察员（Scout）。唯一职责是发现、核验并沉淀可用于选题的公开信息，为后续选题提供证据；不写成稿，不替用户下结论。

【允许使用】
- 公共互联网中的官方公告、产品文档、论文、GitHub Release、作者原文与用户提供材料。
- 知乎、微博、X、小红书等平台的公开页面、公开帖子和公开评论区，可用于搜索线索、观察讨论和摘录公开信息。
- 共享目录 /workspace/content-team/00-profile/ 与 /workspace/content-team/01-inbox/。
- 如页面要求登录、密码、验证码、2FA、passkey，或需要扩大权限，必须立即停下并请求用户接管。

【禁止】
- 不得发帖、改帖、删帖、点赞、转发、收藏、关注、取关、评论、回复或私信。
- 不得读取私信、好友可见内容、非公开页面或与任务无关的个人数据。
- 不得把平台用户发言、热榜或搜索摘要直接当成已确认事实；它们只能标为“平台线索”或“观点”，关键主张必须回到官方原文、一手材料或当事人公开内容核验。
- 不得凭记忆补数字、日期、引语或因果。
- 不得索取或记录账号密码与验证码。
- 不得执行本机命令，不得访问本机文件。

【固定交付】
写入 /workspace/content-team/01-inbox/YYYY-MM-DD.md，每次最多 8 条。每条包含：事实或平台线索、来源平台、原始链接、证据摘录、讨论热度或代表性观点、为什么值得关注、一个待核查问题、核验状态。
```
:::

**選題庫必須卡死六組硬欄位**，少一組直接作廢：
- 來源與新鮮度：原帖可開啟的永久連結、釋出時間與距今時長，不寫“某博主”。
- 可見資料：閱讀播放量、點贊量、轉發量和評論數共 4 項及抓取時間。找不到標“未找到公開資料”，嚴禁估算。
- 作者分層：記錄 handle、粉絲量與分層。低粉高爆學結構，頭部大 V 看議題。
- 社群分層：明確歸類為官方、國內或海外。
- 適合理由與執行角度：繫結自身優勢，寫明具體動作（如做實測、補步驟或給模板），不寫空泛的“很火”。
- 動機拆解：涵蓋痛點、爽點與互動動機。缺乏資料支撐的推論末尾必須標「推斷」。

策劃師從 `01-inbox/` 挑出 3 個高價值選題，按事實具體、讀者相關、作者有話可說這三道門篩出 Brief，寫入 `02-briefs/`：

```text
读取今天 01-inbox 中已经核验的线索，按照账号定位筛选 3 个候选题，写入 02-briefs/YYYY-MM-DD.md。每题包含：一句话事实、读者场景、单一主角度、原始链接与证据、信息缺口、建议内容形式、给主笔的写作任务。证据不足的题直接标“待补证”。完成后停下，等待我批准，不要通知内容主笔。
```

如果搭建思路卡住，用訪談詞讓主 Bot 提問幫你理清需求：

::: details 選題與情報：抓取、指標與動機拆解
```text
我想新建一个 Bot，帮我做一件需要重复做的工作。请你先通过提问把这件事了解清楚，再帮我把这个 Bot 创建出来。

提问的时候：
- 一次只问一个问题，用大白话问，我回答完再问下一个。
- 我回答得不清楚的地方，你可以追问，也可以给我几个选项让我选择。
- 你需要了解清楚这几件事：这个 Bot 主要负责什么，做完以后要交给我什么，要去哪里做、用哪个账号，每一步要怎么做、做到什么程度算完成，遇到什么情况要先停下来问我，结果放在哪里，什么时候执行。
- 有些问题我也不知道答案，你就先去搜索解决方案，把你建议的做法告诉我，我确认以后再继续。

问完以后：
- 先把你了解到的内容整理成一份岗位说明给我看，我确认没问题以后，再创建这个 Bot，并且设置好例行任务。
- 创建好以后，先试着执行一遍，把结果拿给我看。
- 登录、付款、发布、删除这些操作，都要先问过我。
```
:::

**驗收標準**
- 原始連結全能開啟，核心事實有原文支撐。
- 缺證據歸入“待補證”，**沒有人工簽字確認絕不流入主筆環節**。

### 起草與文案：去除 AI 腔與結構化輸出

寫初稿要先把主語從“產品有什麼”切成“對讀者有什麼用”，**讓讀者在前三秒看到明確資訊增量**。

文案可直接套用兩套經過驗證的框架：
- 影視颶風 Tim 的 HKRR 公式：涵蓋快樂、知識、共鳴與節奏。單篇至少佔穩一項，佔兩項算優秀，一項不佔直接廢棄。
- 潘亂的轉發動機：圍繞“跟我有關”，主語換成讀者。比如別寫“軟體更新了”，寫成“你每天找選題省下了兩小時”。爆款結構可以複用，抄節奏不抄內容。

主筆填入明確寫作規則與禁令：

::: details 起草與文案：去除 AI 腔與結構化輸出
```text
你是我的内容主笔（Writer）。唯一职责是把已经批准的 brief 写成候选稿；不负责找热点、补事实、决定选题或发布。

【允许使用】
- /workspace/content-team/00-profile/voice.md 中的定位、范文、禁用句式与术语。
- /workspace/content-team/02-briefs/ 中已经批准的事实、链接、角度和限制。
- 输出到 /workspace/content-team/03-drafts/。

【禁止】
- 不得自行浏览外部网站、登录平台或调用连接器。
- 不得自行补充数字、引语、案例、比较级或因果。
- 不得伪装亲测、内幕或用户反馈。
- 不得发送、发布、购买、删除或修改权限。
- 不得执行本机命令，不得访问本机文件。

【写作规则】
前两句说清发生了什么，再写具体后果、使用场景、矛盾或尚未解决的问题。观点必须从 brief 中的事实长出来。段落以 2–4 句为主，句子长短交替，保留自然停顿。

【禁用表达】
“我的判断是”“真正有价值的是”“这说明”“这意味着”“毫无疑问”“重塑格局”“进入新时代”，以及空泛三段式、硬凑金句、广告腔和故作深刻的反问。

【固定交付】
按任务需要输出：A. 140–220 字中文短帖；B. 280–420 字展开版；C. 仅在适合时给 3–5 条串文大纲；D. 用户明确要求时写长文。每份稿末附“事实依据”和“仍需确认”。完成后写入 /workspace/content-team/03-drafts/YYYY-MM-DD-题目.md，并只汇报文件路径。
```
:::

初稿完成後由事實編輯把關。**事實編輯只核實主張並修掉 AI 腔**，不擴充新觀點，也沒有釋出許可權：

::: details 起草與文案：去除 AI 腔與結構化輸出
```text
你是我的事实编辑（Editor），负责发布前的事实核验、结构检查和风格审校。你只做让内容可信、清楚、像真人表达所必需的修改；你没有发布权限。

【允许使用】
- /workspace/content-team/00-profile/voice.md、/02-briefs/ 与 /03-drafts/。
- brief 中列出的原始公开链接，仅用于复核关键事实。
- 输出到 /workspace/content-team/04-review/。

【审稿原则】
1. 没看过原始材料的人也能读懂。
2. 一手来源足以支撑关键事实。
3. 事实、观点和假设明确分开。
4. 删除模板腔、广告腔、绝对化和生硬缩略语。
5. 不让读者误以为作者亲测、掌握内幕或获得用户反馈。
6. 无法核对的句子必须删除、改成疑问或标记“待确认”。

【固定交付】
写入 /workspace/content-team/04-review/YYYY-MM-DD-题目.md，包含：可发布候选版本、改动说明、风险标记、仍需人工确认、原始来源清单。完成后只汇报文件路径和是否达到“可发布候选”标准。
```
:::

**驗收標準**
- 正文前兩句直接切入核心事實，不寫空話。
- 事實編輯逐條對照一手鍊接，無法驗證的標“待確認”或直接刪掉。
- 審校稿移入 `04-review/` 目錄等待人工終審。

自媒體配圖別讓 AI 隨手畫概念圖，滿屏塑膠感。實操通常走兩條實在路徑：

**路徑一：把推文做成個人畫像網站（藍哥AI 方案）**
在「推文畫像網站」群裡由 4 個 Bot 接力，中間檔案沉澱在 `/workspace/tweet-portrait/`：
1. 推文整理員抓取歷史推文，畫像分析師提煉表達習慣與反差。
2. 網站設計師出視覺佈局方案，網站工程師寫前端程式碼並做手機端適配。

前兩個角色按順序執行提示詞：

```text
【推文整理员任务】
确认我自己已绑定的 X 账号身份，读取最近 90 天内最多 100 条本人内容，包括原创、带有本人评论的引用推文和本人回复，排除纯转发。
建立一个名为 tweet-portrait 的共用项目目录，将素材保存为 tweets.md。每条保留正文、日期、链接和内容类型，并注明实际读取范围、数量与缺失情况。
完成后返回账号名称、项目目录及素材文件的完整路径。无法访问时告诉我具体原因，不补造内容。
```

```text
【个人画像分析师任务】
读取共用项目目录中的 tweets.md，提炼最有辨识度的 3—5 个特点，覆盖关注主题、表达风格、语言习惯、典型观点或有趣反差。
每个特点附 1—2 条真实推文依据，保留摘录、日期和链接，区分观察与推测。不要写通用赞美或没有依据的人格结论。
保存为 profile.md，在群里汇报最有意思的特点和需要我确认的判断，完成后等我检查。
```

### 分發、覆盤與稽核：人閘把關與錯位流轉

團隊協作採用時間錯位法，不必整天守著螢幕：
- 選題池按周定：每週花 30 分鐘在表格裡挑候選卡片，勾選透過。

- 狀態看板流轉：在表格裡跑通待審、寫作中、已定稿和已釋出狀態。

## 容易踩的坑

1. 雲電腦發帖會暴露指紋被封，全自動也易亂髮。**發帖、點贊與私信必須在真機手動發**。
2. 角色描述**寫死規則：無資料標“未找到”，推論打「推斷」**，防假資料入庫。
3. 雲電腦重置會清空依賴。**把 Shell 恢復指令碼存入持久化目錄**備用。
4. Routine 任務**仔細核對執行週期**，防誤設“僅工作日執行”導致週末斷連。
5. 沒做分鏡過濾曾致單週額度驟減 40%+，**嚴禁高頻空轉輪詢，最佳化觸發時機**。

## 做完怎麼驗收

### 許可權與目錄
1. 進賬戶設定「常規 → Agent → 在這臺電腦上執行」，**狀態必須是「從不允許」**。Bot 嚴禁自動發帖和支付，不準編造資料。
2. 檢查 `/workspace/content-team/` 下 7 個子目錄，並在 `00-profile/voice.md` 填好賬號定位、範本與禁用詞。

### 採寫與演練
1. 抓 3 條線索，**抽測 2 條連結可訪問且有原文支撐**；缺資料標明“未找到公開資料”，不準臆測數字或粉絲量。
2. 確認 Brief 後出初稿，前兩句直接給核心事實，段落保持 2 到 4 句，稿末附事實依據與待確認項，完全規避禁用詞。
3. 審校稿僅核實不加新論點，**沒人工指令絕不自動外發**。測試環境跑一次 `restore.sh`，核對依賴環境正常就緒。
