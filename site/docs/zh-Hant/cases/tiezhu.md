# 鐵柱的實戰長文與推文

跟做 Grok Bot 最容易踩**三個坑**。
1. 高耗任務全堆給主對話，兩三天燒光整週額度。
2. 雲電腦一旦重置，環境工具全丟。
3. 多個 Bot 進群迴圈喚醒，瞬間耗盡用量。

這裡收錄了鐵柱（@cgnot996）的 **9 篇實戰長文與 4 篇系統推文合集**，涵蓋訂閱額度與外部協同、防災備份和架構選型四個主題。每篇都附帶人工摘要卡與直達連結，方便直接照抄提示詞、指令碼與分流方案。

## 訂閱方案與算力額度精打細算

### 額度機制與分流策略

官方按每週共享池計費。**每輪互動都會全量重讀歷史**，直接在主對話貼長文件或長程式碼會讓上下文暴漲，後續每次改動都在重複付費。

**主對話只留關鍵結論與檔案路徑**，長資料存進工作目錄，重活分流給後臺：
- 寫程式碼交給命令列工具 Grok Build。
- 日常監控交給系統底層定時指令碼。
- 圖片與音影片解析在命令列出純文字摘要後再返回。

日常驗收看兩條指標：
- 每週重新整理日前保留 20% 以上用量。
- **關閉按量付費**，杜絕後臺死迴圈與輪詢空轉。

| 檔位 | 月費 | 建議與額度 |
| :--- | :--- | :--- |
| Plus | 8 美元/月 | 不含 Bot，僅適合輕量開發 |
| Premium | 30 美元/月 | 開啟 Bot 門檻，周額度 4 倍 |
| Super | 100 美元/月 | 高頻排程多 Agent，周額度 15 倍 |
| Ultra | 200 美元/月 | 適合專業團隊，周額度 50 倍 |

把規則發給主力 Bot 即可生效：

```text

```

## 自動化入庫與外部協同網路

### 自動化管道與協同配置

配上 Webhook，Grok Bot 就是 **7×24 小時自動化節點**。

1. Bot 端建例行任務，觸發選“當 Webhook 被觸發時”，儲存後獲取介面地址與 Bearer 金鑰。
2. 手機用快捷指令配“獲取 URL 內容”，以 POST 傳送 JSON 文字或連結。
3. 微信無分享面板就讀剪貼簿；大附件或多圖存臨時網盤換公網連結，Bot 雲端下載解壓。
4. 飛書走長連線，免公網 IP 和自建伺服器，配門鈴觸發器定向派活。

**驗收標準**：
- 手機即發即走不用等。
- Bot 雲端非同步抓取、抽幀轉錄、落庫並給收錄回執。
- 群聊僅被精準艾特或全員時響應。

發提示詞可**自動生成接收端點**：

```text
帮我创建一个 Webhook 触发的例行任务。快捷指令会用 POST 请求发来一个 JSON，里面包含一个字段 info。info 可能是我输入的文字，也可能是一个文件下载链接，比如微信聊天记录压缩包、截图、录音。收到后：如果是链接就先下载文件再读取，压缩包先解压；然后整理出要点，收录进知识库，最后给我一份回执，写清楚收录了什么、存在哪里。
```

## 虛擬機器防災與記憶資產備份

### 災備機制與資產分類

所有 Bot 共享同一 Linux 底座（至強 8 核 8 執行緒、16GB 記憶體與 128GB 硬碟，作者自述未核）。**不同 Bot 會話獨立但底層檔案系統打通**，官方無原生匯出。

|場景|保留|丟失與影響|
|---|---|---|
|系統更新|工作目錄與部分憑據|抹掉常駐程序、定時任務與全域性包|
|整機重置|無保留|系統盤格式化，非持久化資料全丟|

手動備份不現實，**必須把重建邏輯程式碼化**。災後在新環境跑總入口指令碼，透過健康檢查恢復運轉。

|資產|路徑與檔案|恢復策略與坑點|
|---|---|---|
|記憶設定|私有Git：agent-spec.md、profile.md、MEMORY.md|按清單讀入新Bot，還原度約80%（作者自述，未核）|
|常駐服務|私有Git vm-services/：REGISTRY.md、registry.json、原始碼|靠restore-*.sh冪等重灌並透過健康檢查|
|訪問憑證|本地 ~/.agents/secrets/：.env（chmod 600）|**嚴禁進 Git 或日誌**，災後人工按總賬填入|

配給獨立運維 Bot 以下提示詞，維護服務總賬與恢復指令碼。

```text
你是「虚拟机服务管家」，负责维护这台机器部署的所有第三方服务。你维护一份登记总账（REGISTRY.md 与 registry.json）、每个服务的独立恢复脚本（restore/restore-<服务>.sh，必须幂等可重复运行）、总入口 restore/restore-all.sh，以及一份排除日志和密钥的自写源码备份 service-src/。总账记录服务 ID、用途、安装方式、启停命令、健康检查命令和密钥存放路径。仓库严禁存入明文密钥。收到恢复指令后，按依赖顺序跑脚本并逐项交出健康检查验收清单。
```

## 架構演進、業務實戰與生態選型

### 矩陣分工與選型評估

平時用 Agent 要堅持“一人一崗”。**別把寫程式碼、抓資料，連同生活歸檔與發帖全塞給同一個 Bot**，提示詞容易衝突，超長上下文也會把模型帶偏。

平臺選型可以參考鐵柱的“品牌整機”與“DIY 組裝機”對比：

| 路線 | 代表產品 | 優勢 | 適用場景與侷限 |
| :--- | :--- | :--- | :--- |
| 品牌整機 | Grok Bot、Muse | 雲電腦開箱即用，免運維遠端會話與應用整合 | 受官方周額度與規則限制；適合重度依賴社交分發與雲端託管 |
| DIY 組裝機 | 本地開源 Hermes、DS Bot | 自由掛載開源模型，無額度限制，資料高度私有 | 需要自己搭系統、調指令碼；適合純程式碼開發與定製模型微調 |

業務落地要守住安全與自動化底線：
- 機械性的抓取資料和錄入表格做到全自動化。
- 涉及公開社交運營或資金變動，必須保留人工確認閘門。
- **發帖必須走官方 API，嚴禁在雲電腦裡用無頭瀏覽器模擬登入**，避免賬號被封。

崗位分工與避坑參考：

| 業務崗位 | 常駐 Bot | 職責 | 安全邊界與避坑配置 |
| :--- | :--- | :--- | :--- |
| 程式碼與運維 | 倉庫管理員、SEO 監控 | 每日監測專案、自動合併 PR、補全指引 | **檢查定時任務日曆**，避免誤設僅工作日執行導致週末停擺 |
| 生活與歸檔 | 記賬管家、知識庫收錄 | 接收快捷指令推送的圖文，錄入多維表格 | 臨時圖床設定高強度隨機 ID，敏感隱私不走公網跳板 |
| 協作與排程 | 文章主編、虛擬機器管家 | 拆解選題、協調各 Bot、管理後臺總賬 | 外部工具採用裝置程式碼（Device Code）授權，防止兩臺機器互相頂掉登入態 |

合集記錄了 Grok Bot 的底層演進。**同一賬號下的所有 Bot 共享同一臺 Linux 雲電腦**，配置是 8 核 16G 記憶體配 128G 硬碟，各桌面會話相互獨立。文中還記錄了專屬郵箱申領、呼叫原生 X 搜尋與排查出口網路的方法。

環境排障重點記住兩點：
- **Webhook 面板點選沒反應時，直接發指令讓 Bot 回覆直達連結。**
- 核心環境配置與自定義指令碼必須收斂到持久化路徑，避免系統底層更替帶來損耗。

### 鐵柱推文合集③：實戰玩法與案例

作者：铁柱AGI（推文合集）｜適合誰讀：找業務落地靈感、想避開自動化封號和死迴圈的實踐者

鐵柱記錄了十餘個真實執行的 Bot 崗位，包括倉庫巡檢與 SEO 日報，也涵蓋微信抓取、多維表格記賬及拼圖介面呼叫，並給出了從單崗配置到持久化災備的四步實施法則。

平穩執行必須遵守兩項運維規範：
- **釋出內容必須走官方 API，嚴禁在虛擬機器內用無頭瀏覽器模擬發帖**，防止賬號受限。
- **外部命令列工具統一用裝置程式碼（Device Code）授權**，防止兩臺機器爭奪憑證導致掉線。
