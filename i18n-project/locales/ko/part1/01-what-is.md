# 제1장 Grok Bot이란 무엇인가: 자체 컴퓨터를 갖춘 AI 동료

전통적인 웹 대화는 자산을 축적할 수 없으며, **컴퓨터를 덮는 순간 작업이 바로 중단됩니다**. 소프트웨어 간 호출과 지속적인 점검 작업 앞에서도 사람은 여전히 컴퓨터 앞에 묶여 기계적인 클릭을 반복해야 합니다.

본 장은 4가지 핵심 내용을 다룹니다.
- Grok Bot의 작동 메커니즘과 공유 클라우드 컴퓨터의 물리적 경계;
- 수행하기에 적합한 작업과 적합하지 않은 작업 유형;
- 시중의 다른 상주형 Agent와의 제품 선정 차이점;
- **규격에 부합하는 직무 기술서를 작성하고, 권한 남용을 방지하는 수동 승인 게이트를 구축하는 방법**.


![Grok Bot이란 무엇인가: 자체 컴퓨터를 갖춘 AI 동료](/info/01-what-is.png)

## Grok Bot의 기본 작동 메커니즘은 무엇인가? {#产品机制-环境底座与思考模型拆分}

**Grok Bot의 핵심은 클라우드에 상주하는 Linux 베이스와 필요에 따라 호출되는 사고 모델을 분리한 것으로, 터미널, 브라우저 및 지속성 파일을 갖추고 있어 컴퓨터를 끄거나 덮개를 닫아도 백그라운드 작업이 클라우드 컴퓨터에서 그대로 계속 실행됩니다.**

![제품 메커니즘: 환경 베이스와 사고 모델의 분리](/info/01-what-is-s1.png)

xAI와 Cursor는 2026년 8월 11일 Grok Bot을 출시했으며, **핵심은 환경 베이스와 사고 모델을 분리한 것입니다**.

- **베이스（Harness）**: 클라우드에 상주하며 Linux 터미널, 브라우저 및 지속성 파일을 갖추고 있습니다. 컴퓨터를 끄고 덮개를 닫아도 백그라운드 작업은 정상 실행됩니다.
- **모델（Brain）**: 필요에 따라 호출되며, 단일 모델에 고정되지 않고 사용자가 확인하거나 지정할 수도 없습니다. 2026년 10월 7일부터 작업이 Claude Opus 5.5 등의 모델로 라우팅될 수 있으며, Cursor Agent를 파생시켜 협업 코딩을 진행할 수도 있습니다.

| 도구 | 실행 환경 | 오프라인 및 협업 |
| --- | --- | --- |
| 챗봇 어시스턴트 | 임시 웹페이지 | 웹페이지를 닫으면 즉시 종료, 단일 대화 |
| CLI Agent | 로컬 터미널 | 종료 시 즉시 중단, 로컬 리포지토리로 제한 |
| Grok Bot | 영구 클라우드 컴퓨터 | **컴퓨터를 꺼도 계속 실행**, 작업 간 파일 인계 |

메커니즘에 대한 자세한 내용은 [《1.1 Grok Bot 是什么：一页看懂》](https://jcng5q8n0f3z.feishu.cn/wiki/I04Gw3wEaisftUkBikxcg43rnpc)를 참고하세요.

## Grok Bot 공유 클라우드 컴퓨터는 어떻게 격리하고 제어권을 넘겨받는가? {#共享云电脑的物理边界与接管机制}

**동일 계정의 모든 Bot은 클라우드 컴퓨터를 공유하며 경로와 Cookie를 격리할 수 없습니다. 작업 간 인계는 /workspace에 파일을 저장해야 하며, 비밀번호 입력이나 결제 등의 작업 발생 시 Take over를 클릭하여 수동으로 제어권을 인수할 수 있습니다.**

![공유 클라우드 컴퓨터의 물리적 경계와 제어권 인수 메커니즘](/info/01-what-is-s2.png)

동일 계정의 모든 Bot은 클라우드 컴퓨터를 공유합니다. Heavy 등급 실측 기준 Xeon 8코어 8스레드, 16GB 메모리, 128GB 디스크(미검증, 공식 기준 우선)이며, v0.68.1에서 해상도가 1920×1200으로 상향되었습니다.

자세한 규격은 [Grok Bot 컴퓨터 및 애플리케이션 문서](https://cursor.com/cn/docs/grok-bot/work#the-computer-and-apps)를 참조하세요.

- 새 Bot을 생성해도 **권한을 격리할 수 없습니다**. 경로와 로그인 세션을 공유하므로 모든 Bot이 Cookie를 읽을 수 있습니다.
- Bot 간 협업은 파일 디스크 저장에 의존합니다. 개별 대화창은 기본적으로 격리되어 있으므로, 인계 작업은 `/workspace`에 파일을 저장해야 합니다.
- 비밀번호 입력, 2단계 인증, 결제 등은 Take over를 클릭하여 처리하고, **채팅창에 평문 비밀번호를 절대 보내지 마세요**.
- 로컬 제어는 별도 승인이 필요합니다. 로컬 환경과는 기본적으로 격리되어 있으며, Settings → General → Agent → Execution on Local Computer에서 활성화할 수 있고 실행 시 팝업 확인을 거칩니다.

## Grok Bot은 어떤 작업에 적합하고 적합하지 않은가? {#适合与不适合的任务类型}

**Grok Bot은 프로세스가 고정되어 있고, 빈도가 높으며, 여러 툴을 넘나들며 호출해야 하는 작업(예: 정보 모니터링, 버그 재현)에 적합합니다. 반면 실시간 질의응답, 로컬 코딩 및 사람의 승인 게이트가 없는 고위험 작업에는 적합하지 않습니다.**

![적합한 작업과 적합하지 않은 작업 유형](/info/01-what-is-s3.png)

### 작업 필터링 기준
**작업을 Grok Bot에게 맡겨야 할지는 세 가지 필터링 기준을 통해 바로 판단할 수 있습니다.**
- 웹 브라우저, 터미널 또는 API를 통해 전체 프로세스를 실행할 수 있는가;
- 중간 파일이나 최종 보고서를 사람이 직접 검증할 수 있는가;
- 고위험 민감 작업 시 멈추고 사람의 팝업 승인을 기다릴 수 있는가.

### 적합한 작업
**프로세스가 고정되어 있고, 고빈도로 반복되며, 툴 간 호출이 필요한 작업에 적합합니다.**
- 정보 모니터링: 정기적으로 지정된 공식 사이트를 방문하여 요약 표 작성.
- 리드 정제: CRM에서 타깃 계정을 추출하고, 공개 정보를 결합하여 검토용 아웃리치 이메일 초안 작성.
- 재무 정산: 매주 인보이스를 대조하고, 누락된 세금계산서를 표시하여 청구 독촉.
- 버그 재현: Issue를 읽고 프리릴리즈 환경에서 재현한 뒤 로그 및 스크린샷 추출.
- 경영 모닝 리포트: 매일 재고 지표를 취합하고 이상 수치를 포착.

### 적합하지 않은 작업
**맞지 않는 작업을 억지로 맡기면 주간 한도만 헛되이 소모하거나 통제 불능 상태에 빠지기 쉽습니다.**
- 실시간 질의응답: 에러 검색은 일반 웹 모델로 몇 초 만에 해결되므로 클라우드 컴퓨터를 쓸 필요가 없습니다.
- 로컬 코딩: 중단점 디버깅 및 Git 충돌 해결은 로컬의 Codex CLI 또는 Claude Code에 맡기세요.
- 일상 잡무: 캘린더 관리 등은 엔터프라이즈급 데이터 소스가 부족하여 억지로 적용하기에 부적합합니다.
- 무증분 폴링: 5분마다 무조건 새로고침하는 방식은 추론 한도만 낭비합니다.
- 고위험 작업: 대량 메일 발송이나 데이터베이스 삭제 등은 반드시 사람의 승인 게이트를 마련해야 합니다.

계획 수립 방법은 [《1.2 Grok Bot 和 Muse、Hermes、dots、Cue 怎么选》](https://jcng5q8n0f3z.feishu.cn/wiki/BnH9wLTmyiQZ03kJhsecOrffnAd)를 참고하세요.

## 제품 선정 비교: Grok Bot과 주요 상주형 Agent 비교

### 완제품 PC와 조립 PC 형태

상주형 Agent를 선택할 때는 주로 편리함을 추구하는지, 직접 튜닝하는 것을 즐기는지에 따라 갈립니다. **즉시 사용 가능한 완제품 형태**(Grok Bot, Muse)는 배포의 번거로움이 없지만 플랫폼 한도 제한을 받습니다. 반면 조립형(Hermes)은 오픈소스 모델과 연동하여 한도 제약이 없지만, 환경 오류를 직접 해결해야 합니다.

## 대표 실전 사례 분석

### 金尘马의 정보 디렉터 (개인 리서치 포지션)

金尘马(@jinchenma_ai)는 과거 Edit Profile의 Description에 장기 직무 규칙을 명시하여(해당 메뉴는 현재 삭제되었으며, 현재 방식은 제3장 참조) 정보 리서처로 역할을 규정했습니다. 작업 지시 시 결과, 출처, 제약 조건, 포맷, 확인 포인트의 5대 요소를 명확히 하고, X 플랫폼의 장문 글을 검색하며 동영상 게시물을 구분하고 노출 데이터를 명시하도록 했으며, **1차 데이터가 없으면 절대 날조하지 못하도록 엄격히 금지했습니다**.

첫 포맷 교정 후, Bot에게 지시하여 해당 프로세스를 Skill 「AI 튜토리얼 정보 수집」으로 정착시켰습니다.

두 번째 입력 세트로 테스트를 완료한 후 Routine을 설정하여 매 평일 아침 8시 10분에 자동으로 보고를 실행하도록 했으며, 주제를 검토할 「콘텐츠 디렉터」를 새로 생성하고 초안을 `/workspace/grokbot-demo/`에 저장하도록 했습니다.

**직무 기술서로 장기 규칙을 확립하고 임시 요구사항은 메시지로 전달**하며, 여러 Bot은 `/workspace`에 파일을 저장하여 디커플링합니다.

자세한 내용은 [《万字长文｜Grok Bot 从入门到精通｜金尘马》](https://jcng5q8n0f3z.feishu.cn/wiki/MIKpwiUXpiE9mWkyG8ccFM6Znee)를 확인하세요.

### 金尘马의 전자상거래 운영팀 (다중 역할 분업 파이프라인)

팀은 4개의 Bot 협업으로 구성되었습니다. 먼저 「스토어 운영 당직자」를 생성하여 상품 목록, 재고 목록, 주문 목록을 읽고 모닝 리포트를 발송하도록 했으며, **읽기 전용을 절대적인 레드라인으로 설정하여 가격 수정, 재고 수정, 이메일 발송 및 환불 처리를 엄격히 금지했습니다**.

기존 당직자는 「전자상거래 운영 총괄」로 승격시키고, 콘텐츠 성장 담당, 상품 재고 분석가, 주문 CS 어시스턴트로 역할을 분리하여 데이터를 `/workspace/ecommerce-ops/日期/`에 저장하도록 했습니다. 베스트셀러 상품의 재고가 3일분만 남자, 콘텐츠 담당은 프로모션을 일시 중단하고, CS 어시스턴트는 배송 지연 안내 멘트를 준비하며, 총괄은 의사결정 체크리스트를 취합했습니다.

처음부터 거대한 팀을 구축하지 마세요. **자금, 재고, 외부 발신과 관련된 작업은 모두 사람의 수동 승인으로 잠가두어야 합니다**.

### 铁柱의 오픈소스 리포지토리 관리자 Bot (자동화 운영 및 점검)

铁柱AGI(@cgnot996)는 상주형 Bot을 구축하여 awesome-grok-bot 지식 베이스를 유지관리하고 있습니다. 시스템은 정기적으로 X 플랫폼 트윗, 공식 업데이트 로그 및 기술 커뮤니티를 모니터링하여 새로운 활용법, 튜토리얼, 공식 문서 및 이벤트를 분류하여 수록합니다.

공식 홍보 전 이미 관련 자료가 자동으로 수록되었으며, **2026년 8월 Star 130개 이상을 돌파했고(작성자 본인 언급, 미검증)**, 공식 담당자로부터 신청 양식 초대를 받기도 했습니다.

### 구독 등급 확인 및 클라이언트 설치

2026년 10월 12일부터 시행된 The X Subscription 통합 요금제에 따라 등급을 선택합니다:
- **Premium 등급**: 월 $30(연간 결제 시 $300), 4배 한도 풀 제공, 개인 일상 업무 시작 시 이 등급을 권장합니다.
- **Super 등급**: 월 $100(연간 결제 시 $1,000), 15배 한도 풀 제공, 헤비 리서치 및 다중 루틴 작업에 적합합니다.
- **Ultra 등급**: 월 $200(연간 결제 시 $2,000), 50배 한도 풀 제공, 고빈도 팀 핵심 작업에 적합합니다.
- **월 $8(연간 결제 시 $80)의 Plus 등급에는 Bot 기능이 포함되어 있지 않으므로**, 절대 잘못 선택하지 마세요. 이미 Cursor 유료 개인 플랜이나 팀 플랜, SuperGrok 구독 또는 Grok Business 시트를 보유하고 있다면 바로 사용할 수 있습니다.

  데스크톱은 macOS, Windows, Linux를 지원하고, 모바일은 iPhone, iPad 및 Android를 지원하며, 설치 후 계정에 로그인합니다.

### Bot 생성 및 테스트 작업 지시

1. 사이드바에서 **+**(또는 Cmd+N)를 클릭하여 Bot을 생성하고, 이름을 「경쟁사 정보원」으로 지정합니다. 개인 Bot에는 이제 Description 항목이 없으므로 아래의 6줄을 대화창에 보내 기억하도록 지시하고, 공유 Bot인 경우 세부 정보 About의 Description에 작성합니다.
```text
Own: 负责监控目标清单的每周功能更新与定价变动
Sources: Notion 中的关注名单、目标官网 Changelog 页面
Output: 不超过 8 条核心动态，附带日期与原始链接，存入 /workspace/scan.md
Approval: 严禁对外发布任何内容，严禁主动发送任何邮件
Failure: 若目标页面无法打开，在报告中明确标为数据缺失，严禁推测或编造内容
Never: 在源系统可访问时，严禁依赖自身记忆给出概括
```
2. 대화창에 목표, 출처, 제약 조건, 포맷, 확인 포인트의 5대 요소를 명시하여 테스트 지침을 전달합니다.
```text
调研所附竞品清单中的前 3 个产品官网。
比对它们过去两周内的功能更新与价格调整。
跳过无任何变动的模块。
提取核心变动点，整理成 Markdown 表格，并直接保存到 /workspace/scan.md。
在对话框中仅回复处理状态与保存路径；不要对外发送任何通知，不要擅自更改系统设置。
```
3. **우측 클라우드 컴퓨터 화면을 관찰합니다**. Bot이 자동으로 클라우드 브라우저를 실행하여 페이지를 추출하고, 내용을 지정된 파일에 작성합니다.

### 보안 승인 및 정기 루틴 설정

1. Settings → General → Auto-review로 이동하여 **고위험 작업은 반드시 모두 Ask first로 설정합니다**.

   메일 발송(`send`), 게시글 작성(`post`), 결제(`buy`), 파일 삭제(`delete`, `/workspace` 또는 로컬 파일 포함) 및 권한 변경(`permissions`)을 엄격히 제한하며, 트리거 발생 시 카드가 팝업되면서 일시 중단되어 사용자가 수동으로 승인을 클릭할 때까지 대기합니다.
2. 스크래핑 작업이 2회 연속 안정적으로 실행되면 대화창에 자산화(정형화) 지침을 전송합니다.
```text
把刚才已经跑通的竞品页面抓取与格式整理流程保存为一个 Skill，名称叫「竞品动态巡检」。
写清调用条件、所需权限、抓取步骤、异常报错逻辑与产出文件格式。
```
3. 다른 경쟁사 웹사이트 URL로 변경한 뒤 `/`를 입력해 해당 Skill을 호출하여 테스트합니다. 이상이 없음을 확인한 후 **Routine 정기 실행을 설정**하여 매주 월요일 오전 9:00에 자동 실행되도록 지정하고, 결과 보고는 현재 대화창에 발송하며 상세 보고서는 `/workspace`에 저장하도록 설정합니다.

## 자주 겪는 함정

### 아키텍처 및 보안

- 커뮤니티의 29개 Bot 아키텍처(Melvin Vivas 본인 언급, 미검증)를 무작정 따라 하지 마세요. 유사한 Bot이 난립하면 관리가 복잡해지고 한도만 낭비됩니다. **하나의 직무가 원활하게 실행되기 전에는 두 번째 Bot을 만들지 마세요**.
- 모든 Bot은 클라우드 컴퓨터와 파일 시스템을 공유하므로, 크롤러가 `/workspace`와 Cookie를 읽을 수 있습니다. **보안 제어는 Ask first 수동 승인 게이트에만 의존할 수 있습니다**.
- 대화창에 계정 비밀번호를 보내지 마세요. 로그인 화면이 나오면 **우측 화면을 띄워 Take over 버튼을 클릭한 뒤 사람이 직접 로그인하세요**.

### 리소스 및 기대치

- 월 $8의 Plus 등급에는 Bot 진입점이 없으므로, **반드시 월 $30부터 시작하는 Premium 등급을 확인해야 합니다**.
- Routine을 5분 또는 10분 간격의 폴링으로 설정하면 주간 한도 풀이 순식간에 바닥납니다. **정기 작업 간격을 넓히고, 업데이트가 없으면 즉시 종료하는 로직을 추가해야 합니다**.
- Alex Finn의 수익 창출이나 0xkvro의 비용 절감 신화(본인 언급, 미검증)를 맹신하지 마세요. **비즈니스는 실제로 검증된 지표를 기준으로 삼아야 합니다**.

## 완료 후 검증 방법

1. 사이드바에서 Bot을 클릭해 대화창에 진입한 후, 메시지를 보내 **1920×1200 실시간 데스크톱**을 펼칩니다. Usage & Billing으로 이동해 요금제가 Premium, Super 또는 Ultra인지 확인하고 사용량 프로그레스 바가 정상인지 체크합니다.
2. 6줄 계약서에는 직무, 데이터 소스, 산출물, 승인 레드라인, 데이터 누락 시 폴백 로직이 모두 작성되어 있어야 합니다(**6줄 강제 제약**). 개인 Bot은 대화창에 전송하여 기억시키고, 공유 Bot은 세부 정보 About에 작성합니다. 깨진 링크를 전송해 테스트했을 때 **데이터가 누락되었음을 사실대로 보고해야 하며**, 데이터를 지어내지 않아야 합니다.
3. Settings → General → Auto-review에서 `send`, `post`, `buy`, `delete`, `permissions`를 Ask first로 설정합니다. 메일 발송이나 파일 삭제를 테스트했을 때 **반드시 승인 카드가 팝업되어 사람의 확인을 대기해야 합니다**.
4. Routine에서 마우스 우클릭 후 Test run으로 정상 실행을 확인한 뒤 노트북을 덮고 소프트웨어를 종료합니다. 예정된 시간에 다시 열어 알림을 확인하고, 클라우드 컴퓨터의 `/workspace`로 들어가 **Markdown 또는 CSV 파일이 최신 타임스탬프로 업데이트되었는지 확인합니다**.
