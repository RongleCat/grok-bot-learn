# 第 10 章 额度与成本：让一周用量撑满一周

周二额度用尽、被扣上百美元，常因算力空转。**Bot 每次唤醒都重读完整历史**，几小时就胀到数十万 token。

想稳撑一周，做好这三项。
1. 关掉后台按需付费。
2. 减少高频轮询与多 Bot 互聊。
3. 收紧会话，少往聊天框塞大文件。

## Grok Bot 的额度扣费原理是什么？ {#扣费原理-额度是怎么被花掉的}

**Grok Bot 按调用 token 计费，核心机制是单会长对话，每次回复或唤醒都会全量重读历史上下文，总消耗等于唤醒次数乘每次重读的上下文长度。**

![扣费原理：额度是怎么被花掉的](/info/10-usage-s1.png)

Grok Bot 按模型实际调用的 token 计费。**它的核心机制是单会长对话，每次回复或定时唤醒，都会把全部历史重新读取一遍。**

```
每周总消耗 = Bot 唤醒的总次数 × 每次唤醒时重读的上下文长度
```

会话堆积大量日志或网页时，单次重读可达数十万 token，回一句也是全量计算。

**官方明确没有模型选择器（there is no model picker），无法切到低配模型。** 控制成本只能降低唤醒频率、截断上下文长度，或把高耗计算分流到外部。

## Grok Bot 有哪些常见的高耗额度陷阱？ {#高耗操作清单-坚决避开的六大陷阱}

**必须避开多 Bot 群聊、对话喂图与视频、全天高频轮询、长会话一用到底、无保护重试死循环，以及未设月度上限就盲目开启按需付费。**

| 高耗操作 | 费额度原因 | 避坑做法 |
| :--- | :--- | :--- |
| 多 Bot 群聊 | 互相唤醒导致 token 翻倍空转 | 单主导 Bot 配 Subagents 派活，或人工单聊 |
| 对话直接喂图与视频 | 历史帧常驻，每轮全量重读买单 | 终端命令行处理，Bot 只接百字内结构化文本 |

| 无保护重试死循环 | 报错后连续自我尝试数十次 | **提示词强制设 2 次重试上限**，失败立刻阻断问人工 |
| 盲目开按量付费 | 死循环可能一夜产生高额账单 | **平时关闭按需付费**，开启必须设严格低额月度上限 |

## 省额度四步工作流：从止损到分流

![省额度四步工作流：从止损到分流](/info/10-usage-s3.png)

### 锁定计费与安全底线
1. 进 Settings > Usage & Billing 核对套餐（Premium $30/月 或 Super $100/月）、用量与倒计时；卡住点 Stop 强制结束。
2. **调试时关 Additional Usage / On-demand**；若开，去 cursor.com/dashboard > 支出 > Monthly Limit 设月限额（$10-$20）。
3. 进 Settings > General > Auto-review，**把 send、post、buy、transfer、delete、permissions 设为 Ask first 人工批准**。

### 规范会话与交互
- **单任务单会话**，做完立即归档。
- 日志长文存进 `/workspace/`，只回结论和路径，严禁贴回。
- X 搜索限每分 30 次、每天 1000 次（不扣周额度），**约束 Bot「提取核心事实，以 3 到 5 条要点输出」**。
- 会话臃肿时用 Duplicate 重置，先让旧 Bot 写 10 行内总结，复制发给新 Bot 接手，隐藏旧 Bot。

### 能力路由与分流
- 主 Bot 只负责拆解、派发与汇总，不写长代码或转大文件。
- **写代码走 Cursor 云端 Agent**（走 Cursor 额度不扣周额度），或在虚拟机无头跑 Grok Build CLI / Codex CLI。
- 截图与音视频由云电脑命令行处理，或用免费模型转文字再喂给 Bot。

### 定时任务改造
1. Details > Routines 里，**暂停或删除过去一周天天报「没有变化」的例程**。
2. 换 Linux 脚本低成本轮询，有变动再发 Webhook 唤醒 Bot。
3. **保留例程写入静默指令**：「检查后若无变化，直接结束任务，严禁输出任何文字」。

参考：[《4.1 额度与成本：省额度清单》](https://jcng5q8n0f3z.feishu.cn/wiki/KFbzwPhAliezlBkkvIuc1Abgn4h)

## 例程与轮询深度优化：告别无效空转

例程是隐蔽的额度黑洞，高频轮询**一天就能用掉整周用量**。

### 频率收敛与运行窗口控制

客户端先核对 Bot 的 Timezone 是否与本地一致。不同调度设定消耗如下：

| 调度设定 | 每周运行次数 | 适用场景 |
| :--- | :--- | :--- |
| 每 15 分钟一次（全天候） | 672 次 | 极易在 1 到 2 天耗尽额度，极少需要 |
| 每小时一次（全天候） | 168 次 | 关键基础设施故障监控 |
| 工作日 9:00 至 17:00 每小时一次 | 45 次 | 看板跟踪、工单处理与邮件分拣 |
| 每个工作日 3 次 | 15 次 | 每日收件箱早中晚初筛、进展跟进 |
| 每周 1 次 | 1 次 | 行业周报、技术动态总结与文档归档 |

限定工作时间可用标准 cron 格式：

```text
CRON_TZ=Asia/Shanghai 0 9-17 * * 1-5
```

**这行规则把唤醒量降低了 93%**。在上海时区工作日 9:00 至 17:00 整点运行，一周仅触发 45 次。

### 指向技能并严格执行沉默规则

例程提示词只指向技能，不展开细节：
- 斜杠命令指定具体技能名与检查对象
- 给出判定阈值、停止条件与单次重试限制
- **无变化时保持完全静默，不发任何消息**

纯静默容易掩盖中途故障。搭配方案参考[Cursor 官方指南：例程](https://cursor.com/cn/help/grok-bot/routines)：高频例程保持静默；低频例程每天 18:00 发单行心跳日志，确认过去一天正常执行。

### 双角色分离：Linux cron 脚本巡检加 Webhook 唤醒

Bot 休眠时底层 Linux 云电脑还在运行，**别让大模型去干机械比对**。
- 检查角色：系统自带 cron 调度 Python 或 Shell 脚本比对，耗时几秒，消耗额度为零。
- 判断角色：脚本检测到变动再发 Webhook 唤醒 Bot 进行逻辑判断与报告。

Webhook 唤醒步骤与验收标准：
1. 在例程 Webhook 区域获取 `POST to` 地址与 `key`。
2. 向该 URL 发送带有 `Authorization: Bearer <key>` 头的 POST 请求。
3. 检查响应状态码，返回 200 即代表唤醒成功。

### 实战案例与避坑

- **铁柱改造营销总监 Bot 的 6 条例程**：4 条交付类例程保留不变；2 条纯等回复与审 PR 的空转任务换成系统 cron 脚本加 Webhook。脚本工作日白天每半小时检查一次，有新变动才唤醒。

  **改造耗时约 23 分钟，每周减少 8 到 10 次多余唤醒**，新动态发现速度提到了半小时内。

  案例出处：[《Grok Bot 额度再省一点：定时任务极限优化》](https://jcng5q8n0f3z.feishu.cn/wiki/SDr3wRrG5iGmz1kejdTcss0Rned)。
- **Craig Hewitt 24 小时烧光 Ultra 周额度**：订阅每月 $200 的 Cursor Ultra 套餐，2026 年 8 月 23 日一天耗尽整周额度。

  他在日常主聊的主管 Bot 上归档 10 年旧邮件，接口拉取正文不断追加到会话，上下文胀到几十万 token 引发全量重读风暴。

  案例出处：[《How to Stop Your Grok Bot From Eating a Week of Usage in a Day｜Fan Grok Bot Radar》](https://jcng5q8n0f3z.feishu.cn/wiki/HO20w5OQQiNtNuk92mhcdQEynOi)。
- **高负载避坑要点**：**高负载一次性任务绝不能放在天天聊的主 Bot 上**，必须新建专用 Bot 或通过 Duplicate 生成副本；处理前先用邮箱规则过滤垃圾邮件；批量任务必须先拿 1 到 2 个样本验证无误后再启动。

## 群聊与多 Bot 控制：杜绝互相唤醒

**千万别把多个 Bot 拉进同一个群聊。** 新消息会全员广播，每个 Bot 都会重读全量历史并回复。铁柱自述 4 个 Bot 互聊迅速吃掉了 25% 周配额（未核）。

多 Bot 协作要坚持**中心辐射、禁止横向串联**。

- 唯一主导：只保留一个主导 Bot 作为交互入口。
- 单向派活：主导 Bot 启动 Subagents 或 A2A 单点交接，子智能体跑完自动退出，不在群里接话。
- 成果落盘：上游把数据写入 `/workspace/` 下的文件，下游直接读取，不在聊天框推敲。
- 清理闲置：确认无挂载例程后及时删除闲置 Bot，防止被误唤醒。

## Grok Bot 如何做用量审计与耗尽应急？ {#用量审计与应急机制-守住每周节奏}

**每周重置前一天花 15 分钟排查例程记录与扣费，若额度耗尽前端锁定，底层 Linux 云电脑不会销毁，可直接打开终端接管代码并手动提交推送。**

### 每周 15 分钟审计流程

建议在每周重置日前一天花 15 分钟核查：
1. 打开 Settings > Usage & Billing 查看已用百分比。若消耗超前，调出前几天任务定位异常日期。
2. 进入 Details > Routines 查看近 20 次执行记录（Running、Succeeded 或 Failed），排查报错重试或频繁空转的例程。
3. 针对 v0.66.0 起的星标主 Bot，**在描述中明确禁止主动接活**，防它自行揽下琐事。
4. 访问 cursor.com/dashboard，核对 Monthly Limit 与实际按需扣费，确认无异常扣款。

### 监控盲区与应对

系统不提供单个 Bot、例程、会话或模型的消耗明细，20 条运行历史也不记录 token 和金额。**测试新流程必须采用控制变量法**：
1. 每次只新建或修改一个 Bot 或例程。
2. 运行前后各查一次 Usage & Billing 的百分比对比增量，切忌同时上线多个新例程。

### 额度耗尽时的云电脑接管应急

周额度 100% 耗尽且前端对话锁定后，底层的 Linux 云电脑并没有销毁，通过客户端打开桌面或系统终端即可接管：
1. 查看 `/workspace/` 目录下未交付的代码与文件。
2. 手动执行 `git commit` 和 `git push` 推送到远端仓库。
3. 用本地命令行工具在终端接替调试，**绝不需要花钱购买附加用量**。

## 直接发给 Bot 的省额度提示词库

### 上下文防膨胀
- 规则让 Bot 提炼后记住，**省去聊天重复交代**；共享 Bot 可写入详情 About。
```text
请回顾我们至今的协作流程，执行两项沉淀工作：
1. 把你需要长期遵守的行为边界、汇报格式与约束规矩，提炼成一段不超过 300 字的精简文本，我将直接粘贴到你的描述（Description）中；
2. 把我们刚才已经跑通的标准操作流程，封装为一个可复用的技能（Skill），供后续例程直接调用。
完成提取后直接在对话中给出文本，不要展开多余闲聊。
```
- 原始日志与长资料强制存盘，不直接贴进会话。
```text
从现在起执行上下文瘦身规则：
所有抓取的长篇网页、接口调试日志、大批原始数据和阶段性中间产物，一律直接保存为 /workspace/ 目录下的文本文件。在聊天窗口中回复我时，严格只提供核心结论、关键变动要点以及对应的文件绝对路径。严禁将大段原始文本或日志代码贴回对话。
```
- 多模态图片转命令行解析，**避开聊天框高消耗**。
```text
遇到查看多张截图、分析视频画面、逐帧拉片、音频转写或处理长扫描件的任务时，严禁在当前对话框中直接读取原始多模态文件。
你应当在云电脑终端中调用系统已配置的命令行工具（如 Grok Build 或相关转录 CLI）在后台执行，并输出简明的结构化文字摘要；你只需阅读生成的文字结论。如果当前环境无法执行命令行解析，请停下提醒我先在网页端转换成文字后再发给你。
```

找出其中运行最频繁、消耗最大的任务，向我提出降低频率的具体建议；同时为所有监控类例程添加硬性约束：执行检查后若目标无实质变动，立刻静默退出，严禁向我发送「一切正常」或「没有新消息」等无有效信息的通报。
```

严格执行独立单聊工作模式：
只接收并执行我本人下达的直接指令。严禁在没有得到我明确授权的情况下，主动在会话中唤醒、提及或联络其他 Bot 开展群聊协同；如果任务涉及多个专业环节，请将结果写成文件并由我来负责跨 Bot 调度，或者将其派发给云电脑内的后台 CLI 工具独立运行。

```

## 容易踩的坑

- Details > Routines 点击 Test 会跑真机流程，**每次都扣真金额度**。
- Cursor 与 SuperGrok **额度不累加**，只算周用量高的一方，另一方闲置。
- grok.com 与 Grok Bot 计费独立，网页版充值**不能抵扣且不退款**。
- 聊天框贴 API Key 或 Webhook 占 token 且危险，**必须用安全弹窗写环境变量**。
- 点「更新电脑」会抹掉 Linux cron，`/workspace/` 保留，**更新后得重装 cron**。
- Duplicate 会丢弃对话、learned memory 与附件，**得手动给新 Bot 喂上下文**。
- Monthly Limit 触发后不杀进程，**长任务会跑完**，死循环可能超额。

## 做完怎么验收

1. 进 Settings > Usage & Billing 和 cursor.com/dashboard 查账单，确认看到已用百分比与重置倒计时，**关掉 Additional Usage 或把 Monthly Limit 设在安全低位**。
2. 让 Bot 模拟删文件或对外发网络请求，必须弹出 **Ask first** 审批卡片并挂起等待，绝不能静默执行。
3. 检查当前会话并下发多推文 X 搜索，侧边栏不留数十轮长会话，只返回 3 到 5 条简报，长文本落盘至 `/workspace/`，对话框不刷原文。
4. 去 Details > Routines 给无变动的监控例程点 Test，检查后直接静默退出，不发多余的「无更新」闲聊。
5. 让 Bot 编写多文件依赖代码，看它在后台调用 Grok Build 或云端 Agent，**只输出最终状态与执行摘要**，聊天框不贴整屏代码。
