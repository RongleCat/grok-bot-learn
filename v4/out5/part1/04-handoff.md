# 第 4 章 交代任务：消息、附件与一次好的交接

需求给得太简短，它容易搜几十个无关网页、改乱文件。**发消息就是给云端电脑交接工作**。

- **设死任务边界**并说明附件用途，防止它自作主张
- 给出明确指令，换回可直接验收的交付物
- 执行中随时插话纠偏，或用语音补充背景

## 好请求的五要素

跟 Grok Bot 交代任务，**指令必须明确目标与工具范围**，规范见 [《Grok Bot》](https://cursor.com/cn/docs/grok-bot) 文档。

1. **动作具体单一**。写明「抓取比对」或「起草外信」，别用「研究一下」，路径越短越省步数。
2. **限定数据来源**。指定 Notion 页面、Slack #sales-leads 频道或网址，防全网乱搜。
3. **划清审批红线**。读取比对自动跑；**涉及发外信、在线支付或删改数据，必须暂停等审批**。
4. **锁定交付形态**。**拒收口头汇报**，要求在 `/workspace/leads/` 生成带链接的 Markdown 报告或 CSV 表格。
5. **定好报错规则与事实边界**。区分推测与客观事实；遇到登录失效跳过并记录，**禁止死循环重试**。

## 附件规格与限制清单

上传规则见 [《使用 Grok Bot》](https://cursor.com/cn/docs/grok-bot/work)。

### 规格限制

- 桌面端每条**限 6 个**（超额放工作区）；图文音频限 25MB，视频限 200MB。
- 遇阻或报错，先在本地转 PDF、CSV 或图片再传。

### 交接与群聊

1. **拖入后别直接回车**，写清各文件身份、关联逻辑与保护声明。

```text
上传的 PDF 是已经签署的标准采购合同模板。上传的 Excel 是本月供应商提交的实际报价清单。
请对照合同模板中第 4 条关于各类物料的基准单价，逐行核验 Excel 里的实际报价。
标出单价超出基准价的所有条目，在附带的备忘中引用合同中的对应条款编号。
将核验结果另存为一份新的 Excel 表格，并输出一份简短的异常摘要。
请勿改动原始上传文件。
```

2. 群聊中 Bot 间**仅支持纯文本**。下游要看附件必须私聊发它。

## 任务交付实用提示词库

常用场景**直接套模板**，改改就能用。

1. **调研外联**：查线索备料，不直接发送。
```text
从我们的 CRM 系统中获取本周销售管道的重点评审列表。
请跳过当前已经处于活跃跟进序列中的联系人。
在指定公开网页和已授权的 Slack 相关频道中，深入调研排名前五的重点账户，找出负责采购或技术的对口联系人。

将草稿保存在系统草稿箱中，并在明天上午 9 点前在此对话中列出清单供我审批。未经我的明确确认，绝不向外发送任何邮件。
```
2. **附件核验**：对齐多表并核查收支。
```text
附件中的 PDF 为《2026 年度差旅与报销政策细则》，CSV 表格为本月部门提交的待审批费用报销流水。
请逐项核对 CSV 中的每一笔申报项目：
1. 检查报销金额是否超过对应城市级别的住宿与餐饮标准。
2. 检查单笔超过 500 元的支出是否有对应的发票类别标记。
3. 提取所有不符合政策规定的异常申报，列明行号、申报人、金额、超标原因及违背的政策条款。
最后生成一份 Markdown 格式的核查报告，并列出通过与未通过的统计汇总。保持原始 CSV 文件不被改动。
```
3. **网站巡检**：巡查页面并留存证据。

```text
你负责检查我的网站运行状态。本次只访问我提供的以下三个页面：首页、最新更新日志页、用户注册页。

2. 区分页面直接看到的事实与你的推测，事实写在证据栏，分析写在备注栏。
3. 检查受阻或遇到需要验证码时，记录阻碍原因并继续检查下一个页面，不要重复尝试。
4. 检查结果报告保存在 /workspace/site-check/ 目录下，命名为 check-report.md。
你仅有只读检查与生成报告的权限，严禁更改后台设置或提交任何表单。
```

## 长期规则与单次任务：别把家规当家务

**分清长期规则与单次任务**（参见 [《使用 Grok Bot》](https://cursor.com/cn/docs/grok-bot/work)），别把临时参数写进长期设定，也别每次重打底线。

| 类型 | 周期与设定 | 示例与限制 |
| --- | --- | --- |
| 长期规则 | 跨会话生效；Bot Details 配置或输入“请将这条作为你的长期规则记入你的记忆区” | 权限红线、日期 YYYY-MM-DD |
| 单次任务 | 单轮生效不沉淀；直接下达 | 处理 12 个账户或 3 个音频，提取十点会议清单 |

所有 Bot 共用 `/workspace`（参考 [《10 条必备经验，让你的 Grok Bot 变得更好用》](https://jcng5q8n0f3z.feishu.cn/wiki/Hfqxwy3zQiWkRPkVjRZcVCuHnbc)）。**记忆不能替代业务系统**，余额与库存必须回源拉取，严禁脑补。

## 任务进行时的干预：停止、插话与审批

### 插话与停止
Bot 偏离目标时发普通消息就能**即时插话**，比如发“换成 2026 年 10 月更新后的新版规范再查”。

操作出错或遇高风险调用，在输入框发四个字停下。
```text
立即停止
```

**停止只阻断未执行动作，绝不回滚已保存的文件或发出的 API 请求**。停下后按三步排查。
1. 打开云电脑预览面板看状态。
2. 清理半成品或错误写入。
3. 缩小范围并明确边界后再重启。

### 审批与超时
开启 Auto-review 或触发高风险操作会弹出「评审操作」卡片（参见 [《Grok Bot 操作指南》](https://cursor.com/cn/help/grok-bot/how-to)），包含三个选项。
- 允许一次：仅批准本次，后续同类继续询问。
- 始终允许：加入白名单并不再提醒。
- 拒绝：彻底拦截该操作。

| 场景 | 等待机制 | 超时结果 |
| --- | --- | --- |
| 实时交互 | 挂起等待 | 持续等待直到点击处理 |
| 后台无人值守 | 约 10 分钟自动过期（Expired） | **不执行操作并结束任务** |

### 凭据接管（Action needed）
涉及密码、2FA，以及 CAPTCHA 或真实支付时弹出接管卡片，按三步操作。
1. 点击 **Take over** 在云电脑手动输入。
2. 完成后点击 **I'm done** 交还控制权。
3. **切勿在普通对话框输入明文密码**。

## 语音交互：实时语音通话与语音听写的区分使用

Grok Bot 包含听写与通话**两套不同的语音功能**，详情参考 [《与 Bot 语音聊天》](https://cursor.com/cn/help/grok-bot/voice-chat) 与 [《Grok Bot 操作指南》](https://cursor.com/cn/help/grok-bot/how-to)。

### 两种模式对比

| 模式 | 触发与快捷键 | 输出与场景 |
| --- | --- | --- |
| 语音输入（听写） | 桌面点「开始语音输入」，Mac 按 Cmd+D，Win/Linux 按 Ctrl+D，手机点「开始听写」 | 文字填入输入框，适合精改提示词或补参数 |
| 实时语音聊天 | **清空输入框**后点波形图标（Start voice chat） | 双向实时通话，适合梳理思路或快速交接 |

### 开启步骤与避坑

1. 打开单个 Bot 对话。
2. **输入框必须彻底清空**，残留空格或草稿都会隐藏波形图标。
3. 点击波形图标，首次使用需允许麦克风权限。
4. 显示 Connecting…（手机端 Calling…），Bot 主动开口即连通。

### 控制与硬性限制

- 通话中能静音，能看滚动字幕，也可调语速和音色；切屏查看资料时，点顶栏「返回语音聊天」即可切回。
- **仅支持一对一单聊**，群聊、多 Bot 群与「团队 Bot」均无法发起。
- **同一时间只能维持一个通话**，切到新 Bot 需确认「结束并聊天」。
- 挂断后自动生成 Voice chat 卡片记录总时长，点击查阅完整文本，后续任务在文字流继续推进。

## 常见失败写法与优化对照

1. **收敛路径**：没定范围与方法，Bot 会乱点控制台，**甚至修改生产环境代码**。
```text
  帮我维护一下网站，看看有没有什么 Bug。
  ```
改成限定页面与排查步骤：
```text
  对站点清单（/workspace/sites.txt）中的三个静态展示页进行巡检。
  用云浏览器打开每个页面，检查控制台是否有 404 或 500 报错，检查顶部导航栏链接是否全部有效。
  将报错信息、对应页面 URL 及当时的屏幕截图写入 /workspace/logs/err-20261014.md。
  全程仅做只读检查，严禁点击任何带有提交或删除性质的表单按钮。
  ```

2. **审批边界**：别给对外发送权限，一旦理解跑偏，**容易给重要客户发错内容**。
```text
  读取 Gmail 里的未读邮件，重要的直接帮我回一下。
  ```
关键节点让人来审批：
```text
  读取 Gmail 中过去 12 小时的未读邮件。
  仅筛选出发件人属于我们现有企业客户、且正文包含售后或咨询诉求的邮件。
  根据产品常见问题手册，为每封邮件起草回复草稿并存入 Gmail 草稿箱。
  在当前对话中列出客户名称、邮件摘要与草稿正文，等待我的审批。未经我的明确确认，绝不点击发送。
  ```

3. **事实分立**：提示词别夹带偏见，**防止 Bot 迎合假设把小促销当成价格战**。
```text
  去看看竞品今天的动态，总结一下他们是不是要跟我们打价格战。
  ```
要把客观数据和推测分开：
```text
  访问竞品官网的公开定价页与首页横幅，获取他们当下的方案价格表。
  对照我们在 /workspace/competitor/last-month-price.json 中记录的旧价格：
  1. 事实列：标出哪些 SKU 的标价发生了变动，变动金额是多少，附带页面截图与访问时间。
  2. 推测列：基于该降价是限时促销还是永久调价，给出你的分析理由。
  两部分内容必须分开分栏呈现，不得将分析推论当作已知事实。
  ```

4. **只读保护**：没交代主从表与保留字段，**原始数据极易被覆盖损坏**。
```text
  （直接拖入三个 Excel 表格）把这几个表整理一下。
  ```
必须明确以哪张表为准、设为只读：
```text
  上传的三个表格分别是 7 月、8 月和 9 月的销售明细。
  以「订单编号」为唯一主键进行数据去重合并：
  1. 字段统一保留：订单号、成交日期、客户名称、销售代表、成交金额。
  2. 生成一份全新的 Q3_sales_summary.csv 文件，保存在当前工作区。
  3. 保持我上传的原始 7、8、9 月表格内容与文件名完全不变。
  ```

5. **单一使命**：别在一个 Bot 塞多个任务，既搞乱记忆，**还会快速耗尽每周额度**。
```text
  你帮我写一篇关于新产品的推文，顺便把昨天的账目算了，然后再帮我看看竞品推特。
  ```
拆成单任务分工流转：
```text
  遵循一个 Bot 负责一项核心任务的原则。当前 Bot 仅承担社媒文案起草职责：
  依据 /workspace/product/spec.md 中的新功能说明，为 X 平台起草三条不同风格的发布文案。
  要求突出性能提升数据，字数控制在 280 字符以内。
  账目核算与竞品调研交由对应的专用 Bot 负责，不要在此会话中处理。
  ```

## 真实业务交接案例

### 网站日常巡检与证据留存
站长 yishan 把巡检要求直接写成验收规范。工作目录严格限定在 `/workspace/site-check/`，只准检查首页、最新文章与订阅入口，严禁漫游爬取。
- 报告必须留存完整链接、时间戳和当时截图。**直接看到的报错算事实，排查原因算推测，必须分开记录。**
- 遇到登录失效或死链就记下缺口直接跳过，严禁反复死磕。具体做法见 [《如何在一个小时内深入使用 Grok Bot》](https://jcng5q8n0f3z.feishu.cn/wiki/GBV8wdZOaijukikjO0pcYFWKnbg)。

### 收件箱中转与业务分流
一泽Eze 专门设了一个收件箱 Bot 接管 Gmail，没给下游各个 Bot 分别开放邮箱权限。
- 收到反馈邮件私聊转给「产品反馈 Bot」，账单转给「订阅管理 Bot」。
- 纯数值对比直接交给命令行脚本跑。**只给 Bot 同步增量数据，能省下每周使用额度。**
- 高权限工具不要到处接，先用专职入口做初筛最稳当。经验总结见 [《10 条必备经验，让你的 Grok Bot 变得更好用》](https://jcng5q8n0f3z.feishu.cn/wiki/Hfqxwy3zQiWkRPkVjRZcVCuHnbc)。

### 幕僚长摸底与建 Bot
CyrilXBT 先让幕僚长 Bot 读团队 Notion 与 Slack，排查出耗时最长、重复最高且卡点最多的前三项任务，分三步推进。
1. 幕僚长 Bot 手动带跑，人在旁监督输出质量。
2. 确认无误后沉淀为技能，建独立专属 Bot。
3. 最后配置定时自动跑。
**涉及发送、采购、发布或修改线上系统的节点，必须严格保留人工审批。** 完整教程见 [《How to master Grok Bot in 16 minutes - Full Course｜CyrilXBT》](https://jcng5q8n0f3z.feishu.cn/wiki/WGaCwZU71iHAGPkzjkLcahN2nHd)。

## 容易踩的坑

1. **传附件带说明**：传多张图或两个以上表格时，**务必写明用途**，否则容易搞反主从关系。
2. **长期规则存入记忆**：单次指令换会话就丢，底线规范要**写进 Bot 详情的关于/职责**或存入记忆。
3. **本地联动防休眠**：纯云端合盖能跑，但联动本地电脑休眠会断连，记得**检查电源与休眠设置**。
4. **跨 Bot 传图走路径**：群里 Bot 间只支持纯文本，传图必须**存到 `/workspace/` 共享路径**让对方读取。
5. **语音按钮消失先清空**：输入框留有未清空的文字或空格时波形按钮会隐藏，**彻底清空输入框**即可恢复。
6. **高危操作选允许一次**：发邮件或删改数据别选「始终允许」，稳定跑数周前，**坚持选「允许一次」**。

## 做完怎么验收

1. 去 `/workspace/` 或指定目录核验文件，**确认能正常预览且无乱码**，别只看临时文本。
2. 抽 2 到 3 处核心数据点开链接或截图，防模型凭空臆测。
3. 翻调用日志，**确认没私自外发通信，也没改配置或覆盖原文件**。
4. 分清事实与推测，页面原话放事实区，推论建议放备注区，混淆的当场纠正。
5. 查异常清单，**遇到失效网页或缺字段要记明原因并跑完**，别一报错就中断。
