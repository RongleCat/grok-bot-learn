## 1+N 主 Bot 派活模式：单入口与履约章程

别让所有 Bot 都对接用户，免得你在窗口间传话，群聊也白耗 Token。**推荐采用 1+N 模式，你只跟统筹主 Bot 沟通**，由它拆解、派活与汇总，详见 [《从一个 Bot 到一整个组织，Grok Bot 的进阶用法分享：本地电脑、AI 分工和知识库怎么接起来》](https://jcng5q8n0f3z.feishu.cn/wiki/DdqFwLmn7i8cV1kYtDwc840enLg)。

### 主 Bot 六行章程与专职边界

**主 Bot 只负责路由与监督，绝不能亲自写长代码或长文。** 在 Profile Description 写入六行章程，使其无事静默、有事派活，超长汇报存为文件。团队组织规范参考 [《4.2 团队编排：章程、岗位与放权》](https://jcng5q8n0f3z.feishu.cn/wiki/POTrwwThoiQxIakFDIDcUcKjnmh)。

```text
Own: 负责需求的统一拆解、分派、汇总与五行简报汇报。
Sources: 人工下发的指令、项目看板文件。
Output: 纯文本状态摘要，超出五行时输出为指定文件路径。
Approval: 任何对外通信、采购、删除操作必须暂停等待确认。
Failure: 下游专职 Bot 报错时如实上报，不使用过期数据假装完成。
Never: 永远不直接编写业务代码，不擅自修改生产配置。
```

专职 Bot 须在 Description 写死负向边界：
- 广告投手 Bot：分析数据并出具待批清单，**绝不碰后台与出价，不调预算，也不加词或建组**。
- 文案创作 Bot：只出草稿文件，严禁调接口直接上线公开内容。
- 竞品调研 Bot：前台只看不动，严禁下单加购，也不留评或向卖家提问，防反爬封禁。

投放专员直接套用提示词模板。

```text
Own: 负责广告投放数据诊断与策略输出。
Sources: 运营分析文件 /workspace/project/ad_data.json。
Output: 待批操作清单 /workspace/project/pending_actions.md，列出出价建议与预期影响。
Approval: 绝不直接写入广告后台，不修改出价，不修改预算，不加否定词，所有操作必须等待人工审批。
Failure: 数据缺失时明确标注缺失字段，不推测填充。
Never: 绝不执行任何后台写入与线上提交操作。
```

### 待批清单与验收

**专职 Bot 只输出结构化待批清单，把决定权留给人工。** 比如主 Bot 汇总出 5 条广告出价冲突项，你回复“确认建议”或批注修改后才触发下一步。

系统达标后按三项标准验收：

| 验收项 | 达标标准 |
| --- | --- |
| 交互与主 Bot | 单入口清晰运行；主 Bot 不写长代码、不写长文章 |
| 专职 Bot | 各司其职，只产出结构化清单 |
| 高风险动作 | 不可逆操作均有明确人工确认卡点 |
