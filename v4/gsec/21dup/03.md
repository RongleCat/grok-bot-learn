## 21.3 记忆管家：把 Bot 的核心记忆装进私有仓库

Grok 官方没有全量导出记忆的功能，账号变更或系统迁移时，对话攒下的偏好全会丢掉。办法是设立一个**记忆管家 Bot 备份到私有 Git 仓库**，把记忆沉淀为纯文本快照。

[《Grok Bot 百万撤离：一套完善的 Agent 系统备份方案》](https://jcng5q8n0f3z.feishu.cn/wiki/W0TCwnTmbiIJ9KkF4S4cV6ifnCh)

### 记忆分层与管理原则

- **分层逻辑**：公共 Skill、插件配置和云电脑本地文件归共享层，全员可读；单个 Bot 的 Description 规则契约、专属独立记忆和 Routine 任务归专属层。
- **管理原则**：动态业务事实只存源头指针，用时回源抓取；共用记忆须经人工审核，防止交叉感染；固定操作流程固化进 Skill 代码。

[《4.6 虚拟机、记忆与备份》](https://jcng5q8n0f3z.feishu.cn/wiki/KUggwkhqqiRyxZkwTLhcrCU2ncg)

### 仓库结构与归档工作流

```text
├── bots/                     # 各 Bot 独立配置与记忆
│   ├── cyber-xiaowan/        # 单个 Bot 文件夹
│   │   ├── agent-spec.md     # 身份设定、名称、bot-id、slug、description
│   │   ├── MEMORY.md         # 核心记忆全量快照
│   │   ├── profile.md        # 角色信息与权限边界
│   │   └── archive/          # 历史版本与过往日志
│   └── ...                   # 其他 Bot 目录
├── meta/                     # 全局元数据与多 Bot 拓扑关系
├── shared-user-memory/       # 账号级共享记忆
├── vm-services/              # 虚拟机服务总账与恢复脚本（见 21.2 节）
├── README.md                 # 仓库使用说明与最新状态
├── RESTORE.md                # 跨环境恢复操作 SOP
└── registry.md               # 登记索引
```

Bot 目录下的 `MEMORY.md` 提炼为身份权限、历史决策和现场快照三层。管家按三步完成归档调度。
1. 枚举当前账号下的 Bot，圈定核心备份名单。
2. 下发标准化指令，让各 Bot 读取当前记忆并写入 `/workspace` 对应的 Markdown 文件。
3. 扫描敏感信息，**确认无明文 Token** 后统一打上日期标签（如 `tag-2026-10-15`）推送到远端私有仓库。

**Bot 负责全量快照，Git 负责增量追踪**。Bot 每次直接全量覆盖文件，版本变动交由 Git 沉淀。
