## 21.2 虚机服务总账与自动化恢复流水线

Grok Bot 不给虚机快照权限，**把重建步骤写成 Git 幂等脚本成本最低**。参考 [《4.6 虚拟机、记忆与备份》](https://jcng5q8n0f3z.feishu.cn/wiki/KUggwkhqqiRyxZkwTLhcrCU2ncg)。

### 服务总账与源码防污染

私有仓库建一个 `vm-services/` 目录，`REGISTRY.md` 给人看，`registry.json` 供脚本解析。自写脚本单独存进 `service-src/`。

总账登记服务 ID（如 `wechat-crawler`）、负责 Bot、路径以及启停检查命令。**凭证只填绝对路径（如 `~/.env`），绝不明文记录**，人工扫码或 OAuth 认证需高亮。

推送自写代码前排除 `venv/`、`.env/` 和 `node_modules/` 等目录与缓存日志，**commit 前跑脚本正则扫描防泄漏**。

### 自动化恢复流水线

在 `vm-services/restore/` 为各服务编写 `restore-<服务名>.sh`，**脚本必须保证幂等，重复跑不报错**。

总入口 `restore-all.sh` 按固定依赖顺序串联六个执行层。
1. **系统依赖**：安装 `cron`、`ffmpeg` 和 `yt-dlp` 等底层工具。
2. **源码就位**：从 `service-src/` 拷回自写脚本，跳过已有目录只补缺失。
3. **语言环境**：创建虚拟环境并执行 `pip install -r requirements.txt`。
4. **常驻进程**：拉起接口代理与后台转发。
5. **系统调度**：读取 crontab 恢复定时任务。
6. **健康检查**：跑核验命令，**单项失败只记日志并继续，不中断退出**。

机器重置后，拉取仓库跑一次脚本即可全部恢复。参考教程：[《Grok Bot 虚拟机重置后工具全没了？备份恢复教程（附提示词）》](https://jcng5q8n0f3z.feishu.cn/wiki/Q6ZdwzjO5i6z0pkdMfyca8Cbnye)。
