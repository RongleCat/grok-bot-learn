## 自媒体团队的岗位设计与协作机制

### 是什么

**在 Grok Bot 搭团队，核心是「单岗单责」。** 账号下所有 Bot 共享同一台云电脑（拥有独立内核、内存和 `/workspace` 路径），但各自拥有独立的窗口、记忆与设定。Bot 之间靠在共享文件夹读写 Markdown 文件交接任务。

### 怎么做

**主 Bot 头像带星标（右键头像可切换）**负责统筹派工，5 到 6 个专职 Bot 严格按职责边界工作。

| 岗位名称 | 交付路径 | 核心职责与禁止操作 |
| :--- | :--- | :--- |
| 情报侦察员 | `/workspace/content-team/01-inbox/` | 搜集一手线索。严禁互动发帖与私信，严禁把二手言论当事实 |
| 选题策划师 | `/workspace/content-team/02-briefs/` | 评估线索出 Brief。严禁外部冲浪，未获人工批准不得推进到主笔 |
| 内容主笔 | `/workspace/content-team/03-drafts/` | 依 `voice.md` 写作。严禁捏造事实与通用公关腔 |
| 事实编辑 | `/workspace/content-team/04-review/` | 核验一手信源。无发布权限，证据冲突列出待确认 |
| 数据复盘师 | `/workspace/content-team/06-analysis/` | 分析内容数据。严禁账号互动，严禁将相关性写成因果，缺数据严禁硬猜 |
| 网站工程师 | `/workspace/tweet-portrait/` | 提炼画像建站。严禁伪造经历，严禁把本地路径当公网链接 |

1. 在云电脑终端创建标准共享目录。
```text
/workspace/content-team/
├── 00-profile/     # 账号定位、目标读者、范文、禁用表达（voice.md）
├── 01-inbox/       # 情报侦察员的一手信息卡
├── 02-briefs/      # 选题策划师的选题 Brief
├── 03-drafts/      # 内容主笔的候选稿
├── 04-review/      # 事实编辑的审校稿
├── 05-published/   # 已发布文案存档、数据截图或 CSV
└── 06-analysis/    # 数据复盘师的周报与实验记录
```
2. 在 `00-profile/voice.md` 写入风格基座，避免主笔产出套话。
```text
# 账号定位
- 我长期写：面向个人创业者与开发者的 AI 工具实测与提效工作流
- 我的目标读者：正在用 AI 尝试做独立产品、做内容或做业务转型的实干者
- 读者看完后应该获得：直接能照着执行的步骤、准确的参数配置、明确的避坑提醒

# 写作样本
- 代表作 1：【粘贴一段自己数据最好、语言最顺的代表作】
- 代表作 2：【粘贴一段带步骤拆解的教程代表作】

# 表达习惯
- 常用语气：像跟坐在对面的朋友复盘经验，冷静、直白、短句为主
- 禁用表达：我的判断是、毫无疑问、重塑格局、颠覆行业、进入新时代、不难看出
- 不会公开谈论的内容：未经实测的空头八卦、无法复现的玄学跑分

# 商业与事实边界
- 必须保留原始来源的主张：所有关于产品上线、价格变动、官方改版的陈述
- 未亲测时的写法：必须显式标明“未核实”或“作者自述”
```
3. **建群分发规则**。点击「新建聊天」创建「自媒体内容团队」群聊并拉入全员。初次切忌直接指派选题，必须先发统一规范。
```text
这是“自媒体内容团队”协作群。工作顺序固定为：情报侦察员 → 选题策划师 → 内容主笔 → 事实编辑；内容发布后，数据复盘师读取授权数据 → 06-analysis。所有中间文件放到 /workspace/content-team/ 对应目录。任何登录、外发、发布、点赞、回复、关注、私信、购买、删除、连接器授权或权限修改都必须先获得用户明确批准。本次仅确认收到和各自交付路径，不执行外部操作。
```
