## 老订阅切换决策与操作指南

### 是什么

The X Subscription 统一大订阅在 2026 年 10 月 12 日上线。手头有老订阅的用户，官方给出了两套处理规则。

不主动切换的用户，原有套餐方案、价格与功能全部维持现状不变。年付周期会完整保留到自然到期，后续若有变动也会提前通知，且变动只在续订时生效。

如果确认切换，**操作在网页端一旦确认完成便永久生效，联系客服也无法撤回或恢复老套餐**。系统结算时会自动终止旧订阅，未消耗的时间按天折算退款至原支付方式，这笔钱不能抵扣新套餐，新套餐需要全额支付，新的账单周期从当天重新计算。此外，切换操作必须在网页端进行，手机客户端目前不支持。

不同支付渠道在切换时的退款规则差异明显，处理不当容易造成重复扣费。

| 支付渠道与订阅产品 | 切换时的处理方式 | 退款途径与用户操作 |
| :--- | :--- | :--- |
| **网页端直接购买的各种旧方案** | 结账时系统自动取消旧订阅 | 官方自动按比例退款到原支付卡，无需额外人工操作 |
| **Apple 渠道订阅的 Grok / X Premium** | 系统自动向 Apple 发起取消申请 | 官方协助提交，由 Apple 最终决定退还金额 |
| **Apple 渠道订阅的 Cursor** | 官方无法代为取消，也无法代为退款 | **用户必须亲自前往 iOS 系统的「Apple ID → 订阅」手动取消，并向 Apple 客服申诉退款** |
| **Google Play 渠道订阅的各项服务** | 系统切换后不会自动解约 | **用户必须在 Google Play 的「支付和订阅」中手动取消自动续订** |

### 实战案例：社区作者面对大一统订阅的决策实录

社区开发者铁柱AGI（@cgnot996）长期使用 Grok Bot 与 Cursor 处理编程与自动化发布，手里有一份有效期至 2027 年的年费方案（作者自述，未核）。大订阅上线后，他全面排查了用量，决定**暂时不把手里的老订阅切换为新版大一统订阅**，同时关闭原方案的自动续费，继续持有老权益观望。

他主要排查了三项指标：

1. **核对个人账单优惠与年付沉没成本**。老方案带有长期优惠，强行切换新方案已享有的优惠直接作废。
2. **核对第三方模型调用依赖度**。老套餐附带第三方模型额度；新方案每周共享池只覆盖自家模型，所有第三方模型调用都得按 API 标价另行掏钱。他日常编程重度依赖第三方模型辅助审查，切换后单月总支出会大幅增加。
3. **权衡共享池机制的影响**。老套餐中 Grok Bot 与其他产品额度分开计算；新方案每周用量池共享，Bot 跑多了容易挤占网页端与代码补全的正常额度。

| 人群分类 | 典型特征与核心诉求 |
| :--- | :--- |
| **建议换的人群** | 原先单独购买多个零散订阅、每月开销远超 30 美元；主要使用官方模型、很少调用第三方模型；对 Grok Bot 自动化与 X 账号运营有强捆绑需求。 |
| **不建议换的人群** | 手里持有包含额外第三方模型额度的旧方案；只在 Cursor 里重度写代码、对 X 社交权益与视频生成完全不感兴趣。 |

从实操中可以总结出三条避坑原则：

- 决定切换前，先打开用量面板查看真实的调用分布，摸清自家模型与第三方模型的比例。
- AI 工具尽量按月订阅，套餐政策两三个月就会重组，一次性锁定长周期年费容易陷入被动（作者自述，未核）。
- 涉及应用商店的订阅必须亲自清理后台。**通过 Apple 订阅过 Cursor 的用户，决定迁移后必须在手机后台手动取消自动续订**，网页端升级不会代为处理。

决策分析细节可参阅 [《大一统 X 订阅解读：新用户怎么选，老订阅要不要切换？一文讲清楚》](https://jcng5q8n0f3z.feishu.cn/wiki/Myw6wFW8EicOiRkoEAXcVJqinee) 与 [《铁柱推文合集①：开通、套餐与额度》](https://jcng5q8n0f3z.feishu.cn/wiki/PCZIw5IqgiZLjTkXqNncpxannpc)。

### 做到什么程度算好

保留老方案的用户，需确认自动续订状态符合预期，核心模型额度完好。

**决定切换新方案的用户，需确认旧订阅已彻底解除且原渠道收到退款，新方案按 Premium 正常计费，两端没有出现重复计费或通道冲突。**
