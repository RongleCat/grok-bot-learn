## 21.1 认清云电脑的底细：更新、恢复与重置有什么区别

**同一账号下所有 Bot 共用同一台虚拟机**，共享 `/workspace` 目录与系统进程。一台机器装了全局工具其他 Bot 都能调，机器一旦重置，所有依赖环境会同时失效。参考 [《4.6 虚拟机、记忆与备份》](https://jcng5q8n0f3z.feishu.cn/wiki/KUggwkhqqiRyxZkwTLhcrCU2ncg)。

客户端在 **Settings** > **计算机** 的 **Bot's 计算机** 下提供控制项。三者区别如下：

| 操作 | 机制 | 保留内容 | 丢失内容 |
| :--- | :--- | :--- | :--- |
| **更新（Update）** | 升级环境镜像。分软件更新和计算机更新两类 | 软件更新保留全部；计算机更新保留机器人、文件与登录信息 | 软件更新无丢失；计算机更新移除全局应用和软件包 |
| **Recover** | 基于已存数据在最新镜像建新机，先尝试连接旧机存数据 | 已保存的机器人、文件与登录信息 | 全局应用和软件包；若旧机连不上，未同步的修改会丢 |
| **Reset** | 直接按最近保存的数据建新机，中断正在运行的工作 | 已保存的机器人、文件与登录信息 | 全局应用和软件包；未同步的修改会丢 |

对话记录存在云端，机器重置或误删文件都不影响。但**全局安装的应用包、`node_modules` 与 Python 虚拟环境不会被官方保存**，遇到计算机更新、Recover 或 Reset 都会被清掉。详见 [《Grok Bot 计算机》](https://cursor.com/cn/help/grok-bot/computer-recovery)。

虚拟机卡死或响应异常时，排查要按顺序来：

1. 显示 **Reconnecting** 或 **Couldn't Reach Grok Bot's 计算机**：属于网络波动，稍等后点 **Retry**。重连期间文件不丢，**严禁在这个阶段点 Reset**。
2. 重启客户端。Mac 用户必须在顶部菜单栏选 **Quit**，单纯点窗口红叉无效。
3. 检查更新。进 **Settings** > **计算机**，有可用更新先点 **更新**。提示智能体未暂停就等当前任务跑完再点。
4. 尝试恢复。依然连不上或更新卡住出现 **恢复计算机** 时点 **Recover**。若提示 **Update 仍在运行**，选 **Keep waiting**。
5. 执行 **Reset**。前四步无效再点 Reset。失败可用 **Retry Recover** 或 **Retry Reset** 重试，继续报错联系官方支持。
6. 处理磁盘告警。收到 **Computer is low on disk space** 或 **Computer is critically low on disk space** 时别手动删文件，点侧边栏 **Go to Disk Saver** 查看方案，未经确认系统不会删文件。详见 [《Grok Bot 计算机》](https://cursor.com/cn/help/grok-bot/computer-recovery)。

**云电脑只是一次性容器**，不要手动微调环境。搭建过程全部脚本化，配置与自写源码必须存进外部私有 Git 仓库。
