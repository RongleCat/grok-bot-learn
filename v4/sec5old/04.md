## 多 Bot 文件交接约定与目录规划

### 基于文件的协作模式

**Bot 之间读不到彼此的聊天记录**，串联协作全靠共享磁盘里的文件交接。

开发者 0xlangeai 做推文画像网站时跑通了四步协作，每个 Bot **只需在提示词里接收上一棒的文件路径**。具体实践见 [《4.6 虚拟机、记忆与备份》](https://jcng5q8n0f3z.feishu.cn/wiki/KUggwkhqqiRyxZkwTLhcrCU2ncg)。

1. 整理员抓取内容，生成 `tweets.md`。
2. 分析师提炼 `tweets.md`，输出 `profile.md`。
3. 设计师根据画像生成 `design.md`。
4. 工程师读取设计文件构建代码。

### 共享磁盘目录规划

建议建第一台机器起就定好目录，避免多 Bot 把磁盘写乱。

| 目录路径 | 存放内容 | 写入规范 |
| --- | --- | --- |
| `/workspace/handoff/` | 多 Bot 中间产物 | 统一 Markdown 或 JSON，文件名带任务前缀 |
| `/workspace/projects/` | 项目代码与资产 | 按项目划分独立子文件夹，关联各自 Git 仓库 |
| `/workspace/tools/` | 本地自写脚本工具 | 仅保留无密钥源码，排查无误后同步进备份仓 |
| `~/.env` 或本地文件 | 本地 API 密钥 | **仅存机器本地**，严禁提交代码仓或在会话中打印 |

### 磁盘空间清理与 Disk Saver

空间不足时，系统会弹出 `Computer is low on disk space` 或 `Computer is critically low on disk space` 警告。

点击侧边栏 **Disk Saver** 的「Go to Disk Saver」可查看清理建议。**未经确认它绝不擅自删除文件**，拒绝清理则原样保留。
